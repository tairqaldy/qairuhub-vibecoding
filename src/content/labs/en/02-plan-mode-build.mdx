<Lead>
In twenty-five minutes you go from an empty folder to a working sign-up page. The most valuable thing you do is not typing. It is *reading a plan*, and changing one line of it before a single file exists.
</Lead>

Anthropic's guide gives the order in four words: explore, plan, implement, commit. Plan mode does the first two ([best practices](https://code.claude.com/docs/en/best-practices)). One bad line of plan becomes hundreds of bad lines of code, so review the plan, not only the diff ([advanced context engineering](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/ace-fca.md)).

A plan is short enough to read end to end. Its diff is not. Read the cheap one.

You build the first real version of **QAIRU Event Sign-up**: one page, one event, a form that reserves a seat, a counter that runs down. One file, no framework, no build step.

## Nine steps from an empty folder to a commit

<Steps>

<Step title="Make the folder a repo before the agent touches it">
<Terminal title="bash">
```bash
mkdir qairu-event
cd qairu-event
git init
```
</Terminal>

Expected: `Initialized empty Git repository` and a path ending in `qairu-event/.git/`. On Windows PowerShell chain the three with `;`, not `&&` — `&&` there prints `The token '&&' is not a valid statement separator`.

Do not skip `git init`. Claude Code checkpoints its own edits, but not Bash commands, most subagent edits, or files you change in another window ([checkpointing](https://code.claude.com/docs/en/checkpointing)). Checkpoints are local undo. Git is permanent ([module 09](/en/learn/git-and-github/)).
</Step>

<Step title="Start in plan mode, and prove you are in it">
<Terminal title="bash">
```bash
claude --permission-mode plan
```
</Terminal>

The first run in a new folder asks you to trust the workspace; accept. Then read the status bar under the input box. It must say `plan mode on`.

Already in a session? Press `Shift+Tab` until it does. On Pro, Max and Team plans a terminal session starts in **auto** mode: Manual, accept edits, plan — three presses. A session that started in Manual needs two ([which mode a session starts in](https://code.claude.com/docs/en/permission-modes#which-mode-a-session-starts-in)). On some Windows setups the shortcut is `Alt+M`.
</Step>

<Step title="Hand it the whole job in one prompt">
Paste this exactly. Swap in your own event details or leave them.

<Prompt title="Build prompt" where="Claude Code · plan mode">
```text
Build the QAIRU Event Sign-up landing page in this folder as one file: index.html.
No frameworks, no build step, no new dependencies. All CSS and JS inside index.html.

The page shows ONE event and lets a visitor reserve a seat:
- event title, date, time, place, and two sentences about it
- a reservation form: name, email, one Reserve button
- a "seats left" counter that starts at 40 and drops by one per reservation
- a list of people who have reserved, newest first
- at 0 seats: the form is disabled and the page says the event is full
- reservations survive a page reload
- empty name, empty email, or an email with no "@" is rejected with a visible message

Do not write any code yet.
1. Tell me what is already in this folder and what you plan to reuse.
2. Show me the plan: ordered steps, the file each step touches, and for each step
   the exact thing I should click in the browser and the exact thing I should see.
3. List what you will NOT do, and any assumption you need me to confirm.

Stop and wait for my approval. When I approve, save the approved plan as PLAN.md
before you change anything else.
```
</Prompt>

It reads the folder, runs a read-only command or two, and comes back with findings and a numbered plan. No `index.html` yet: plan mode blocks source edits until you approve ([plan mode](https://code.claude.com/docs/en/permission-modes#analyze-before-you-edit-with-plan-mode)). While it works, `Ctrl+T` toggles its to-do list and `Ctrl+O` opens the transcript.
</Step>

<Step title="Read the plan like it is the only thing you read today">
Three questions.

1. **Does every step name a check I can run?** "Implement the reservation form" is a wish, not a step: nothing there tells you whether it worked ([best practices](https://code.claude.com/docs/en/best-practices)).
2. **Does it say what it will not touch?** An agent with no stated boundary reorganises things you never asked about.
3. **Is there a step I could not explain to the person next to me?** That is the one that hurts later.

Two bad answers means **"No, keep planning"**, with the reason: `Steps 3 and 5 have no browser check. Rewrite them with what I click and what I should see.`
</Step>

<Step title="Change one line before you approve">
Press `Ctrl+G`. The proposed plan opens in your text editor. Add this, save, close.

<Prompt title="The line you add yourself" where="Your editor · via Ctrl+G">
```text
- Every string a visitor can see exists in Kazakh and English. A KK / EN button in the
  header switches between them and remembers the choice. Kazakh is the default.
```
</Prompt>

The agent will not invent that constraint for you. Now the plan is partly yours — the difference between supervising a build and watching one.
</Step>

<Step title="Approve it the slow way">
Claude offers three answers: use auto mode, approve edits manually, or keep planning. Where auto mode is unavailable the first reads "Yes, auto-accept edits".

Pick **"Yes, manually approve edits"**. Read **one** diff end to end: the JavaScript that handles the form submit, where the rules you wrote either exist or do not. Approve the rest at any speed. Simon Willison's main anti-pattern is the same rule one size up: never open a pull request with code you have not read ([anti-patterns](https://simonwillison.net/guides/agentic-engineering-patterns/anti-patterns/)).

Expected: `PLAN.md` written first, then `index.html`, and nothing else in the folder.
</Step>

<Step title="Run it yourself">
Leave Claude running. Open a **second** terminal in the same folder.

<Terminal title="bash">
```bash
npx -y serve
```
</Terminal>

It prints a local address such as `http://localhost:3000`. Read the port off your own screen. Open it and try to break the page, in this order: reserve a seat (counter drops, name appears at the top), reload (the name is still there), submit an empty form (a visible message, not silence), press KK / EN (every visible string changes).

Offline, or `npx` hangs? Open `index.html` from your file manager. Fine today, but get used to `http://` — that is how the page runs once it leaves your laptop.
</Step>

<Step title="Find the one thing that does not work, and say it precisely">
There is always one. Never write "it's broken". Write symptom, location, definition of done.

<Prompt title="Fix prompt" where="Claude Code · manual approve mode">
```text
Bug: [what you see]. Expected: [what should happen].
Where: index.html, [the function or block you suspect].
Fix it with the smallest change that works, then tell me the exact steps
to check it in the browser. Do not touch anything else.
```
</Prompt>

Expected: a small diff and a list of test steps. If it starts rewriting half the file, press `Esc` — it stops and keeps the work so far — then ask again, narrower.
</Step>

<Step title="Commit before you like it too much">
Type `!` at the start of an empty line for shell mode, so the output lands in the conversation where Claude can see it.

<Terminal title="Claude Code · shell mode">
```bash
! git status
```
</Terminal>

<Prompt title="Commit prompt" where="Claude Code · manual approve mode">
```text
Commit everything in this folder. Write one descriptive message in the form
type(scope): summary, saying what this page does.
Then show me git log --oneline and git status.
```
</Prompt>

Expected: one commit, one line, something like `feat(signup): event landing page with seat counter`, and a clean `git status`. Commit after every unit of progress, so a later session — or you tomorrow — can return to a state that worked ([harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)).
</Step>

</Steps>

## Four ways this goes wrong, and the move for each

- **It explores forever.** Unscoped investigation reads hundreds of files and fills the context window — the guide calls it "infinite exploration". Scope it to named files, or hand it to a subagent.
- **You have corrected the same thing twice.** Stop: the context is now mostly failed attempts. `/clear` and write a better first prompt ([best practices](https://code.claude.com/docs/en/best-practices)).
- **It says done and it is not.** Ask for evidence, not assertions: the command it ran and the output it got.
- **It is quietly cheating.** Kent Beck's warning signs: it loops, it adds functionality nobody asked for, or it disables and deletes tests to get green ([augmented coding](https://newsletter.kentbeck.com/p/augmented-coding-beyond-the-vibes)).

Want the last ten minutes back? `Esc` `Esc` on an empty input opens the rewind menu ([lab 04](/en/labs/undo-anything/)). It will not undo what a Bash command did. That is what your commit is for.

<Callout type="warn" title="What you built is not a sign-up system yet">
The reservations live in the visitor's own browser. Nobody else sees them, and clearing site data erases them. This is a page, not a service. Put no real event on it, and ask nobody for a real email address until it has somewhere safe to put one.
</Callout>

<Deeper title="When to skip the plan entirely">
Exploration and the plan both spend context. The rule from the docs: if you can describe the change in one sentence, skip the plan and ask. A typo, a log line, a rename. Planning pays when the approach is uncertain, the change spans files, or the code is unfamiliar ([best practices](https://code.claude.com/docs/en/best-practices)).
</Deeper>

<Deeper title="Making plan mode the default for a project">
Want a plan first every time in a repo? Put `{"permissions": {"defaultMode": "plan"}}` in its `.claude/settings.json`. Every session there starts in plan mode, and `Shift+Tab` still leaves without approving anything ([permission modes](https://code.claude.com/docs/en/permission-modes)).
</Deeper>

Do steps 1 to 4 on the projector and stop at the plan. Read it aloud, then ask the room what it is missing before you press `Ctrl+G`.
