<Lead>
Right now your project is a folder. In twenty-five minutes it will be a URL. You do it *by hand first*, because you cannot supervise an agent doing something you have never done.
</Lead>

"Deployed successfully" is a claim, not proof. By the end of this page you will know four ways it can be wrong.

## Part one: six steps you do yourself

<Callout type="warn" title="Thirty seconds that save you a bad week">
Before the first push, open `.gitignore` and check that `.env` is in it. A public repo is public the instant it exists, and a committed key stays compromised after you delete it. Run `git status` and read every filename before committing.
</Callout>

<Steps>

<Step title="Log in to GitHub from the terminal">
The GitHub CLI turns account work into commands, so your agent can do it later too. It also costs less context than a GitHub MCP server doing the same job ([costs docs](https://code.claude.com/docs/en/costs)).

<Terminal title="bash">

```bash
gh auth login
gh auth status
```

</Terminal>

`gh auth login` opens a browser login and a one-time code. `gh auth status` prints the account you are actually logged in as. Check it: half the "permission denied" problems here are a forgotten second GitHub account.
</Step>

<Step title="Create the repo and push, in one command">
You never open github.com. From inside your project folder:

<Terminal title="bash">

```bash
git init
git add -A
git commit -m "QAIRU Event Sign-up: first working version"
gh repo create qairu-event --public --source=. --remote=origin --push
```

</Terminal>

`--source=.` means "this folder is the repo". `--remote=origin` names the connection, `--push` sends the commits. `--public` matters for money: GitHub's standard Actions runners are free on public repositories, while a free private repo gets 2,000 minutes a month ([GitHub billing docs](https://docs.github.com/en/billing/concepts/product-billing/github-actions)).
</Step>

<Step title="Build the folder that is the website">
A static site is a folder. Build it, then open the folder and look inside. That removes most of the fear from deploying.

<Terminal title="bash">

```bash
npm run build
ls dist
```

</Terminal>

If `dist/` does not appear, your project builds somewhere else — `build/`, `out/`, `public/`. Find the real name now. The most common failed first deploy is a successful upload of the wrong folder.

No build step? The QAIRU Event Sign-up page from [lab 02](/en/labs/plan-mode-build/) is one `index.html`, which is already a website. Give it its own folder so you upload the page, not the whole repo:

<Terminal title="bash">

```bash
mkdir site
mv index.html site/
```

</Terminal>

Then read `site` wherever this lab says `dist`.
</Step>

<Step title="Deploy to Cloudflare Pages">
Wrangler is Cloudflare's CLI. `npx` runs it without installing anything.

<Terminal title="bash">

```bash
npx wrangler pages deploy dist --project-name=qairu-event
```

</Terminal>

The first run sends you to a browser to authorise Wrangler and offers to create the project. Then it uploads `dist/` and prints a `pages.dev` URL, already on HTTPS, already served worldwide.

To check which account you are uploading into:

<Terminal title="bash">

```bash
npx wrangler whoami
```

</Terminal>
</Step>

<Step title="Open it on your phone, on mobile data">
Not on your laptop. Your laptop has a cached localhost and a browser that will lie to you. Turn off wifi on your phone, type the `pages.dev` URL, load it.

This is the only step that counts as proof. Everything else is a claim. A device that is not yours, on a network that is not yours, just got an answer from a server that is not yours.
</Step>

<Step title="Attach a custom domain — and this one is not a command">
There is no `wrangler` flag for this. Open the Cloudflare dashboard, find your Pages project, open **Custom domains**, add the name. Cloudflare creates the DNS record and the SSL certificate (what those are: [module 12](/en/learn/deploy/)). Then DNS spreads — minutes to hours.

Write this step down. In a few minutes you hand this job to an agent that cannot open a browser, and it will report the `pages.dev` URL as finished anyway.

Cloudflare's free plan allows 100 custom domains per project ([Pages limits](https://developers.cloudflare.com/pages/platform/limits/)). The limit is never why this fails. Nobody clicked.

No domain yet? The GitHub Student Developer Pack gives one free for a year — a `.me` from Namecheap, a `.TECH`, or a `.dev`/`.app` from Name.com ([education.github.com/pack](https://education.github.com/pack)).
</Step>

</Steps>

<Deeper title="What the free tier actually gives you, in numbers">
Cloudflare Pages Free: 500 builds per month, 1 concurrent build, a 20-minute build timeout, 20,000 files per site, 25 MiB per file, 100 custom domains per project and 100 projects per account. No bandwidth cap is listed for static assets.

Add a function later and Workers Free gives 100,000 requests a day, 10 ms of CPU per invocation, no charge for egress. Paid starts at $5 a month.

Sources: [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/), [Pages limits](https://developers.cloudflare.com/pages/platform/limits/). For a student project: serving your page costs nothing and keeps costing nothing. Functions and databases spend a budget, not HTML.
</Deeper>

## Part two: hand the same job to the agent

You know what a good deploy looks like, so you can recognise a bad one. Delegate it now.

<Prompt title="Deploy this project" where="Claude Code · plan mode">

```text
Plan a first deploy of this project to Cloudflare Pages. Write no code and
run no commands until I approve the plan.

Facts about this repo:
- Static site. The build command is `npm run build`. Confirm the output
  folder yourself by reading the config — do not assume it is dist/.
- Not yet on GitHub. I want a public repo named qairu-event.
- `gh` and `npx` are available. I am on [Windows PowerShell / macOS / Linux].

In the plan, give me:
1. The exact commands, in order, that you will run.
2. For each one: what it changes that I cannot undo by editing a file.
3. Which of them you cannot run at all, and why.
4. The single command I can run afterwards to prove the site is live.

Then, under the heading "I must do these in a browser myself", list every
step that has no CLI equivalent. Do not tell me the site is live until
that list is empty or I have confirmed I did them.
```

</Prompt>

**It will stop and ask before deploying, and that is correct.** On Pro, Max and Team plans, sessions start in auto mode: a classifier model reviews actions first, and production deploys are blocked by default, alongside force pushes and mass deletions ([permission modes](https://code.claude.com/docs/en/permission-modes); the modes themselves are [module 07](/en/learn/the-agent/)). The docs warn it cuts prompts without guaranteeing safety. Read the command it is asking about, and the folder name in it.

**You can draw a line in plain language.** Say "don't push" and the classifier treats that as a boundary until you lift it. A real fence, not politeness.

**Or make the fence permanent** ([lab 03](/en/labs/claude-md-and-permissions/) goes deeper). In `.claude/settings.json`:

<Terminal title=".claude/settings.json">

```json
{
  "permissions": {
    "ask": ["Bash(git push *)", "Bash(npx wrangler *)"],
    "deny": ["Read(./.env)", "Read(./.env.*)"]
  }
}
```

</Terminal>

Mind the space before the star: `Bash(git push *)`, wildcard after the subcommand, not `Bash(git *)` ([permissions docs](https://code.claude.com/docs/en/permissions)). And Bash rules match command text, not programs — convenience, not a security boundary.

## Part three: check what it actually did

Claude Code users approve 93% of permission prompts. Anthropic's engineering post calls this approval fatigue, "where people stop paying close attention" ([auto mode, 25 Mar 2026](https://www.anthropic.com/engineering/claude-code-auto-mode)). You are not immune, so verify mechanically.

Press `Ctrl+O` to open the transcript viewer and read the tool calls, not the summary the agent wrote ([interactive mode](https://code.claude.com/docs/en/interactive-mode)). Inside a session, `!` at the start of a line runs a command and drops the output into the conversation.

<Terminal title="bash">

```bash
git log --oneline -3
git remote -v
gh repo view --web
curl -sI https://qairu-event.pages.dev | head -1
```

</Terminal>

Four commands, four different lies. `git log`: does the commit exist, or did the agent only stage files? `git remote -v`: which repository did it push to? `gh repo view --web`: is a `.env` sitting in there? `curl -sI`: `HTTP/2 200` means a server answered.

On Windows PowerShell that last line needs two changes: `curl` is an alias for something else, and `head` does not exist. Run `curl.exe -sI https://qairu-event.pages.dev` on its own, or run the whole block in Git Bash.

<Prompt title="Audit the deploy you just did" where="Claude Code · new session, after /clear">

```text
Audit the deploy that was just done to this project. Assume nothing from
memory — check the current state with commands.

Report, as a table, one row per claim:
- claim (e.g. "the repo is public", "dist/ was the folder uploaded",
  "the live URL serves the newest build")
- the command you ran to test it
- the actual output
- PASS or FAIL

Finish with two lists: what is genuinely live right now, and what is still
only true on my laptop. If any claim cannot be tested with a command from
here, say so instead of guessing.
```

</Prompt>

Run it after `/clear`. The session that did the work will confirm its own summary; a session with no memory of the deploy has to go and look.

<Callout type="danger" title="Rewind does not reach the internet">
Checkpoints ([lab 04](/en/labs/undo-anything/)) cover only what Claude Code's own tools edited in your files. Remote side effects — database writes, pushes, deploys — are not tracked ([checkpointing](https://code.claude.com/docs/en/checkpointing)).

So `/rewind` puts your source back while the broken version stays live, and your terminal looks calm. Undoing a deploy is `git revert`, push, rebuild, `npx wrangler pages deploy` again. No shortcut, and the first time you need it should not be the first time you try it.
</Callout>

<Callout type="live" title="If you are teaching this lab">
Do Part one live on the projector, slowly, and stop at the `pages.dev` URL. Read it out and ask the room to type it into their phones. Twenty phones loading one page at once is where the abstraction becomes real, and it costs nothing.

Then break it on purpose: deploy a folder that is not the build output, show the agent reporting success, and let someone catch it with `curl -sI`.
</Callout>
