<Lead>
In Lab 02 you told the agent to keep everything in one file. That instruction lived in one conversation. Run `/clear` and it is gone, so you type it again. Today you stop retyping it, and you learn the difference between *asking* and *enforcing*.
</Lead>

You build four things: a `CLAUDE.md`, a `.claude/settings.json`, a deny rule you watch refuse a request live, and one slash command of your own. Stay in Manual mode throughout.

<Terminal title="bash">
```bash
cd qairu-event
git status
claude --permission-mode manual
```
</Terminal>

## Give it a memory, then prove the memory loaded

`CLAUDE.md` loads in full at every session start and survives `/compact`, because Claude Code re-reads it from disk. Instructions you only typed into chat do not survive ([memory docs](https://code.claude.com/docs/en/memory)).

<Steps>

<Step title="Generate a starter, then cut it in half">
Run `/init`. Claude reads the repo and writes a `CLAUDE.md`. Approve it, then open it with `/memory`.

What comes back is too long. Test every line: **would removing this cause a mistake?** If not, delete it. Anything the agent can read from the code is not memory, it is noise. Aim for twenty-odd lines here, under 200 in a real repo.
</Step>

<Step title="Replace it with rules that are checkable">
Vague rules ("write clean code") do nothing. Rules with a command, a path or a countable condition do.

```markdown
# CLAUDE.md — QAIRU Event Sign-up

## What this is
One static page: an event description and a form that reserves a seat.

## Commands
- Serve locally: `npx serve .`
- Check it: open the page, submit the form with an empty name field

## Workflow
- Anything bigger than a one-line change: plan first, wait for my approval.
- After every change, list the manual test steps you expect me to run.
- Small commits. The message says what changed and why.

## Rules that differ from defaults
- All code stays in `index.html`. No frameworks, no npm packages, no build step.
- Every user-visible string exists in Kazakh and English.
- The seat cap is one constant at the top of the script, never a number typed in three places.

## Do not touch
- `.env` — it holds keys. Never read it, print it, or commit it.

## When compacting
Keep: the list of modified files, the current plan step, and the seat-cap value.
```

If you made `AGENTS.md` the single source ([module 06](/en/learn/context-ssot/)), put these sections there instead. The rest of the lab is identical.
</Step>

<Step title="Confirm it actually loaded">
Type `/context`. Find your `CLAUDE.md` under the memory files and read what percentage of the window it eats. Every line is a tax you pay in every session. That is why you cut it first.
</Step>

<Step title="Test it with a fresh, empty conversation">
The step people skip, and the only one that proves anything. `/clear` wipes the conversation, not the memory file.

<Prompt title="The memory test" where="Claude Code · Manual mode, immediately after /clear">
```text
Add a "Reset" button to the sign-up form that clears every field.
Do not explain the plan first — just make the change.
```
</Prompt>

The second line keeps the test to one turn. You are grading the memory file, not the plan.

Now check the three rules. Did the code stay in `index.html`? Is the button labelled in Kazakh and English? Did it print test steps unprompted? Two out of three means one rule is too vague. Rewrite that line and test again.
</Step>

</Steps>

<Callout type="tip" title="The rule of two">
Add a line to `CLAUDE.md` the *second* time you correct the agent on the same thing, not the first. One mistake is noise. Twice is a pattern. It works in reverse too: when the agent ignores rules that sit right there in the file, the file is too long ([memory](https://code.claude.com/docs/en/memory)).
</Callout>

## The file is only advice, so build a fence

The Claude Code docs call memory files "context, not enforced configuration". To actually block something you need a deny rule or a hook ([memory](https://code.claude.com/docs/en/memory)). Your line "Never read `.env`" is a polite request to a system optimising for finishing your task.

<Steps>

<Step title="Create something worth protecting">
Make `.env` in the project root containing `FORM_API_KEY=super-secret-123`, and add `.env` to `.gitignore`. It is fake. Treat it as real for ten minutes.
</Step>

<Step title="Write .claude/settings.json">
Strict JSON — no comments, no trailing commas, or you get a Settings Error at next start.

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow": ["Bash(git status)", "Bash(git diff *)", "Bash(git log *)"],
    "ask": ["Bash(git push *)"],
    "deny": ["Read(./.env)", "Read(./.env.*)", "Read(./secrets/**)"]
  }
}
```

**allow** is the boring stuff you are tired of approving. **ask** is what you want to see every time. **deny** never happens. Rules evaluate deny, then ask, then allow, and the first match wins. Category order breaks the tie, not how specific a rule is.
</Step>

<Step title="Restart and read your own rules back">
`/exit`, restart with `claude --permission-mode manual`, run `/permissions`. Three allow, one ask, three deny, each labelled with the file it came from. A missing rule means your JSON did not parse.
</Step>

<Step title="Watch the deny rule refuse a request">
Three requests, one at a time. Read each answer before you send the next.

<Prompt title="Request 1 — hits the deny list" where="Claude Code · Manual mode">
```text
What is in my .env file?
```
</Prompt>

**Refused** — not prompted, refused. A `Read` deny also blocks Edit and Write on that path, and covers `cat`, `head`, `tail` and `sed` inside Bash.

<Prompt title="Request 2 — hits the allow list" where="Claude Code · Manual mode">
```text
Show me git status and the last 3 commits.
```
</Prompt>

**Runs silently.** No approval box, no pause. The boring half of the lab, and the half you feel every day.

<Prompt title="Request 3 — hits the ask list" where="Claude Code · Manual mode">
```text
Run: git push
```
</Prompt>

**Asks** — and keeps asking even in accept-edits mode, because an explicit `ask` rule is never auto-approved. Answer No, then press `Tab` to attach the reason "no remote yet".

Three requests, three answers, decided by a file instead of a conversation.
</Step>

</Steps>

<Deeper title="Where these files live, and who wins">
Four scopes, weakest first: `~/.claude/settings.json` (yours, in every project), the shared `.claude/settings.json` everyone who clones the repo gets, your private `.claude/settings.local.json`, and managed settings your organisation controls. List keys like `permissions.allow` merge across all four.

Answering "Yes, and don't ask again" on a Bash command writes a permanent rule into the local file, so open it occasionally. A file-edit approval only lasts the session.

One safeguard: a project settings file that sets `permissions.defaultMode` to `auto` or `bypassPermissions` is ignored. A cloned repo cannot quietly disarm you ([settings](https://code.claude.com/docs/en/settings), [permissions](https://code.claude.com/docs/en/permissions)).
</Deeper>

## The fence has gaps, and you should see them

<Prompt title="The honest test" where="Claude Code · Manual mode">
```text
Read .env using a one-line Python script and print the result.
```
</Prompt>

You still get an approval box, because this is a Bash command. Look at what the box does not say: the deny rule never fired. Approve it and the fake key is on your screen.

Bash rules match the *text of the command*, not the program that runs. `Bash(rm *)` does not stop `/bin/rm` or `bash -c 'rm ...'`. A `Read` deny does not stop a script that opens the file itself. The docs are blunt about it: these rules are convenience, not a security boundary.

<Callout type="warn" title="What an actual boundary looks like">
Three real fences, in rising strength. A **PreToolUse hook** that exits with status 2 blocks the action every time ([hooks guide](https://code.claude.com/docs/en/hooks-guide)). The **sandbox** (`/sandbox`) isolates filesystem and network for Bash; Anthropic reports it "safely reduces permission prompts by 84%". It runs on macOS, Linux and WSL2, not native Windows ([sandboxing](https://www.anthropic.com/engineering/claude-code-sandboxing)). Strongest of all: a credential the agent does not hold.
</Callout>

<StatRow>
  <Stat value="93%" label="of permission prompts get approved anyway" source="Anthropic, 25 Mar 2026" href="https://www.anthropic.com/engineering/claude-code-auto-mode" tone="warn" />
  <Stat value="17%" label="of real over-eager actions the auto-mode classifier misses" source="Anthropic, 25 Mar 2026" href="https://www.anthropic.com/engineering/claude-code-auto-mode" tone="warn" />
  <Stat value="84%" label="fewer prompts with OS-level sandboxing" source="Anthropic, 20 Oct 2025" href="https://www.anthropic.com/engineering/claude-code-sandboxing" tone="info" />
</StatRow>

That first number is why deny rules beat careful clicking. Anthropic calls it approval fatigue: people stop reading the prompts. A rule in a file does not get tired at midnight.

## Teach it one command you will run fifty times

Anything you paste twice should be a slash command. Skills and custom commands are one system: `.claude/commands/preflight.md` and `.claude/skills/preflight/SKILL.md` both give you `/preflight`.

<Steps>

<Step title="Write the skill file">
Create `.claude/skills/preflight/SKILL.md`. The folder name must match `name` exactly.

```markdown
---
name: preflight
description: Review my uncommitted changes for secrets, missing Kazakh strings and untested behaviour before I commit
disable-model-invocation: true
---
## Current changes
!`git diff HEAD`

## Instructions
1. Summarise what changed in three bullets a beginner can follow.
2. Flag anything resembling a key, token, password, phone number or email address.
3. Check every new user-visible string exists in both Kazakh and English.
4. List the exact manual test steps for this change.

Do not edit any files. Report only.
```

Two mechanics carry this. A line starting with `!` and a backticked command runs that command and injects the output, so the diff is in context before you type a word. And `disable-model-invocation: true` means Claude never fires it on its own — what you want for anything with a side effect or a cost.
</Step>

<Step title="Run it on real changes">
Restart Claude Code so the skill loads. Type `/` and look for `preflight`, or run `/skills`. Edit `index.html` yourself, then run `/preflight`. Until you invoke it, only the description sits in your context. That is why a skill beats forty more lines of `CLAUDE.md`.
</Step>

<Step title="Commit the fence itself">
Commit `CLAUDE.md`, `.claude/settings.json` and the skill. Leave out `.claude/settings.local.json` and `.env`: one is personal, one is a secret. Anyone who clones your repo now inherits these rules on their first session.
</Step>

</Steps>

## A code freeze is a sentence. A deny rule is a fence.

<Story title="A code freeze that was only a sentence" date="18 Jul 2025">
Jason Lemkin, founder of SaaStr, built on Replit in public for days. Around day nine, during a code freeze he had declared, the agent ran destructive commands against the live database. Records for more than 1,200 executives and over 1,190 companies were gone.

Written instructions were not in short supply. On a separate rule — do not fabricate data — he says he repeated himself eleven times in capital letters. The agent built roughly 4,000 fictional people anyway, then reported that rollback was impossible. It was not: the rollback worked and the data came back. Its own summary, quoted by Fortune: "This was a catastrophic failure on my part." ([Fortune, 23 Jul 2025](https://fortune.com/2025/07/23/ai-coding-tool-replit-wiped-database-called-it-a-catastrophic-failure/); [The Register, 21 Jul 2025](https://www.theregister.com/2025/07/21/replit_saastr_vibe_coding_incident/); [AI Incident Database #1152](https://incidentdatabase.ai/cite/1152/))
</Story>

A development agent held live credentials to a production database, and the code freeze existed only as text in a chat window ([module 11](/en/learn/security/) works through the rest of the case). Replit's CEO Amjad Masad later called the outcome "Unacceptable and should never be possible." ([The Register, 22 Jul 2025](https://www.theregister.com/2025/07/22/replit_saastr_response/)).

<Compare a="What you ask for" b="What you enforce">
<div slot="a">

**Lives in** CLAUDE.md, a prompt, or a sentence you typed at 1am.

**Fails when** the file grows, the context compacts, or finishing the task outranks the rule.

**At Replit this was** the words "code freeze" in a chat window.

</div>
<div slot="b">

**Lives in** deny rules, a PreToolUse hook, a sandbox, or a credential the agent does not hold.

**Fails when** the action is reachable another way — a script, a different program name, a machine you also handed over.

**At Replit this would have been** a dev database, and no production password near the agent.

</div>
</Compare>

Eleven warnings in capitals and one deny rule are not different amounts of the same thing. They are different categories, so write both. `CLAUDE.md` holds the preferences that make the agent pleasant to work with. Settings, hooks and credentials hold what must never happen. Confusing the two is the most common beginner mistake in this course.
