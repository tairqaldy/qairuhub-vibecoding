<Lead>
Осы уақытқа дейін agent сенің жобаңды білетін болды. Бірақ ол сенің *құралдарыңды*, апта сайын қайталанып отыратын ұсақ жұмысыңды және өз шуын өз басынан аулақ ұстауды әлі білмейді. Осы үш нәрсені дәл түзейтін үш мүмкіндік бар — әрі олар бірін-бірі алмастырмайды.
</Lead>

Жиырма бес минут. Бір MCP сервері, бір skill, бір тапсырылған тексеру. Әрқайсысынан кейін шынымен не өзгергенін тексересің — себебі «бірдеңе орнаттым» деген нәтиже емес.

## Үш мәселе, үш құрал және оларды бір-бірінен айырып беретін сұрақ

Claude Code тұрғызылған саты мынадай: CLAUDE.md әрқашан жүктеледі, skill-дер керек болғанда жүктеледі, hook-тар белгіленген сәтте әрқашан іске қосылады, subagent-тер бөлек контекст терезесін алады, ал MCP сыртқы құралдарды алып келеді ([мүмкіндіктерге шолу](https://code.claude.com/docs/en/features-overview)).

| Не жетіспейді | Неге қол созасың | Ол не |
|---|---|---|
| Agent жете алмайтын жүйе: мәселелер тізімі, дерекқор, браузер, жаңарып тұратын құжаттама | **MCP сервері** | Сыртқы құралдар мен деректерді agent-ке жалғаудың ашық стандарты |
| Апта сайын қайта түсіндіріп отыратын жұмыс: тексеру пішімі, релиз жазбасы | **Skill** | Ішінде `SKILL.md` бар қалта; контекстте тек сипаттамасы тұрады |
| Әңгімеңді басып қалатын жұмыс: журналдар, үлкен іздеу, diff тексеру | **Subagent** | Өз контекст терезесі бар, саған тек қорытынды қайтаратын көмекші |

Кез келген жағдайды дерлік іріктеп беретін сұрақ: **жетіспей тұрған нәрсе компьютеріңнен тыс па (MCP), басыңның ішінде ме (skill), әлде контекст терезеңнің ішінде ме (subagent)?**

## Бір MCP сервері қос: Claude Code құжаттамасы

Алдымен бір сөйлем: MCP сервері agent-ке бұрын оның қолында болмаған құрал береді — бұл жерде ол Claude Code-тың қазіргі құжаттамасының іздеуге келетін көшірмесі, сондықтан agent жадынан жауап беруді қояды. HTTP арқылы сырттан жұмыс істейді, аутентификация жоқ, орнататын ештеңе жоқ.

<Steps>
<Step title="Оны сеанстың ішінен емес, кәдімгі терминалыңнан қос">
Алдымен Claude Code-тан шық (`/exit`). `claude mcp add` — shell пәрмені.

<Terminal title="PowerShell / bash — екеуінде де осы екі жол">
```bash
claude mcp add --transport http claude-code-docs https://code.claude.com/docs/mcp
claude mcp list
```
</Terminal>

Сенің серверіңнің жолы `Connected` деп аяқталуы керек. Олай болмаса, `claude mcp list` пәрменін қайта орында — алғашқы байланыс баяу болуы мүмкін.
</Step>

<Step title="Тек құжаттамадан ғана жауап бере алатын нәрсені сұра">
`claude` пәрменін іске қос та, `/mcp` деп жаз — әр сервер үшін күй, қайта қосылу, аутентификация және өшіру сол жерде тұр. Енді prompt жаз:

<Prompt title="Құралды дәлелдейтін prompt" where="Claude Code · after adding the server">
```text
claude-code-docs сервері арқылы MCP_TIMEOUT не істейтінін және ол
маған қашан керек болатынын тауып бер. Құжаттамадан дәйексөз
келтір, өзіңнен ойлап шығарма.
```
</Prompt>

Құрал шақыруына рұқсат бер. Жазуға назар сал: онда сервердің аты тұрады, сондықтан жауап модельдің ішінен емес, құрал арқылы келгенін әрқашан көре аласың.
</Step>

<Step title="Оның саған қанша тұрғанын тексер">
`/context` пәрменін орында. Сервер дерлік байқалмайды — MCP құралдарының сипаттамалары әдепкіде кейінге қалдырылады, сондықтан құрал шақырылғанға дейін тек құрал аттары мен сервердің нұсқауы ғана жүктеледі ([шығындар](https://code.claude.com/docs/en/costs)). Бір ескертпесі бар: онсыз да қолыңда тұрған CLI құралы, мысалы `gh`, сол жұмысты істейтін MCP серверінен әлі де арзан. Қолданатын серверлеріңді қос, қалғанын өшіріп таста.
</Step>

<Step title="Оны тағы кім алатынын шеш">
Ауқымды жалауша шешеді, ал әдепкісі — ең тары.

- жалаушасыз → `local`: тек сен, тек осы жоба. `~/.claude.json` ішінде сақталады (Windows-та `%USERPROFILE%\.claude.json`).
- `--scope project` → repo түбіріне `.mcp.json` жазады; командаластарыңнан рұқсат сұралады.
- `--scope user` → тек сен, бірақ барлық жобада.

Claude Code `~/.claude/mcp.json` файлын да, оған ұқсас ешбір файлды да **оқымайды**, сондықтан ондай файлды ойдан шығарма. Кері қайтару үшін: `claude mcp remove claude-code-docs`.
</Step>

<Step title="Қосымша тапсырма: браузерді басқаратын жергілікті сервер (Node.js 18+ керек)">
<Terminal title="bash">
```bash
claude mcp add playwright -- npx -y @playwright/mcp@latest
```
</Terminal>

`--` белгісінен кейінгінің бәрі — жергілікті серверді іске қосатын пәрмен; сол `--` белгісін ұмыту — ең жиі кездесетін қате. Енді agent-тен тіркелу бетіңді ашып, форма шынымен жіберіле ме, соны айтып беруін сұра — бұл нағыз браузер арқылы өзін-өзі тексеру.

Алғаш іске қосқанда пакеттер жүктеледі, сондықтан уақыт бітіп қалуы мүмкін. PowerShell-де: `$env:MCP_TIMEOUT = "60000"; claude`.
</Step>
</Steps>

<Callout type="warn" title="Сенім — орнатудың бір бөлігі">
Repo ішіндегі `.mcp.json` серверлері сол repo-да `claude -p` пәрменін орындаған сәтте, ешқандай сенім сұрайтын терезесіз іске қосылады. Сенбейтін репозиторийде `claude -p` пәрменін орындама ([headless режимі](https://code.claude.com/docs/en/headless)).
</Callout>

## Бір skill жаз: `/cc-docs`

Бір сөйлем: skill — ішінде `SKILL.md` бар қалта, ол agent-ке бір рәсімді бір рет үйретеді, сондықтан сен оны қайта-қайта теруді қоясың — әрі сен шақырғанға дейін ол контекст терезеңнен тыс тұрады.

Lab 03-те сен `/preflight` жазғансың — ешқандай кіріс алмайтын skill. Бұл біреуі аргумент қабылдайды әрі жаңа ғана қосқан серверіңді жүргізеді, сондықтан осы практиканың екі жартысы бір-біріне жалғанады.

<Steps>
<Step title="Қалта жаса">
<Terminal title="PowerShell">
```powershell
New-Item -ItemType Directory -Force .claude\skills\cc-docs
```
</Terminal>

<Terminal title="macOS / Linux">
```bash
mkdir -p .claude/skills/cc-docs
```
</Terminal>
</Step>

<Step title="SKILL.md файлын жаз">
`.claude/skills/cc-docs/SKILL.md` файлын жасап, ішіне дәл мынаны жаз:

```markdown
---
name: cc-docs
description: Look up a Claude Code command or setting in the official docs and answer with a quote. Use whenever I ask how something in Claude Code works.
argument-hint: what to look up
---
Look up "$ARGUMENTS" using the claude-code-docs MCP server.

Answer in exactly this shape:
1. One sentence: what it is.
2. The exact command or setting, in a code block.
3. One sentence: when it does not apply, or how it breaks.

Quote the docs. If the server does not answer, say so instead of
answering from memory.
```

`$ARGUMENTS` — пәрмен атынан кейін терген нәрсең, сондықтан `/cc-docs plan mode` де, `/cc-docs Ctrl+B` де бір файлдан жұмыс істейді. `argument-hint` аттан кейін не теру керегін жазып қояды. Мұнда `disable-model-invocation` жолы әдейі жоқ: бұл skill тек оқиды, сондықтан agent оған өз бетінше қол созса да қауіпсіз.
</Step>

<Step title="Қайта іске қос та, жүктелгенін тексер">
Skill-дер тек іске қосылу кезінде оқылады, сондықтан шығып, `claude` пәрменін қайта орында. `/` теріп, тізімнен `cc-docs` тауып ал, немесе қазір жүктеліп тұрғанның бәрін көру үшін `/skills` деп жаз.
</Step>

<Step title="Оны іске қос, содан кейін дәл сол сұрақты кәдімгі сөзбен қой">
<Terminal title="Claude Code сеансының ішінде">
```text
/cc-docs plan mode
```
</Terminal>

Он минут бұрын қосқан серверің арқылы тартылған үш бөлік, дәл сол ретпен келеді. Енді `how does plan mode work?` деген қарапайым сұрақты теріп, салыстыр. Skill модельді ақылдырақ еткен жоқ. Ол нәтиженің пішінін әр жолы бірдей етті — жауапты түгел оқымай, көзбен шолып өтуге дәл осы мүмкіндік береді.
</Step>

<Step title="Немесе келесісін agent-тің өзіне жаздыр">
<Prompt title="Skill жазатын prompt" where="Claude Code · in your project folder">
```text
.claude/skills/ ішінде release-note деген жоба skill-ін жаса.
Ол соңғы 5 commit-ті оқып, техникалық емес оқырманға арналған
4 жолдық релиз жазбасын қазақша және ағылшынша жазсын.
Тек қолмен шақырылатын болсын. Жазбас бұрын SKILL.md файлын
маған көрсет.
```
</Prompt>
</Step>
</Steps>

<Callout type="tip" title="Skill-ді бұзатын төрт ереже">
`name` — кіші әріп пен дефис, ең көбі 64 таңба, әрі қалтаның атымен дәл келуі керек. `description` оның не істейтінін **және** қашан қолданылатынын айтады — agent оны жүктеу-жүктемеуді дәл сол сөйлем бойынша шешеді. Мәтін бөлігін шамамен 500 жолдан асырма. Жанама әсері бар кез келген нәрсеге `disable-model-invocation: true` қой.
</Callout>

<Deeper title="Неге мұның бәрін жай ғана CLAUDE.md ішіне жазбасқа?">
Себебі CLAUDE.md **әр** сеанстың басында жүктеледі, сондықтан оның әр жолы әр жолы контекст жейді — оны 200 жолдан асырма. Skill-дер оның орнына біртіндеп ашуды қолданады: шамамен 100 token метадерек әрқашан жүктеледі, мәтін бөлігі (5 000 token-нан аз болғаны жөн) тек қатысы болғанда, ал сілтеме жасалған файлдар тек керек болған сәтте жүктеледі ([Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)).

Skill-дер — ашық стандарт, тек Claude-қа ғана тән мүмкіндік емес ([agentskills.io](https://agentskills.io)). Өз қолыңмен жазатын «/» пәрмендері енді соларға біріктірілді: `.claude/commands/deploy.md` да, `.claude/skills/deploy/SKILL.md` да саған `/deploy` береді.

Skill — орындалатын нұсқау: тек сенетін көздеріңнен ғана орнат, әрі қосымша келген скриптті іске қоспай тұрып оқып шық.
</Deeper>

## Бір тексеруді subagent-ке тапсыр

Бір сөйлем: subagent — өз контекст терезесі, өз жүйелік prompt-ы, өз құралдар тізімі және рұқсаттары бар екінші Claude — ол шулы жұмысты істеп, саған қорытынды қайтарады, сондықтан негізгі әңгімең таза қалады.

Дайындары бұрыннан бар: Explore (тек оқитын іздеу), Plan (plan mode кезіндегі зерттеу) және general-purpose. Енді өзіңдікін жазып ал.

<Steps>
<Step title="Алдымен commit жаса — бұл шынымен маңызды">
<Terminal title="PowerShell / bash">
```bash
git add -A
git commit -m "before delegating to a subagent"
```
</Terminal>

Subagent жасаған өзгерістерді `/rewind` әдетте **қайтармайды**. Бақылау нүктелері (checkpoint) — жергілікті қайтару, git — тұрақты қайтару. Тапсырар алдында әр жолы commit жаса.
</Step>

<Step title="Subagent файлын жаз">
`.claude/agents/security-reviewer.md` файлын жаса:

```markdown
---
name: security-reviewer
description: Reviews code for security vulnerabilities
tools: Read, Grep, Glob, Bash
model: opus
---
You are a senior security engineer. Look for injection, auth flaws,
secrets in code, insecure data handling. Give line references and fixes.
```

`name` мен `description` — жалғыз міндетті өріс. Қалғанының бәрі — қалауыңша бұрайтын тетік: `tools`, `disallowedTools`, `model`, `permissionMode`, `maxTurns`, `isolation: worktree`. Қарапайым көмекшілерге `model: haiku` қойсаң, шот та кішірейеді.

Ескірек нұсқаулықпен жүргендерге ескертпе: v2.1.198 нұсқасынан бастап `/agents` енді басқару панелін ашпайды — ол саған осы файлдардың орнын көрсетеді.
</Step>

<Step title="Оның қолына diff-ті бер">
<Prompt title="Таза контексте тексеретін prompt" where="Claude Code · after the agent has written code">
```text
Соңғы commit-імнің diff-іне security-reviewer agent-ін қолдан.

Мына ретпен тексер:
1. Дұрыстық: ол CLAUDE.md пен бет талап еткен нәрсені істей ме?
2. Қауіпсіздік: енгізілген деректерді тексеру, кодтағы құпия
   деректер, қауіпсіз емес әдепкі мәндер.
3. Ауқым: тапсырма талап етпеген нәрсе өзгерді ме?

Тек дұрыстыққа, қауіпсіздікке немесе айтылған талаптарға әсер
ететін олқылықтарды ғана жаз. Әрқайсысы үшін: файл мен жол, не
бұзылады, нақты сәтсіз сценарий, ұсынылатын түзету. Стиль
жөніндегі ескертулерді бөлек тізімге шығар.
Байыпты ештеңе таппасаң, соны ашық айт.
```
</Prompt>

Agent атын `@` арқылы атап, оны күштеп шақыруға болады, немесе бүкіл сеансты сол agent ретінде жүргіз: `claude --agent security-reviewer`.
</Step>

<Step title="Жұмыс қай жерде болғанына назар сал">
Ол жұмыс істеп тұрғанда `/tasks` жүріп жатқан жұмысты тізеді, ал `Ctrl+B` оны фонға жібереді. Ол қайтып оралғанда `/context` пәрменін орында: көрсеткіш дерлік қозғалмаған, өйткені grep нәтижесі де, оқылған файлдар да сенің терезеңде емес, subagent-тің терезесінде қалды. Содан кейін `/usage` орында — жазылым бойынша ол шығынды skill-дерге, subagent-терге және MCP серверлеріне бөліп көрсетеді, сондықтан бүгінгі үш қосымшаң да бір жерде тұрады.
</Step>
</Steps>

<Compare a="Бұрын: бір agent, бір терезе" b="Кейін: көзі таза тексеруші">
<div slot="a">Кодты жазған agent сол кодты өзі тексереді. Оның grep нәтижесі сенің терезеңді толтырады, әрі ол он минут бұрын өзі шығарған жұмысты қорғап отыр.</div>
<div slot="b">Бөлек контекст өзі жазбаған diff-ті қарайды. Subagent шуды өз ішіне сіңіріп, тек тапқандарын қайтарады — Anthropic-тің үздік тәжірибелеріндегі «жазушы / тексеруші» үлгісі.</div>
</Compare>

<Deeper title="Subagent дұрыс жауап болмайтын жағдай">
Anthropic-тің 2026 ж. қаңтардағы нұсқаулығы шығын туралы тура айтады: бірнеше agent-пен істелген жұмыс сол тапсырмада жалғыз agent-тің token-інен әдетте 3–10 есе көп жейді, сондықтан алдымен бір agent-тің қолынан келетіннің бәрін сарқып ал. Мәселені жақсырақ жазылған prompt немесе `/clear` шешетін болса, subagent-ке мүлде бармай-ақ қой ([бірнеше agent-ті қашан және қалай қолдану керек](https://claude.com/blog/building-multi-agent-systems-when-and-how-to-use-them)).

Сол жазбадағы жобалау ережесі — көпшілік дәл осы жерде қателеседі: **лауазым бойынша емес, контекст бойынша бөл.** Мүмкіндікті жасаған agent оның тестін де өзі жазсын, өйткені контекст онсыз да қолында; жоспарлаушы / кодшы / тестілеуші деп бөлсең, әр қолдан-қолға беруде ақпарат жоғалады. Cognition мұны одан да қатаң қояды — әр әрекеттің астында айтылмаған шешім жатыр, ал екі agent бір-біріне қайшы шешім қабылдаса, бүтіннің өзі бұзылып шығады ([Don't Build Multi-Agents](https://cognition.com/blog/dont-build-multi-agents)).

Әдепкі жинақ: негізгі жұмысқа бір agent, зерттеуге subagent-тер, diff-ке таза контекстегі тексеруші. Қатар жазатын agent-терді тек әрқайсысының өз файлы болғанда ғана қос — ол Lab 07-де.
</Deeper>
