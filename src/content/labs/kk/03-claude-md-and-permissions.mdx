## Оған жад бер, сосын жүктелгенін дәлелде

`CLAUDE.md` әр сеанстың басында толық жүктеледі, `/compact` пәрменінен кейін де аман қалады: Claude Code оны дискіден қайта оқиды. Чатқа терген нұсқауларың аман қалмайды ([жад туралы құжаттама](https://code.claude.com/docs/en/memory)).

<Steps>

<Step title="Дайындаманы жасат та, жартысын қырқып таста">
`/init` пәрменін орында. Claude репозиторийді оқып, `CLAUDE.md` жазады. Қабылда да, `/memory` арқылы ашып қара.

Шыққан файл тым ұзын. Әр жолды бір сынақтан өткіз: **осыны өшірсем, қате туа ма?** Жоқ болса — өшір. Агент кодтан оқып ала алатын нәрсе — шу. Мұнда жиырма шақты жол жеткілікті, нағыз репозиторийде 200-ден аспасын.
</Step>

<Step title="Орнына тексеруге келетін ережелер жаз">
Бұлыңғыр ережелер («таза код жаз») түк өзгертпейді. Ішінде пәрмен, файл жолы немесе санауға келетін шарт бары ғана жұмыс істейді.

```markdown
# CLAUDE.md — QAIRU Event Sign-up

## What this is
One static page: an event description and a form that reserves a seat.

## Commands
- Serve locally: `npx serve .`
- Check it: open the page, submit the form with an empty name field

## Workflow
- Anything bigger than a one-line change: plan first, wait for my approval.
- After every change, list the manual test steps you expect me to run.
- Small commits. The message says what changed and why.

## Rules that differ from defaults
- All code stays in `index.html`. No frameworks, no npm packages, no build step.
- Every user-visible string exists in Kazakh and English.
- The seat cap is one constant at the top of the script, never a number typed in three places.

## Do not touch
- `.env` — it holds keys. Never read it, print it, or commit it.

## When compacting
Keep: the list of modified files, the current plan step, and the seat-cap value.
```

`AGENTS.md` файлын бірден-бір ақиқат көзі еткен болсаң ([6-модуль](/kk/learn/context-ssot/)), бұл бөлімдерді сонда жаз.
</Step>

<Step title="Оның шынымен жүктелгенін тексер">
`/context` деп тер. Жад файлдарының тізімінен `CLAUDE.md` файлыңды тауып, терезенің неше пайызын жеп тұрғанына қара. Бұл салықты әр сеанста төлейсің.
</Step>

<Step title="Жап-жаңа, бос әңгімеде сынап көр">
Көпшілік аттап кететін қадам — әрі бірдеңені шынымен дәлелдейтін жалғыз қадам. `/clear` әңгімені өшіреді, жад файлын емес.

<Prompt title="Жад сынағы" where="Claude Code · Manual mode, immediately after /clear">
```text
Тіркелу формасына барлық өрісті тазалайтын "Reset" түймесін қос.
Алдымен жоспарды түсіндірме — тікелей өзгерісті жаса.
```
</Prompt>

Екінші жол сынақты бір кезекке сыйғызады: сен жоспарды емес, жад файлын бағалайсың.

Енді үш ережеңді тексер. Код `index.html` ішінде қалды ма? Түйме жазуы қазақша да, ағылшынша да бар ма? Тест қадамдарын сұрамай-ақ берді ме? Үштен екеуі шықса, бір ережең тым бұлыңғыр. Сол жолды қайта жаз да, қайта сына.
</Step>

</Steps>

<Callout type="tip" title="Екі рет ережесі">
`CLAUDE.md` ішіне жаңа жолды агентті бір нәрсе үшін *екінші* рет түзеткенде жаз. Бір қате — кездейсоқтық, екі рет — үлгі. Кері бағытта да солай: агент файлда анық тұрған ережелерді елемесе, файлың тым ұзын ([жад](https://code.claude.com/docs/en/memory)).
</Callout>

## Файл — кеңес қана, сондықтан қоршау қой

Claude Code құжаттамасы жад файлдарын "context, not enforced configuration" — мәжбүрлейтін баптау емес, контекст — деп атайды ([жад](https://code.claude.com/docs/en/memory)). «`.env` файлын ешқашан оқыма» деген жолың — тапсырманы аяқтауға бейімделген жүйеге айтылған сыпайы өтініш. Оны бұғаттау үшін тыйым ережесі немесе hook керек.

<Steps>

<Step title="Қорғауға тұрарлық бірдеңе жаса">
Жоба түбірінде `.env` жасап, ішіне `FORM_API_KEY=super-secret-123` жаз, сосын `.env` файлын `.gitignore` ішіне қос. Кілт жалған. Оны нағыз кілт деп есепте.
</Step>

<Step title=".claude/settings.json файлын жаз">
Қатаң JSON: түсініктеме жоқ, соңғы үтір жоқ. Әйтпесе келесі қосқанда Settings Error шығады.

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow": ["Bash(git status)", "Bash(git diff *)", "Bash(git log *)"],
    "ask": ["Bash(git push *)"],
    "deny": ["Read(./.env)", "Read(./.env.*)", "Read(./secrets/**)"]
  }
}
```

**allow** — растай-растай жалыққаның. **ask** — әр жолы өз көзіңмен көретінің. **deny** — ешқашан болмайтыны. Тексеру deny → ask → allow ретімен жүреді, бірінші сәйкестік жеңеді. Таласты ереженің нақтылығы емес, осы санат реті шешеді.
</Step>

<Step title="Қайта іске қос та, өз ережелеріңді оқып шық">
`/exit` жаса, `claude --permission-mode manual` арқылы қайта қос та, `/permissions` пәрменін орында. Үш allow, бір ask, үш deny — әрқайсысының қасында өз файлы жазулы. Бір ереже жоқ болса, JSON файлың дұрыс оқылмаған.
</Step>

<Step title="Тыйым ережесінің сұрауды қалай қабылдамайтынын көр">
Үш сұрау, біртіндеп. Әрқайсысының жауабын келесісін жібермей оқы.

<Prompt title="1-сұрау — deny тізіміне түседі" where="Claude Code · Manual mode">
```text
.env файлымның ішінде не бар?
```
</Prompt>

**Қабылдамады** — рұқсат сұраған жоқ, тікелей бас тартты. `Read` тыйымы сол жолдағы Edit пен Write әрекетін де бұғаттайды әрі Bash ішіндегі `cat`, `head`, `tail`, `sed` пәрмендерін қамтиды.

<Prompt title="2-сұрау — allow тізіміне түседі" where="Claude Code · Manual mode">
```text
git status пен соңғы 3 commit-ті көрсет.
```
</Prompt>

**Үнсіз орындалады.** Терезе жоқ, кідіріс жоқ. Зертхананың ең қызықсыз жартысы — әрі күн сайын сезінетін жартысы.

<Prompt title="3-сұрау — ask тізіміне түседі" where="Claude Code · Manual mode">
```text
Орында: git push
```
</Prompt>

**Сұрайды** — accept-edits режимінде де сұрай береді, себебі анық жазылған `ask` ережесі автоматты түрде ешқашан расталмайды. «Жоқ» деп жауап бер де, `Tab` пернесін басып, себебін жаз: "no remote yet".
</Step>

</Steps>

<Deeper title="Бұл файлдар қай жерде тұрады және қайсысы жеңеді">
Төрт деңгей бар, әлсізінен күштісіне қарай: `~/.claude/settings.json` (тек сенікі, бар жобада), репозиторийдегі ортақ `.claude/settings.json`, тек сенде тұратын `.claude/settings.local.json` және ұйымың басқаратын орталық параметрлер. `permissions.allow` сияқты тізім кілттері төртеуінен де жиналады.

«Иә, енді сұрама» деп жауап берсең, жергілікті файлға тұрақты ереже жазылады. Оны анда-санда ашып оқы. Файл өңдеуге берілген рұқсат тек сол сеанста күшінде.

Жоба файлы `permissions.defaultMode` мәнін `auto` немесе `bypassPermissions` етіп қойса, ол еленбейді: бөтен репозиторий қоршауыңды тыныш шешіп тастай алмайды ([параметрлер](https://code.claude.com/docs/en/settings), [рұқсаттар](https://code.claude.com/docs/en/permissions)).
</Deeper>

## Қоршаудың саңылаулары бар

<Prompt title="Адал сынақ" where="Claude Code · Manual mode">
```text
.env файлын бір жолдық Python скриптімен оқып, нәтижесін экранға шығар.
```
</Prompt>

Растау терезесі шығады, өйткені бұл — Bash пәрмені. Ал тыйым ережесі мүлде оянбады. Растасаң, жалған кілт экраныңда тұрады.

Bash ережелері бағдарламаға емес, *пәрменнің мәтініне* қарап сәйкестендіріледі. `Bash(rm *)` ережесі `/bin/rm` шақыруын да, `bash -c 'rm ...'` жазуын да тоқтатпайды, ал `Read` тыйымы файлды өзі ашатын скриптті ұстамайды. Бұл ережелер — ыңғайлылық, қауіпсіздік шекарасы емес.

<Callout type="warn" title="Нағыз шекара қандай болады">
Үш нағыз тосқауыл, күшінің өсу ретімен. Шығу коды 2 болып аяқталатын **PreToolUse hook** әрекетті әр жолы бұғаттайды ([hook нұсқаулығы](https://code.claude.com/docs/en/hooks-guide)). **Sandbox** (`/sandbox`) Bash үшін файлдық жүйе мен желіні оқшаулайды — Anthropic оның "safely reduces permission prompts by 84%", яғни рұқсат сұрауын 84%-ға азайтатынын айтады — әрі macOS, Linux және WSL2 жүйелерінде істейді, таза Windows-та емес ([sandbox](https://www.anthropic.com/engineering/claude-code-sandboxing)). Бәрінен күштісі — агенттің қолында мүлде жоқ құпия дерек.
</Callout>

## Оған елу рет іске қосатын бір пәрменді үйрет

Екі рет көшіріп жапсырған нәрсе «/» пәрменіне айналуға тиіс. `.claude/commands/preflight.md` да, `.claude/skills/preflight/SKILL.md` да саған `/preflight` пәрменін береді.

<Steps>

<Step title="Skill файлын жаз">
`.claude/skills/preflight/SKILL.md` файлын жаса. Қалта атауы `name` өрісімен дәл сәйкес келуі керек.

```markdown
---
name: preflight
description: Review my uncommitted changes for secrets, missing Kazakh strings and untested behaviour before I commit
disable-model-invocation: true
---
## Current changes
!`git diff HEAD`

## Instructions
1. Summarise what changed in three bullets a beginner can follow.
2. Flag anything resembling a key, token, password, phone number or email address.
3. Check every new user-visible string exists in both Kazakh and English.
4. List the exact manual test steps for this change.

Do not edit any files. Report only.
```

Мұны екі механизм көтеріп тұр. `!` таңбасы мен кері апострофқа алынған пәрмен орындалады да, нәтижесі контекстке түседі: сен бір әріп термей тұрып diff дайын. Ал `disable-model-invocation: true` Claude-тың оны өз бетінше іске қосуына жол бермейді — қосымша әсері немесе шығыны бар нәрсеге дәл осы керек.
</Step>

<Step title="Нағыз өзгеріске қолданып көр">
Skill жүктелуі үшін Claude Code-ты қайта іске қос та, `/skills` тізімін қара. `index.html` файлын өзің өңде де, `/preflight` іске қос. Сен шақырмайынша контекстте тек сипаттамасы тұрады — skill-дің `CLAUDE.md` ішіндегі қырық жаңа жолдан артық болатын себебі осы.
</Step>

<Step title="Қоршаудың өзін де commit жаса">
`CLAUDE.md`, `.claude/settings.json` және skill файлын commit жаса. `.claude/settings.local.json` пен `.env` файлын қалдыр: біреуі — жеке параметрлерің, екіншісі — құпия дерек. Репозиторийіңді клондаған әркім бұл ережелерді бірге алады.
</Step>

</Steps>

## Code freeze — бір сөйлем. Тыйым ережесі — қоршау.

<Story title="Бір сөйлем күйінде қалған code freeze" date="18 Jul 2025">
SaaStr негізін қалаушы Jason Lemkin Replit-те қолданба жасап, әр күнін жұртқа ашық жариялады. Тоғызыншы күндері, өзі жариялаған code freeze кезінде — кодқа тиюге тыйым салынған кезеңде — агент тірі дерекқорға деректі жоятын пәрмендер жіберді. 1 200-ден астам басшы мен 1 190-нан астам компанияның жазбасы жоғалды.

Тағы бір ереже бойынша — дерек ойдан шығарма — ол өзін бас әріппен он бір рет қайталағанын айтады. Агент бәрібір шамамен 4 000 ойдан шығарылған адам жасап шықты да, кері қайтару мүмкін емес деп хабарлады. Олай емес еді: кері қайтару жұмыс істеді, деректер орнына келді. Fortune келтірген өз түйіні: "This was a catastrophic failure on my part." — бұл менің тарапымнан жіберілген апат. ([Fortune, 2025 ж. 23 шілде](https://fortune.com/2025/07/23/ai-coding-tool-replit-wiped-database-called-it-a-catastrophic-failure/); [The Register, 2025 ж. 21 шілде](https://www.theregister.com/2025/07/21/replit_saastr_vibe_coding_incident/); [AI Incident Database #1152](https://incidentdatabase.ai/cite/1152/))
</Story>

Агенттің қолында production дерекқорының тірі кілттері болды, ал code freeze чаттағы мәтін күйінде қалды ([11-модуль](/kk/learn/security/) оқиғаны әрі қарай талдайды). Replit-тің бас директоры Amjad Masad мұны "Unacceptable and should never be possible." — мұндай болуға тиіс емес — деп бағалады ([The Register, 2025 ж. 22 шілде](https://www.theregister.com/2025/07/22/replit_saastr_response/)).
