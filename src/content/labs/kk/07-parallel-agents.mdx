git worktree — сол репозиторийдің өз тармағына көшірілген екінші қалтасы. Екі қалта деген — екі agent *бір мезетте* өңдей алады әрі бір-бірінің файлдарын ешқашан көрмейді. Ал мұның жақсы ой болған-болмағанын кейінгі біріктіру кезінде білесің.

## Екі agent-ті де іске қос, сосын біріктір

<Steps>

<Step title="Бір шешімді бөліспейтін екі мүмкіндік таңда">
QAIRU Event Sign-up үшін: **қараңғы режим қосқышы** және орын толғанда форманы өшіріп тастайтын **бос орын санағышы**. Біреуі — сыртқы көрініс, екіншісі — логика. Екеуінің де бір-бірінің қандай шешім қабылдағанын білуі қажет емес.

Алдымен екеуін де біреуден сөйлеммен жазып шық. Жаза алмасаң — бұл екі тапсырма емес, біреу, ал сен бір сеанста қалғаның жөн.
</Step>

<Step title="Алаңды тазала">
Негізгі қалтада:

<Terminal title="bash">
```bash
git status
git log --oneline
```
</Terminal>

Status таза болуға тиіс. Қазір дискіде осы репозиторийдің үш көшірмесі пайда болады; қайсысында commit жасалмаған жұмыс жатқанын өзің болжап отыратын күйге түспе.
</Step>

<Step title="A терминалы — бірінші agent-ті өз worktree-сінде іске қос">
<Terminal title="bash">
```bash
claude --worktree dark-mode
```
</Terminal>

Сол бір жалауша бүкіл дайындықты өзі жасайды: `.claude/worktrees/dark-mode/` жолындағы жаңа қалта және `worktree-dark-mode` деген жаңа тармақ. `git worktree add` пәрменін өзің ешқашан орындамайсың. Енді оған шекарасы айқын prompt бер:

<Prompt title="Бірінші agent" where="Claude Code · worktree dark-mode">
```text
Тіркелу бетіне қараңғы режим қосқышын қос.

Шекара — тек мына файлдарды өзгертуге болады:
  index.html, styles.css
CLAUDE.md, README.md файлдарына және .github/ ішіндегі ештеңеге тиіспе.

Талаптар:
- Беттің жоғарғы жолағында көзге көрінетін қосқыш болсын.
- Таңдау localStorage жадында сақталып, бет алғаш салынғанға дейін
  қолданылсын.
- Форма белгілері мен жіберу түймесі екі режимде де оқылатындай қалсын.

CLAUDE.md файлын ұстан. Жұмыс істегенде осы тармақта бір жолдық хабармен
commit жаса.
Содан кейін тоқта да, не өзгерткеніңді әр файлды бөлек атап айтып бер.
```
</Prompt>
</Step>

<Step title="B терминалы — екінші agent-ті сол негізгі қалтадан іске қос">
Жобаның **сол** қалтасында екінші терминал терезесін аш. Оны бірінші worktree-нің ішінде ашпа.

<Terminal title="bash">
```bash
claude --worktree seats-left
```
</Terminal>

<Prompt title="Екінші agent" where="Claude Code · worktree seats-left">
```text
Тіркелу бетіне бос орын санағышын қос.

Шекара — тек мына файлдарды өзгертуге болады:
  index.html, seats.js
styles.css, CLAUDE.md, README.md файлдарына тиіспе.

Талаптар:
- Форманың жанында "N орын қалды" деп көрсет, саны бір ғана сыйымдылық
  тұрақтысынан алынсын.
- N нөлге жеткенде жіберу түймесі өшірілсін де, "орын қалмады" деген
  қысқа хабар шықсын.
- Бүкіл логика seats.js ішінде тұрады. index.html бір script тегі мен бір
  контейнер div алады.

CLAUDE.md файлын ұстан. Жұмыс істегенде осы тармақта бір жолдық хабармен
commit жаса.
Содан кейін тоқта да, не өзгерткеніңді әр файлды бөлек атап айтып бер.
```
</Prompt>

Екі prompt-та да ортақ нәрсеге көңіл бөл: файлдардың нақты тізімі. Осы беттегі ең пайдалы жол — сол.
</Step>

<Step title="C терминалы — олар жұмыс істеп жатқанда сырттан бақыла">
<Terminal title="bash">
```bash
git worktree list
```
</Terminal>

Үш жазба: негізгі жұмыс көшірмең және екі worktree. Әр worktree-дегі `index.html` файлын браузерде аш та, мүмкіндіктерді бөлек-бөлек тексер — дәл қазір, agent-тер әлі жұмыс істеп тұрғанда. Өз ақысын ақтайтын бөлік осы: әр жарты екіншісімен кездеспей тұрып тексеріліп қояды.

Жобаңда тәуелділіктер болса, орнату пәрменін әр worktree-нің ішінде орында. Worktree — жаңа жұмыс көшірмесі; `node_modules` онымен бірге көшпейді.
</Step>

<Step title="Әр тармақты оны жазбаған контекстпен тексер">
Бірінші agent commit жасағаннан кейін, A терминалында:

<Prompt title="Таза көзбен тексеру" where="Claude Code · either worktree, after the commit">
```text
Осы тармақтың main тармағына қарсы diff-ін subagent арқылы тексер.
Тек дұрыстық мәселелерін және CLAUDE.md ережелері бұзылған жерлерді айт —
стильді де, атау таңдауын да емес.
Тапқан әр нәрсең үшін мынаны бер: қай файлда, не бұзылады және ең шағын
түзету қандай.
Шын мәселе таппасаң, соны айт та тоқта.
```
</Prompt>

Subagent өзінің жеке контекст терезесін алады, сондықтан жаңа ғана жазған кодына бауыр басып қалмайды; [үздік тәжірибелер беті](https://code.claude.com/docs/en/best-practices) дәл осылай бөлуді ұсынады. Шын мәселені түзет, қалғанын елемей қой да, B терминалында қайтала.
</Step>

<Step title="Екі сеанстан да шық және worktree-лерді сақтап қал">
Әр сеанстан шық. Өзгерісі жоқ worktree шыққан кезде өзі жойылады; commit-і барын сақтау керек пе, жою керек пе деп сұрайды. **Сақтауды таңда** — ол тармақтар саған әлі керек.
</Step>

<Step title="Бірінші тармақты біріктір">
Негізгі қалтаға қайт:

<Terminal title="bash">
```bash
git merge worktree-dark-mode
```
</Terminal>

Бұл таза түседі: тармақ басталғаннан бері main тармағында ештеңе қозғалған жоқ.
</Step>

<Step title="Екінші тармақты біріктір де, қайшылықпен бетпе-бет кел">
<Terminal title="bash">
```bash
git merge worktree-seats-left
```
</Terminal>

Екі agent те `index.html` файлын өзгертті. Олардың өңдеулері файлдың бір аймағына түскенде git тоқтап, файлға қайшылық белгілерін қалдырады — бұл жерде бұл күтілген нәтиже, қате емес. Оны негізгі қалтадағы agent-ке тапсыр:

<Prompt title="Қайшылықты шешу" where="Claude Code · main folder, mid-merge">
```text
git merge index.html файлында қайшылық белгілерін қалдырды.
Оларды ЕКІ мүмкіндік те аман қалатындай шеш: қараңғы режим қосқышы және
бос орын санағышы.
Қайшылықтан құтылу үшін мүмкіндіктің бірін де өшіріп тастама.
Файл тазарғанда маған шешілген бөлікті көрсет, содан кейін біріктіруді
commit жасамай тұрып браузерде екі мүмкіндікті де тексеретін нақты
қадамдарды бер.
```
</Prompt>

Commit жасамай тұрып, шешілген бөлікті өзің оқып шық. Қайшылықты шешіп жатқан agent ниетті болжап отыр, ал мүмкіндіктен айырылудың ең арзан жолы — оның жартысын үнсіз тастап кеткен шешімді қабылдау.

Егер git екі өңдеуді де шағымданбай біріктірсе, жол нөмірлері жағынан жолың болғаны. Бетті бәрібір аш та, екі мүмкіндіктің де орнында тұрғанын тексер — таза біріктіру әлі жұмыс істейтін бет деген сөз емес.
</Step>

<Step title="main тармағында тексер, сосын тазала">
Бетті негізгі қалтадан аш. Екі мүмкіндік те бірге жұмыс істеуге тиіс: режимді ауыстырып көр де, орын санағышының әлі жаңарып тұрғанына көз жеткіз.

<Terminal title="bash">
```bash
git worktree remove .claude/worktrees/dark-mode
git worktree remove .claude/worktrees/seats-left
git branch -d worktree-dark-mode worktree-seats-left
git worktree list
```
</Terminal>

Тармақтарды жоймай тұрып worktree-лерді алып таста — git бір жерде әлі көшірілген күйі тұрған тармақты жоюдан бас тартады. Соңғы пәрмен тек негізгі жұмыс көшірмеңді көрсетуге тиіс.

Қаласаң, қарапайым shell-ден мына аяқтаманы жаса:

<Terminal title="bash">
```bash
claude -p "Summarize what changed in the last 3 commits in 5 bullets" \
  --allowedTools "Bash(git log *),Bash(git diff *)" --output-format json
```
</Terminal>

JSON ішінен `result`, `session_id` және `total_cost_usd` өрістерін тап. Осы беттің шын мәні — соңғы өрісте. `--allowedTools` жолы әсемдік үшін емес: `-p` Manual режимінде басталады, сондықтан рұқсат бермеген пәрменің тікелей қабылданбай қалады, ал қысқаша мазмұн журналды мүлде оқымай жазылады.
</Step>

</Steps>

## Қайшылық — кездейсоқтық емес, сабақтың өзі

Worktree-лер **файлдарды** оқшаулайды. Олар **шешімдерді** оқшауламайды. Екі agent те `index.html` үшін жақсы код жазды, бірақ бәрібір соқтығысты: екеуінің де екіншісі дәл сол жоғарғы жолақты қайта құрап жатқанынан хабары болмады. Файлдар жағын Claude Code өзі мәжбүрлейді: worktree сеансының ішінде ол негізгі жұмыс көшірмесіне бағытталған өңдеулерді, пәрмендерді және git-ті басқа жаққа бұруды бұғаттайды. Шешім жағын ешнәрсе мәжбүрлемейді. Оны сен істейсің.

Сондықтан нағыз шеберлік `--worktree` деп теруде емес. Ол — ештеңе басталмай тұрып жұмысты файлдар шекарасымен бөлуде:

- **Әр файлдың бір иесі.** Жоғарыдағыдай, әр prompt-та файлдарды атап жаз.
- **Мүмкін болса, екінші agent-ке өз файлын бер.** `seats.js` тек сол үшін бар: сонда `index.html` файлының бір ғана жолы өзгеруге тиіс болады.
- **Бір жүгірісте екі agent-ке CLAUDE.md, README немесе баптау файлдарын ешқашан өңдетпе.**
- **Сол күні біріктір.** Ескіріп кеткен тармақ шағын қайшылықты жарты күндік жұмысқа айналдырады.

## Екі agent бір нәтижені қымбат алудың жолы болатын кез

Cognition компаниясының көп агентті жүйелерге қарсы [2025 ж. маусымдағы дәлелі](https://cognition.com/blog/dont-build-multi-agents) ең маңызды жерде күшінде қалады: әр әрекеттің астында айтылмаған шешім жатыр, ал бір-біріне қайшы шешімдер нашар нәтиже береді. Олардың мысалы — ойын жасап жатқан екі subagent: біреуі Mario үлгісіндегі фон салады, екіншісі оған жараспайтын құс салады, ал жетекші agent-ке бір-біріне келмейтін екі жорамалды біріктіру қалады. Бұл — сенің `index.html` қайшылығың, тек үлкейтілген түрі.

Сондықтан жұмыс кезекпен істелетін болса, екі жартысы бір шешімді бөліссе, өткірірек жазылған prompt немесе `/clear` пәрмені жеткілікті болса, не автоматты тексеруің болмаса — екінші agent-тен бас тарт. Нағыз жұмыстан аман шығатын әдепкі жинақ қарапайым: бір agent, зерттеуге subagent-тер, тексеруге таза контекст.

<Deeper title="Тармақ шын мәнінде қайдан басталады және .env файлыңды қалай ала кетесің">
Әдепкіде worktree-лер `worktree.baseRef: "fresh"` мәнін пайдаланады — олар қашықтағы әдепкі тармақтан (`origin/HEAD`) тарайды, ал remote болмаса жергілікті HEAD-ке қайта оралады. Оның орнына push жасалмаған жұмысты қосқың келсе, Claude Code параметрлеріне `{"worktree": {"baseRef": "head"}}` деп жаз.

Жаңа жұмыс көшірмесінде елемей кетілген файлдар да, тәуелділіктер де болмайды. Саған керек елеусіз файлдарды — мысалы, `.env` — gitignore синтаксисімен `.worktreeinclude` файлына тізіп жаз, сонда олар әр жаңа worktree-ге көшіріледі. Тәуелділіктерді қайта орнатасың. Дереккөз: [worktree құжаттамасы](https://code.claude.com/docs/en/worktrees).
</Deeper>

<Deeper title="Қолмен жасайтын жол — кез келген құралда жұмыс істейді">
`--worktree` — Claude Code-тың қарапайым git үстіне салған қабығы, сондықтан дәл сондай оқшаулау Cursor-да, Codex-те, Gemini CLI құралында немесе жай ғана редакторда да жұмыс істейді:

<Terminal title="bash">
```bash
git worktree add ../qairu-dark-mode -b dark-mode
git worktree list
git worktree remove ../qairu-dark-mode
```
</Terminal>

Содан кейін сол қалтаға `cd` пәрменімен кір де, қалаған agent-іңді іске қос.
</Deeper>

<Deeper title="Екеуден үлкені: /batch, agent командалары және workflow-лар">
`/batch` пәрменінен кейін бір нұсқау жазсаң, ол үлкен өзгерісті worktree-мен оқшауланған 5–30 subagent-ке бөледі, әрқайсысы өз pull request-ін ашады. Agent командалары — жетекші және ортақ тапсырма тізімі бар командаластар — тәжірибелік мүмкіндік, әдепкіде өшірулі, ал құжаттамада командаластардың worktree-мен оқшауланбайтыны ашық жазылған, сондықтан файлдарды қолмен бөлесің; шығындар беті командаластар plan mode-та жұмыс істегенде оларды қарапайым сеанстың token-інен шамамен жеті есе көп деп бағалайды. Динамикалық workflow-лар әдепкіде бір мезетте 16 agent-ке дейін жүргізеді. Алдымен [agent-тер туралы шолуды](https://code.claude.com/docs/en/agents) оқы — үшеуі де сен жаңа ғана өлшеген шотты еселейді.
</Deeper>
