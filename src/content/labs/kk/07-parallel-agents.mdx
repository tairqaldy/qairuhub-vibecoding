## Қайшылық — кездейсоқтық емес, сабақтың өзі

Worktree-лер **файлдарды** оқшаулайды, **шешімдерді** емес. Екі agent те `index.html` үшін жақсы код жазды, бірақ соқтығысты: екеуі де екіншісінің дәл сол жоғарғы жолақты қайта құрап жатқанын білмеді. Файлдар жағын Claude Code мәжбүрлейді — worktree сеансы негізгі жұмыс көшірмесіне бағытталған өңдеулерді, пәрмендерді және git-ті бұғаттайды. Шешім жағы — сенің мойныңда.

Нағыз шеберлік `--worktree` деп теруде емес. Ол — жұмыс басталмай тұрып оны файл шекарасымен бөлуде:

- **Әр файлдың бір иесі.** Жоғарыдағы екі prompt-тағыдай.
- **Екінші agent-ке өз файлын бер.** `seats.js` тек сол үшін бар: сонда `index.html` файлының бір ғана жолы өзгереді.
- **Бір жүгірісте екі agent-ке CLAUDE.md, README немесе баптау файлдарын өңдетпе.**
- **Сол күні біріктір.** Ескірген тармақ шағын қайшылықты жарты күндік жұмысқа айналдырады.

## Екі agent бір нәтижені қымбат алудың жолы болатын кез

Cognition компаниясының көп агентті жүйелерге қарсы [2025 ж. маусымдағы дәлелі](https://cognition.com/blog/dont-build-multi-agents) ең маңызды жерде күшінде: әр әрекеттің астында айтылмаған шешім жатыр, ал бір-біріне қайшы шешімдер нашар нәтиже береді. Бұл — сенің `index.html` қайшылығың, тек үлкейтілген түрі.

Нағыз жұмыстан аман шығатын әдепкі жинақ қарапайым: бір agent, зерттеуге subagent-тер, тексеруге таза контекст. Толық дәлелі — [14-модульде](/kk/learn/multi-agent/).

<Deeper title="Тармақ шын мәнінде қайдан басталады және .env файлыңды қалай ала кетесің">
Әдепкіде worktree-лер `worktree.baseRef: "fresh"` мәнін пайдаланады: олар қашықтағы әдепкі тармақтан (`origin/HEAD`) тарайды, ал remote болмаса жергілікті HEAD-ке оралады. Push жасалмаған жұмыс керек болса, Claude Code параметрлеріне `{"worktree": {"baseRef": "head"}}` деп жаз.

Жаңа жұмыс көшірмесінде елеусіз файлдар да, тәуелділіктер де болмайды. Керек елеусіз файлдарды — мысалы, `.env` — gitignore синтаксисімен `.worktreeinclude` файлына жаз, сонда олар әр worktree-ге көшіріледі. Тәуелділіктерді қайта орнатасың. Дереккөз: [worktree құжаттамасы](https://code.claude.com/docs/en/worktrees).
</Deeper>

<Deeper title="Қолмен жасайтын жол — кез келген құралда жұмыс істейді">
`--worktree` — Claude Code-тың қарапайым git үстіне салған қабығы, сондықтан дәл сондай оқшаулау Cursor-да, Codex-те, Gemini CLI-де немесе жай редакторда да жұмыс істейді:

<Terminal title="bash">
```bash
git worktree add ../qairu-dark-mode -b dark-mode
git worktree list
git worktree remove ../qairu-dark-mode
```
</Terminal>

Сосын сол қалтаға `cd` пәрменімен кір де, қалаған agent-іңді іске қос.
</Deeper>

<Deeper title="Екеуден үлкені: /batch, agent командалары және workflow-лар">
`/batch` пәрменінен кейін бір нұсқау жазсаң, ол үлкен өзгерісті worktree-мен оқшауланған 5–30 subagent-ке бөледі, әрқайсысы өз pull request-ін ашады. Agent командалары — жетекші және бір тапсырма тізіміндегі командаластар — тәжірибелік мүмкіндік, әдепкіде өшірулі әрі worktree-мен оқшауланбайды, сондықтан файлдарды қолмен бөлесің; шығындар беті оларды plan mode-та қарапайым сеанстың token-інен шамамен жеті есе көп деп бағалайды. Динамикалық workflow-лар бір мезетте 16 agent-ке дейін жүргізеді. Алдымен [agent-тер туралы шолуды](https://code.claude.com/docs/en/agents) оқы: үшеуі де сен жаңа ғана өлшеген шотты еселейді.
</Deeper>
