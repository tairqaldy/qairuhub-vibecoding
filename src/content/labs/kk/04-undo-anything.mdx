<Lead>
Әр мақұлдау *бір жақты есік* сияқты көрінеді. Олай емес. Өз жобаңды әдейі бұз — үш түрлі зиян, үш түрлі қайтар жол — сонда есік екі жаққа да ашылады.
</Lead>

Бұл — git сабағы емес; commit пен тармақтар [09-модульде](/kk/learn/git-and-github/). Бұл — жүйке сабағы. Anthropic-тің дерегінше, Claude Code пайдаланушылары рұқсат сұрауларының 93%-ын мақұлдайды, ал нәтижесін былай атайды: «approval fatigue, where people stop paying close attention» — мақұлдаудан шаршау, адамдар мұқият қарауды қояды ([Anthropic, 2026 ж. 25 наурыз](https://www.anthropic.com/engineering/claude-code-auto-mode)). Сен де әр diff-ті мәңгі оқып отырмайсың. Сені қорғайтыны — қырағылық емес, қалпына келтіре білу.

## Үш қабат, бір сұрақ

| Қабат | Нені қайтарады | Неге тимейді | Қайда тересің |
|---|---|---|---|
| Rewind — `Esc` `Esc` немесе `/rewind` | осы сеанста Claude-тың өңдеу құралдары өзгерткен файлдарды және әңгіменің өзін | Bash пәрмені тиген нәрсенің бәріне, субагент өңдеулерінің көбіне, өз қолыңмен енгізген өзгерістерге, машинаңнан тыс ештеңеге | Claude Code ішінде, мәзір түрінде |
| `git restore` / `git reset --hard` | бақылаудағы файлдарды — соңғы commit-тің күйіне | бақылауда жоқ жаңа файлдарға, commit-ке түсіп қойғанның бәріне | өз терминалыңда |
| `git revert` | тарихта тұрған commit-ті — дәл керісін жаңа commit етіп жазу арқылы | commit жасалмаған жұмысқа | өз терминалыңда |

Төтенше жағдайдың бәріне дерлік бір сұрақ жауап береді: **ол commit-ке түсті ме?** Түссе — `git revert`. Түспесе — `git restore` немесе `git reset --hard`. Бәрі сол бір Claude сеансының ішінде болып, тек өңдеу құралдары қатысты ма? Онда rewind екеуін де озады: промптыңды енгізу жолына қайтарып береді, сен сөзін түзейсің.

Rewind — мерзімі бар сеанс ыңғайлылығы. Ал git — құлағанда түсетін еденің. Агентті git білмейтін қалтада ешқашан жұмыс істетпе ([checkpoint құжаттамасы](https://code.claude.com/docs/en/checkpointing)).

## Үш рет бұз, үш рет қайтар

<Steps>

<Step title="Екі терезе аш та, сақтау нүктесін жаса">
Сол жақ терезе — Claude Code. Оң жақ терезе — сол қалтадағы кәдімгі терминал. Екеуін де ашық ұста: агент жұмыс істегенде репозиторий қалай өзгеретінін көріп отырасың.

<Terminal title="терминал — оң жақ терезе">
```bash
cd qairu-event
git status
git log --oneline
```
</Terminal>

`git status` өзгерген бірдеңе көрсетсе, оны қазір сақтап ал.

<Terminal title="терминал — оң жақ терезе">
```bash
git add -A
git commit -m "save point before lab 04"
```
</Terminal>

`git log --oneline` шығарған ең жоғарғы жол — сенің бастапқы нүктең.

Сол жақ терезеде агентті manual режимінде іске қос:

<Terminal title="терминал — сол жақ терезе">
```bash
claude --permission-mode manual
```
</Terminal>
</Step>

<Step title="Әдейі бұз да, зиянның commit-ке жетуіне жол бер">
Claude-қа қаламайтын нәрсеңді тапсыр да, commit жасауына рұқсат бер. Әр қадамды мақұлда.

<Prompt title="1-бұзу — commit-ке түскен зиян" where="Claude Code · manual mode">
```text
index.html файлын қайта жаз: барлық тақырып БАС ӘРІППЕН жазылсын,
орын есептегішінің орнына "SOON" деген сөз тұрсын, ал тіркелу
формасының өрістеріндегі мәтін белгілерін өшір.

Содан соң өзгерісті "restyle" деген хабармен commit жаса.
```
</Prompt>

Бетті браузерде аш. Нашарлап кетті, ал форма экраннан оқу бағдарламасына мүлдем жарамайды. Жақсы.

<Terminal title="терминал — оң жақ терезе">
```bash
git log --oneline
```
</Terminal>

Ең үстінде жаңа жол тұр: `restyle`. Зиян тарихыңның ішінде, демек екінші де, үшінші де қабат жарамайды.
</Step>

<Step title="1-кері қайтару — git revert, басқалардың көзінше қауіпсіз">
<Terminal title="терминал — оң жақ терезе">
```bash
git revert --no-edit HEAD
git log --oneline
```
</Terminal>

Браузерді жаңарт: бет орнына келді. Бірақ `git log` бір жол **ұзарды**, қысқарған жоқ. `git revert` ештеңені өшірген жоқ: ол нашар commit-тің дәл керісін үстіне жазды.

Бұл — әдейі жасалған: commit-тің көшірмесі біреуде бар болса, тарихты қайта жазу оның клонын бүлдіреді, ал үстіне commit қосу бүлдірмейді. `--no-edit` мәтін редакторын ашпайды. Ескі commit үшін оның қысқа hash-ын бер: `git revert --no-edit <hash>`.
</Step>

<Step title="Тағы бұз, commit-сіз">
<Prompt title="2-бұзу — commit-ке түспеген былық, үстіне сұрамаған файлың" where="Claude Code · manual mode">
```text
Беттің фонын ашық қызғылт түске ауыстыр, форманың үстіне алып
"SOLD OUT!!!" деген баннер қой, сосын өз пайымдауыңды жазып,
scratch-notes.md деген жаңа файл жаса.

Ештеңені commit жасама.
```
</Prompt>

Мақұлда. Енді бір қалтада екі мәселе тұр: бақылаудағы файл өзгерді, әрі git бұрын көрмеген жаңа файл пайда болды. Екеуіне екі түрлі пәрмен керек.

<Terminal title="терминал — оң жақ терезе">
```bash
git status
git diff --stat
```
</Terminal>

`index.html` — «Changes not staged for commit» бөлімінде. `scratch-notes.md` — «Untracked files» бөлімінде.
</Step>

<Step title="2-кері қайтару — commit-ке түспеген былықты лақтырып таста">
<Terminal title="терминал — оң жақ терезе">
```bash
git restore .
git status
```
</Terminal>

`index.html` таза. Ал `scratch-notes.md` әлі сол жерде: `git restore` git бақылап отырған файлдарды ғана қалпына келтіреді.

Бақылауда жоқ қалдықтарды атпас бұрын қарап ал: `-n` нені жоятынын тізіп береді, ештеңеге тимейді.

<Terminal title="терминал — оң жақ терезе">
```bash
git clean -nd
```
</Terminal>

<Callout type="danger" title="git clean — осы практикадағы кері қайтарылмайтын жалғыз пәрмен">
`git clean -fd` бақылауда жоқ файлдарды біржола жояды. Git-те олардың көшірмесі болған емес, сондықтан revert те, reset те, rewind те қайтара алмайды. Алдымен `-nd` тізімін оқып шық — әр жолы. `.gitignore` ішіндегі файлдар аман қалады, тек `-x` қоспасаң; үйреніп жүргенде оны қоспа.
</Callout>

Ол тізімде `scratch-notes.md` жалғыз тұруға тиіс. Енді шынымен жой — іске асыратыны `-f`.

<Terminal title="терминал — оң жақ терезе">
```bash
git clean -fd
git status
```
</Terminal>

`git restore` пәрменін бір жағдай жеңеді: `git add` орындалып қойған болса, нашар өзгеріс дайындау аймағында жатады да, `git restore .` оны файлдарыңа қайта әкеледі. Ол жағдайдың балғасы — `git reset --hard`: бақылаудағы әр файлды, дайындалғанын да, дайындалмағанын да, соңғы commit-тің күйіне қайтарады. Қазір орында: каталогың таза, ештеңе жоғалтпайсың.

<Terminal title="терминал — оң жақ терезе">
```bash
git reset --hard HEAD
git status
```
</Terminal>

<Callout type="warn" title="Бұл пәрменді агент неге сенің орныңа орындамайды">
Auto mode режимінде Claude Code-тың классификаторы commit-ке түспеген жұмысты `git reset --hard` үлгісімен лақтыруды және күшпен push жасауды әдепкі күйде бұғаттайды ([рұқсат режимдері](https://code.claude.com/docs/en/permission-modes)). Қайтарып ала алмайтын жұмысты жоятын пәрменді өз қолыңмен тересің.
</Callout>
</Step>

<Step title="3-кері қайтару — rewind, git-ке мүлде тимей">
Кез келген кері қайтарудан бұрын ең арзан қимыл: Claude жауап беріп жатқанда `Esc` пернесін **бір рет** бас. Ол тоқтайды, істеп үлгергені сақталады — қате өзгерістің жартысын түзету тұтасын түзетуден жеңіл.

Енді бетті үшінші рет бұз да, оны сеанстың ішінен қайтарып ал.

<Prompt title="3-бұзу — таза өңдеу құралының зияны" where="Claude Code · manual mode">
```text
Байт үнемдеу үшін index.html ішіндегі әр CSS класының атын
бір әріпке ауыстыр. Commit жасама.
```
</Prompt>

Мақұлда да, өзің күтіп отыратын файлға не істегенін қарап шық. **Енгізу жолын бос қалдырып**, `Esc` пернесін екі рет бас (немесе `/rewind`).

Мәзір промпттарыңды тізеді; кезекті бастайтын әр промпт checkpoint жасайды. Алты таңдау: Restore code and conversation, Restore conversation, Restore code, Summarize from here, Summarize up to here, Never mind.

CSS кластарын қайта атаған промптты таңда да, **Restore code and conversation** дегенді бас. Файл бұрынғы күйіне оралады, ал промпт енгізу жолыңда қайта пайда болады — сөзін түзей саласың. Сыртынан тексер:

<Terminal title="терминал — оң жақ терезе">
```bash
git status
```
</Terminal>

Ештеңе өзгермеген. Агенттің жұмысын бірде-бір git пәрменінсіз кері қайтардың.

<Deeper title="Отырған сеансыңды жоғалтпай, бір идеяны сынап көр">
Rewind сені бір сызықтың бойымен артқа жылжытады. Баламаны сынап, бастапқы әңгімені сақтап қалу үшін құжаттама `/branch` немесе `claude --continue --fork-session` дегенді ұсынады: артыңда бір тарих, алдыңда екі болашақ ([checkpoint құжаттамасы](https://code.claude.com/docs/en/checkpointing)).
</Deeper>
</Step>

<Step title="Жоқ болып шығатын кері қайтаруды тап">
Осы практикадағы ең маңызды қадам. Тоқсан секунд кетеді.

<Prompt title="Қосалқы әсер" where="Claude Code · manual mode">
```text
Өңдеу құралыңмен емес, shell пәрменімен ішінде бүгінгі күн жазылған
agent-was-here.txt деген файл жаса. Содан соң тоқта.
```
</Prompt>

Bash шақыруын мақұлда. (Claude бәрібір өңдеу құралына жармасса, былай жауап бер: `өңдеу құралыңмен емес, shell пәрменімен орында`.)

`Esc` `Esc` басып, кодты сол промптқа дейінгі күйге қайтар. Сосын оң жақ терезеге қара:

<Terminal title="терминал — оң жақ терезе">
```bash
git status
```
</Terminal>

`agent-was-here.txt` әлі орнында. Rewind ештеңені қалпына келтірген жоқ: checkpoint Claude-тың *өңдеу құралдары* тиген нәрсені ғана түсіреді, ал Bash пәрмені — өңдеу құралы емес.

Оны өз қолыңмен тазала. Алдымен құрғақ жүріс:

<Terminal title="терминал — оң жақ терезе">
```bash
git clean -nd
```
</Terminal>

Тізімде бір ғана жол — күткен файлың. Енді шынымен.

<Terminal title="терминал — оң жақ терезе">
```bash
git clean -fd
```
</Terminal>
</Step>

<Step title="Тазалықпен аяқта да, ережені жазып қой">
<Terminal title="терминал — оң жақ терезе">
```bash
git status
git log --oneline
```
</Terminal>

Жұмыс каталогы таза. Бастапқы нүктеңнің үстінде екі жол: бұзу және оны жоққа шығарған revert. Бүгін істеген қалған әрекетің еш із қалдырмады.

Енді мұны [03-практикадағы](/kk/labs/claude-md-and-permissions/) жад файлында тұрақты ережеге айналдыр:

<Prompt title="Әдетті үйрет" where="Claude Code · any mode">
```text
Мынаны CLAUDE.md файлына, бұрыннан бар ережелер бөліміне, бір жолмен қос:
екіден көп файлға тиетін кез келген өзгерісті бастамас бұрын тоқта да,
алдымен commit жаса деп маған айт.
```
</Prompt>

Өңдеуді мақұлда да, CLAUDE.md файлын commit жаса. Келесі аптада сен емес, агент саған еске салады.
</Step>

</Steps>

## Кері қайтаруы жоқ зиян

Үш қабат файлдарыңды жабады. Одан әрісін — жоқ.

<Callout type="danger" title="Осы практикадағы ештеңе мыналарды кері қайтара алмайды">
Басқалар pull жасап үлгерген `git push`. Жарияланып кеткен deploy. Дерекқордан өшірілген жол. Жіберіліп кеткен хабарлама. Bash-тағы `rm` пәрмені жойған файлдар. Ақылы API-ден алынған ақы. Ашық репозиторийге түсіп кеткен API кілті — ол кілт күйді, жалғыз шешім: жаңасын алып, ескісінің күшін жою.

Ереже «бәрін тексер» емес. Қай әрекет машинаңнан шығып кететінін біл де, соларға келгенде баяула.
</Callout>

<Deeper title="Тым артқа reset жасап, бір commit-тен айырылдың. git reflog-ты байқап көр.">
`git reflog` тармақ ұшы соңғы кездері болған бүкіл орынды тізеді — жаңа ғана лақтырғандарын қоса. Қатеден бұрынғы жолды тап, hash-ын көшір де, артқа оралу үшін `git reset --hard <hash>` орында — немесе алдымен қарап алу үшін `git checkout -b rescue <hash>`.

Шегі дәл: reflog тек commit-ті біледі. Commit жасалмаған жұмыс еш жерде жазылмаған, оны ештеңе таба алмайды.
</Deeper>
