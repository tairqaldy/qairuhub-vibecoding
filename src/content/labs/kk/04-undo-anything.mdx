<Lead>
Агентпен жұмыс істегенде адамдардың көбі бір себептен баяулайды: әр мақұлдау *бір жақты есік* сияқты көрінеді. Олай емес. Жиырма минут бөліп, өз жобаңды әдейі бұз — үш түрлі зиян, үш түрлі қайтар жол — содан кейін есік екі жаққа да ашылатын болады.
</Lead>

Бұл — git сабағы емес. Бұл — жүйке сабағы. Anthropic-тің дерегінше, Claude Code пайдаланушылары рұқсат сұрауларының 93%-ын мақұлдайды, ал нәтижесін былай атайды: «approval fatigue, where people stop paying close attention» — мақұлдаудан шаршау, адамдар мұқият қарауды қояды ([Anthropic, 2026 ж. 25 наурыз](https://www.anthropic.com/engineering/claude-code-auto-mode)). Сен де әр diff-ті мәңгі оқып отырмайсың. Сондықтан сені шын қорғайтын дағды — қырағылық емес, қалпына келтіре білу.

## Үш қабат және араларынан таңдап беретін жалғыз сұрақ

| Қабат | Нені қайтарады | Неге тимейді | Қайда тересің |
|---|---|---|---|
| Rewind — `Esc` `Esc` немесе `/rewind` | осы сеанста Claude-тың өз өңдеу құралдары өзгерткен файлдарды, қоса әңгіменің өзін | Bash пәрмені тиген нәрсенің бәріне, субагент өңдеулерінің көбіне, өз қолыңмен енгізген өзгерістерге, машинаңнан тыс ештеңеге | Claude Code ішінде, мәзір түрінде |
| `git restore` / `git reset --hard` | бақылаудағы файлдарды — соңғы commit-тің күйіне | бақылауда жоқ жаңа файлдарға және commit-ке түсіп қойған нәрсенің бәріне | өз терминалыңда |
| `git revert` | тарихта тұрған commit-ті — оның дәл керісін жаңа commit етіп жазу арқылы | commit жасалмаған жұмысқа | өз терминалыңда |

Кезексіз жағдайлардың барлығына дерлік бір сұрақ жауап береді: **ол commit-ке түсті ме?** Түссе — `git revert`. Түспесе — `git restore` немесе `git reset --hard`. Ал бәрі сол бір Claude сеансының ішінде болса әрі тек өңдеу құралдары қатысса, rewind екеуін де басып озады: ол промптыңды енгізу жолына қайтарып береді, сен сөзін түзеп, қайта жібересің.

Rewind — мерзімі бар сеанс ыңғайлылығы. Ал git — құлағанда түсетін еденің. Агентті git білмейтін қалтада ешқашан жұмыс істетпе ([checkpoint құжаттамасы](https://code.claude.com/docs/en/checkpointing)).

## Үш рет бұз, үш рет қайтар

<Steps>

<Step title="Екі терезе аш та, сақтау нүктесін жаса">
Сол жақ терезе — Claude Code. Оң жақ терезе — сол қалтадағы кәдімгі терминал. Екеуін де практика бойы ашық ұста: агент жұмыс істеп жатқанда репозиторийдің қалай өзгеретінін көзбен көріп отырғаның керек.

<Terminal title="терминал — оң жақ терезе">
```bash
cd qairu-event
git status
git log --oneline
```
</Terminal>

`git status` өзгерген бірдеңе көрсетсе, оны дәл қазір сақтап ал. Хабардың әдемі болуы міндет емес.

<Terminal title="терминал — оң жақ терезе">
```bash
git add -A
git commit -m "save point before lab 04"
```
</Terminal>

`git log --oneline` шығарған ең жоғарғы жол — енді сенің бастапқы нүктең. Практиканың қалған бөлігінде не істесең де, бәрі соның үстіне қонады.

Сол жақ терезеде агентті manual режимінде іске қос — сонда әр әрекет орындалмай тұрып көрініп тұрады:

<Terminal title="терминал — сол жақ терезе">
```bash
claude --permission-mode manual
```
</Terminal>
</Step>

<Step title="Әдейі бұз да, зиянның commit-ке жетуіне жол бер">
Claude-қа шынымен қаламайтын нәрсеңді тапсыр да, нәтижені сақтауына рұқсат бер. Әр қадамды мақұлда.

<Prompt title="1-бұзу — commit-ке түскен зиян" where="Claude Code · manual mode">
```text
index.html файлын қайта жаз: барлық тақырып БАС ӘРІППЕН жазылсын,
орын есептегішінің орнына "SOON" деген сөз тұрсын, ал тіркелу
формасының өрістеріндегі мәтін белгілерін өшір.

Содан соң өзгерісті "restyle" деген хабармен commit жаса.
```
</Prompt>

Бетті браузерде аш. Нашарлап кетті, ал форма енді экраннан оқу бағдарламасымен келген адамға мүлдем жарамайды. Жақсы.

<Terminal title="терминал — оң жақ терезе">
```bash
git log --oneline
```
</Terminal>

Ең үстінде жаңа жол тұр: `restyle`. Зиян енді тарихыңның ішінде, демек екінші де, үшінші де қабат жарамай қалды.
</Step>

<Step title="1-кері қайтару — git revert, басқалардың көзінше қауіпсізі">
<Terminal title="терминал — оң жақ терезе">
```bash
git revert --no-edit HEAD
git log --oneline
```
</Terminal>

Браузерді жаңарт: бет орнына келді. Бірақ `git log` енді бір жол **ұзарды**, қысқарған жоқ. `git revert` ештеңені өшірген жоқ. Ол нашар commit-ті оқып, оның дәл керісін есептеп шығарды да, сол керісін үстіне жаңа commit етіп сақтады.

Қатені өшіре салғаннан гөрі нашар естіледі. Шын мәнінде жақсы: commit-тің көшірмесі біреуде бар болса, тарихты қайта жазу оның клонын бүлдіреді, ал үстіне бір commit қосу ешқашан бүлдірмейді. `--no-edit` мәтін редакторын ашпай өтеді. Ескілеу commit үшін оның қысқа hash-ын бер: `git revert --no-edit <hash>`.
</Step>

<Step title="Тағы бұз — бірақ бұл жолы commit жасатпа">
<Prompt title="2-бұзу — commit-ке түспеген былық, үстіне сұрамаған файлың" where="Claude Code · manual mode">
```text
Беттің фонын ашық қызғылт түске ауыстыр, форманың үстіне алып
"SOLD OUT!!!" деген баннер қой, сосын өз пайымдауыңды жазып,
scratch-notes.md деген жаңа файл жаса.

Ештеңені commit жасама.
```
</Prompt>

Мақұлда. Енді бір қалтада екі түрлі мәселең бар: бақылаудағы файлдың өзгергені және git бұрын-соңды көрмеген жап-жаңа файлдың пайда болғаны. Екеуіне екі түрлі пәрмен керек — жаңадан бастағандар дәл осы жерде уақыт жоғалтады.

<Terminal title="терминал — оң жақ терезе">
```bash
git status
git diff --stat
```
</Terminal>

`index.html` — «Changes not staged for commit» бөлімінде. `scratch-notes.md` — «Untracked files» бөлімінде. Айырмасын есте сақта.
</Step>

<Step title="2-кері қайтару — commit-ке түспеген былықты лақтырып таста">
<Terminal title="терминал — оң жақ терезе">
```bash
git restore .
git status
```
</Terminal>

`index.html` таза. Ал `scratch-notes.md` әлі сол жерде тұр: `git restore` git бұрыннан бақылап отырған нәрсені ғана қалпына келтіреді.

Бақылауда жоқ қалдықтарға келгенде — атпас бұрын қарап ал. `-n` нені жоятынын тізіп береді де, ештеңеге тимейді.

<Terminal title="терминал — оң жақ терезе">
```bash
git clean -nd
```
</Terminal>

<Callout type="danger" title="git clean — осы практикадағы кері қайтарылмайтын жалғыз пәрмен">
`git clean -fd` бақылауда жоқ файлдарды біржола жояды. Git-те олардың көшірмесі ешқашан болған емес, сондықтан revert те, reset те, rewind те оларды қайтара алмайды. Алдымен `-nd` тізімін оқып шық — әр жолы, әрқашан — және ол тізімде өзіңе керегі жоқ екеніне көз жеткіз. `.gitignore` ішіндегі жолдар аман қалады, тек `-x` қоспасаң; үйреніп жүргенде оны қоспаған жөн.
</Callout>

Ол тізімде `scratch-notes.md` жалғыз тұруға тиіс. Енді оны шынымен жой: іске асыратын нәрсе — `-f`.

<Terminal title="терминал — оң жақ терезе">
```bash
git clean -fd
git status
```
</Terminal>

`git restore` пәрменін бір жағдай жеңеді: сен немесе агент `git add` орындап қойған болса, нашар өзгеріс дайындау аймағында жатады да, `git restore .` оны файлдарыңа қайта көшіріп әкеледі. Ол жағдайдың балғасы — бақылаудағы әр файлдың дайындалған да, дайындалмаған да нұсқасын бір-ақ рет лақтырып, бәрін соңғы commit-тің күйіне қайтарады. Қазір орында: жұмыс каталогың бұрыннан таза, сондықтан ештеңе жоғалтпайсың, ал пәрменнің қай жерде тұрғанын біліп қаласың.

<Terminal title="терминал — оң жақ терезе">
```bash
git reset --hard HEAD
git status
```
</Terminal>

<Callout type="warn" title="Бұл пәрменді агент неге сенің орныңа орындамайды">
Auto mode режимінде Claude Code-тың классификаторы commit-ке түспеген жұмысты `git reset --hard` үлгісімен лақтыруды және күшпен push жасауды әдепкі күйде бұғаттайды ([рұқсат режимдері](https://code.claude.com/docs/en/permission-modes)). Қайтарып ала алмайтын жұмысты жоятын пәрмендерді өз қолыңмен, әдейі тересің.
</Callout>
</Step>

<Step title="3-кері қайтару — rewind, git-ке мүлде тимей">
Алдымен — кез келген кері қайтарудан бұрын келетін арзандау қимыл: Claude жауап беріп жатқанда `Esc` пернесін **бір рет** бас. Ол тоқтайды, ал істеп үлгерген жұмысы сақталып қалады. Қате өзгерістің жартысын түзету — тұтасын түзетуден жеңіл.

Енді бетті үшінші рет бұз да, оны сеанстың ішінен қайтарып ал.

<Prompt title="3-бұзу — таза өңдеу құралының зияны" where="Claude Code · manual mode">
```text
Байт үнемдеу үшін index.html ішіндегі әр CSS класының атын
бір әріпке ауыстыр. Commit жасама.
```
</Prompt>

Мақұлда да, өзің күтіп отыратын файлға не істегенін қарап шық. Енді **енгізу жолын бос қалдырып**, `Esc` пернесін екі рет бас (немесе `/rewind` деп тер).

Промпттарың тізілген мәзір ашылады — кезекті бастайтын әр промпт checkpoint жасайды. Алты таңдау шығады: Restore code and conversation, Restore conversation, Restore code, Summarize from here, Summarize up to here, Never mind.

CSS кластарын қайта атаған промптты таңда да, **Restore code and conversation** дегенді бас. Файлдар бұрынғы күйіне оралады, ал сол промпт енгізу жолыңда қайта пайда болады — қайта теріп отырмай, сөзін түзейсің. Сыртынан тексер:

<Terminal title="терминал — оң жақ терезе">
```bash
git status
```
</Terminal>

Ештеңе өзгермеген. Сен агенттің жұмысын бірде-бір git пәрменін тықпай кері қайтардың.

<Deeper title="Отырған сеансыңды жоғалтпай, бір идеяны сынап көр">
Rewind сені бір сызықтың бойымен артқа жылжытады. Баламаны сынап көріп, бастапқы әңгімені бүтін қалдыру үшін құжаттама `/branch` пәрменін немесе `claude --continue --fork-session` арқылы қайта бастауды ұсынады: артыңда бір тарих, алдыңда екі болашақ ([checkpoint құжаттамасы](https://code.claude.com/docs/en/checkpointing)).
</Deeper>
</Step>

<Step title="Жоқ болып шығатын кері қайтаруды тап">
Осы практикадағы ең маңызды қадам, оған тоқсан секунд кетеді.

<Prompt title="Қосалқы әсер" where="Claude Code · manual mode">
```text
Өңдеу құралыңмен емес, shell пәрменімен ішінде бүгінгі күн жазылған
agent-was-here.txt деген файл жаса. Содан соң тоқта.
```
</Prompt>

Bash шақыруын мақұлда. (Claude бәрібір өңдеу құралына жармасса, былай жауап бер: `өңдеу құралыңмен емес, shell пәрменімен орында`.)

Енді `Esc` `Esc` басып, кодты сол промптқа дейінгі күйге қайтар. Сосын оң жақ терезеге қара:

<Terminal title="терминал — оң жақ терезе">
```bash
git status
```
</Terminal>

`agent-was-here.txt` әлі орнында тұр. Rewind ештеңені қалпына келтірген жоқ, өйткені checkpoint Claude-тың *өңдеу құралдары* тиген нәрсені ғана түсіріп алады — Bash пәрмені жасаған, жылжытқан не өшірген файлдарды емес, субагент өңдеулерінің көбін емес, басқа редакторда өз қолыңмен енгізген өзгерістерді емес, машинаңнан шығып кеткен ештеңені емес.

Оны өз қолыңмен тазала — бүкіл мәселе де сонда. Алдымен бұрынғыдай құрғақ жүріс:

<Terminal title="терминал — оң жақ терезе">
```bash
git clean -nd
```
</Terminal>

Тізімде бір ғана жол тұр, әрі ол — күткен файлың. Енді шынымен:

<Terminal title="терминал — оң жақ терезе">
```bash
git clean -fd
```
</Terminal>
</Step>

<Step title="Тазалықпен аяқта да, ережені жазып қой">
<Terminal title="терминал — оң жақ терезе">
```bash
git status
git log --oneline
```
</Terminal>

Жұмыс каталогы таза. Бастапқы нүктеңнің үстінде екі жол: бұзу және оны жоққа шығарған revert. Git қате мен түзетуді әдейі қатар ұстайды. Ал бүгін істеген қалған әрекеттерің еш із қалдырмады.

Соңғы отыз секунд — мұны 03-практикадағы жад файлына тұрақты ережеге айналдыр:

<Prompt title="Әдетті үйрет" where="Claude Code · any mode">
```text
Мынаны CLAUDE.md файлына, бұрыннан бар ережелер бөліміне, бір жолмен қос:

```
</Prompt>

Өңдеуді мақұлда да, CLAUDE.md файлын commit жаса. Келесі аптада сен емес, агент саған еске салады.

## Кері қайтаруы жоқ зиян

Үш қабат файлдарыңды жабады. Файлдарыңнан тысқары ештеңені жаппайды.

<Callout type="danger" title="Осы практикадағы ештеңе мыналарды кері қайтара алмайды">
Басқалар pull жасап үлгерген `git push`. Жарияланып кеткен deploy. Дерекқордан өшірілген жол. Жіберіліп кеткен хабарлама. Bash-тағы `rm` пәрмені жойған файлдар. Ақылы API-ден алынған ақы. Ашық репозиторийге түсіп кеткен API кілті — ол кілт күйді, жалғыз шешім: жаңасын алып, ескісінің күшін жою.

Сондықтан ереже «бәрін тексер» емес. Ереже мынау: қай әрекет машинаңнан шығып кететінін біл де, тек соларға келгенде ғана баяула.
</Callout>

<Deeper title="Тым артқа reset жасап, бір commit-тен айырылдың. git reflog-ты байқап көр.">
`git reflog` тармақ ұшының соңғы кездері болған бүкіл орнын тізіп береді — жаңа ғана лақтырып тастағандарын қоса. Қатеден бұрынғы жолды тап, hash-ын көшір де, артқа оралу үшін `git reset --hard <hash>` орында, немесе алдымен қарап алғың келсе, `git checkout -b rescue <hash>` деп қауіпсіз жерге қойып қой.

Шегі дәл: reflog тек commit-терді ғана біледі. Commit жасалмаған жұмыс еш жерде жазылмаған, сондықтан оны ештеңе таба алмайды.
</Deeper>
