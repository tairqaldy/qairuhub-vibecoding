<Lead>
Келесі жиырма бес минутта бос қалтадан жұмыс істейтін тіркелу бетіне жетесің. Ең құнды әрекетің пернетақта теру болмайды. Ол — *жоспарды оқу*, әрі әлі бірде-бір файлың жоқ кезде сол жоспардың бір жолын өзгерту.
</Lead>

Anthropic құжаттамасы ретті төрт сөзбен береді: explore, plan, implement, commit — жоспарлау режимі (plan mode) алғашқы екеуін атқарады ([үздік тәжірибелер](https://code.claude.com/docs/en/best-practices)). Себебі — қарапайым арифметика: зерттеудің бір қате жолы жоспардың бірнеше қате жолына, ал жоспардың бір қате жолы кодтың жүздеген қате жолына айналады. HumanLayer ережесі де содан шыққан: тек diff-ті емес, зерттеу мен жоспардың өзін тексер ([контекст инженериясы](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/ace-fca.md)).

Жоспар — басынан аяғына дейін оқып шығуға жететіндей қысқа. Оның diff-і — көз жүгіртіп қана өтетіндей ұзын. Арзанын оқы.

Бүгін **QAIRU Event Sign-up** жобасының алғашқы нағыз нұсқасын жасайсың: бір бет, бір іс-шара, орын брондайтын форма және кері санайтын есептегіш. Бәрі бір файлда: ешқандай framework те, build қадамы да жоқ.

## Бос қалтадан commit-ке дейінгі тоғыз қадам

<Steps>

<Step title="Агент тиіп үлгермей тұрып, қалтаны repo-ға айналдыр">
<Terminal title="bash">
```bash
mkdir qairu-event
cd qairu-event
git init
```
</Terminal>

Күтілетін нәтиже: `Initialized empty Git repository` және `qairu-event/.git/` деп аяқталатын жол. Windows PowerShell-де үшеуін `&&` емес, `;` арқылы тізбекте — ол жерде `&&` таңбасы `The token '&&' is not a valid statement separator` деп жазады.

`git init` пәрменін аттап кетпе. Claude Code өзінің өңдеу құралдары тиер алдында файлдардың сақтық көшірмесін түсіреді, бірақ checkpoint жүйесі Bash пәрмендері енгізген өзгерістерді де, субагент түзетулерінің көбін де, басқа терезеде өзің өзгерткен файлдарды да қадағаламайды ([checkpoint жүйесі](https://code.claude.com/docs/en/checkpointing)). Checkpoint — жергілікті кері қайтару. Git — тұрақты кері қайтару.
</Step>

<Step title="Жоспарлау режимінде баста да, шынымен сонда екеніңе көз жеткіз">
<Terminal title="bash">
```bash
claude --permission-mode plan
```
</Terminal>

Жаңа қалтада алғаш іске қосқанда, жұмыс кеңістігіне сенім туралы сұрау шығады — келісім бер. Содан кейін енгізу өрісінің астындағы күй жолағын оқы. Онда `plan mode on` деп тұруға тиіс.

Сеанс әлдеқашан ашылып қойған ба? Сол жазу шыққанша `Shift+Tab` тіркесімін бас. Басу саны әртүрлі: Pro, Max және Team тарифтерінде терминал сеансы енді **auto** режимінен басталады, сондықтан бірінші басқанда Manual-ға, сосын өңдеулерді қабылдауға, содан соң жоспарлауға өтеді — үш басу. Manual режимінен басталған сеансқа екі басу жетеді ([сеанс қай режимнен басталады](https://code.claude.com/docs/en/permission-modes#which-mode-a-session-starts-in)). Кейбір Windows жүйелерінде бұл тіркесім — `Alt+M`.
</Step>

<Step title="Бүкіл тапсырманы бір промптпен бер">
Мынаны дәл сол күйінде қой. Іс-шараның деректерін өзіңдікімен алмастыр немесе солай қалдыр.

<Prompt title="Жасау промпты" where="Claude Code · plan mode">
```text
Осы қалтада QAIRU Event Sign-up тіркелу бетін бір файл етіп жаса: index.html.
Ешқандай framework, build қадамы, жаңа тәуелділік болмасын. Бүкіл CSS пен JS index.html ішінде.

Бет БІР іс-шараны көрсетеді және келушіге орын брондауға мүмкіндік береді:
- іс-шараның атауы, күні, уақыты, өтетін жері және ол туралы екі сөйлем
- брондау формасы: аты, электрондық пошта, бір Reserve түймесі
- 40-тан басталып, әр брондаудан кейін бірге азаятын "қалған орын" есептегіші
- брондағандардың тізімі, ең жаңасы жоғарыда
- орын 0 болғанда: форма өшіріледі және бетте іс-шараның толғаны жазылады
- бет қайта жүктелгенде брондаулар сақталып қалады
- аты бос, поштасы бос немесе поштасында "@" жоқ болса, көрінетін хабармен қабылданбайды

Әзірге ешқандай код жазба.
1. Осы қалтада қазір не бар екенін және нені қайта пайдаланбақ екеніңді айт.
2. Жоспарды көрсет: реттелген қадамдар, әр қадам тиетін файл, әрі әр қадам үшін
   браузерде нақты нені басатынымды және нақты нені көретінімді жаз.
3. Не істемейтіңді тізіп бер, әрі менен растауды қажет ететін болжамдарыңды айт.

Тоқта да, менің мақұлдауымды күт. Мақұлдағанымда, басқа ештеңені өзгертпей тұрып,
мақұлданған жоспарды PLAN.md етіп сақта.
```
</Prompt>

Ол қалтаны оқып шығады, оқуға ғана арналған бір-екі пәрмен орындайды да, тапқандарымен және нөмірленген жоспармен оралады. `index.html` файлын жасамайды: жоспарлау режимінде сен мақұлдағанша бастапқы кодты өңдеуге тыйым салынған ([жоспарлау режимі](https://code.claude.com/docs/en/permission-modes#analyze-before-you-edit-with-plan-mode)). Ол жұмыс істеп тұрғанда `Ctrl+T` оның тапсырмалар тізімін ашып-жабады, ал `Ctrl+O` әңгіме жазбасын көрсетеді.
</Step>

<Step title="Жоспарды бүгін оқитын жалғыз мәтінің сияқты оқы">
Үш сұрақ.

1. **Әр қадамда мен орындай алатын тексеріс аталған ба?** «Брондау формасын жаса» дегеннің жұмыс істегенін білуге жол жоқ — бұл қадам емес, тілек. Агентке өзі орындай алатын тексеріс беру — осы курстағы ең көп пайда әкелетін әдет ([үздік тәжірибелер](https://code.claude.com/docs/en/best-practices)).
2. **Неге тиіспейтінін айтқан ба?** Шекарасы айтылмаған агент сен мүлде сұрамаған нәрселерді қайта реттеп тастайды.
3. **Қасымда отырған адамға түсіндіріп бере алмайтын қадам бар ма?** Кейін дәл сол қадам соққы береді.

Екі жауап көңілден шықпаса, **«No, keep planning»** дегенді таңда да, себебін жаз: `3 және 5-қадамда браузерде тексеру жоқ. Екеуін де мен нені басатынымды, нені көруім керегін жазып қайта жаз.`
</Step>

<Step title="Мақұлдар алдында бір жолды өзгерт">
`Ctrl+G` тіркесімін бас. Ұсынылған жоспар мәтін редакторыңда ашылады. Мынаны қос, сақта, жап.

<Prompt title="Өзің қосатын жол" where="Your editor · via Ctrl+G">
```text
- Келуші көретін әр жазба қазақша және ағылшынша болады. Беттің жоғарғы жолағындағы
  KK / EN түймесі екеуін ауыстырады және таңдауды есте сақтайды. Әдепкісі — қазақша.
```
</Prompt>

Дәл осы талап — бұл жобада бар, ал қарапайым тіркелу формасында жоқ нәрсе, әрі агент оны сен үшін өзі ойлап таппайды. Енді мақұлдайтын жоспарың ішінара өзіңдікі — жобаның жасалуын басқару мен оны жай ғана бақылап отырудың айырмасы осында.
</Step>

<Step title="Асықпай мақұлда">
Claude үш жауап ұсынады: auto режимін қосу, өңдеулерді қолмен мақұлдау немесе жоспарлауды жалғастыру. Auto режимі қолжетімсіз жерде біріншісі "Yes, auto-accept edits" деп тұрады.

**«Yes, manually approve edits»** дегенді таңда. **Бір** diff-ті басынан аяғына дейін оқы — форманы жіберуді өңдейтін JavaScript кодын, себебі сен жазған ережелердің бар-жоғы дәл сол жерден көрінеді. Қалғанын қалаған жылдамдығыңмен мақұлдай бер. Simon Willison агентпен жұмыстағы басты анти-үлгі деп осы ереженің бір деңгей үлкен түрін атайды: өзің қарап шықпаған кодпен ешқашан pull request ашпа ([анти-үлгілер](https://simonwillison.net/guides/agentic-engineering-patterns/anti-patterns/)).

Күтілетін нәтиже: алдымен `PLAN.md`, сосын `index.html` жазылады, ал қалтада басқа ештеңе жоқ.
</Step>

<Step title="Өзің іске қосып көр">
Claude-ты жаппа, жұмыс істей берсін. Сол қалтада **екінші** терминал аш.

<Terminal title="bash">
```bash
npx -y serve
```
</Terminal>

Ол `http://localhost:3000` сияқты жергілікті мекенжай шығарады. Портты өз экраныңнан оқы — терминал қай есікті ашқанын әрдайым өзі айтады. Мекенжайды ашып, бетті бұзып көруге тырыс, мына ретпен: орын бронда (есептегіш азаяды, аты жоғарыда шығады), бетті қайта жүкте (аты орнында тұр), бос форманы жібер (үнсіздік емес, көрінетін хабар шығады), KK / EN түймесін бас (көрініп тұрған әр жазба өзгереді).

Интернет жоқ па, әлде `npx` қатып қалды ма? `index.html` файлын файлдар менеджерінен тікелей аш — бүгінге жарайды, бірақ `http://` арқылы ашуды әдетке айналдыр, себебі бет ноутбугіңнен шыққаннан кейін дәл солай жұмыс істейді.
</Step>

<Step title="Жұмыс істемейтін бір нәрсені тауып, оны дәл айт">
Ондай нәрсе әрқашан табылады. Ешқашан «бұзылып қалды» деп жазба. Белгісін, орнын және не болса бітті саналатынын жаз.

<Prompt title="Түзету промпты" where="Claude Code · manual approve mode">
```text
Қате: [не көріп тұрсың]. Күтілетіні: [не болуға тиіс].
Қай жерде: index.html, [күдіктенген функция немесе блок].
Оны жұмыс істейтін ең шағын өзгеріспен түзет те, браузерде тексеретін
нақты қадамдарды айт. Басқа ештеңеге тиіспе.
```
</Prompt>

Күтілетін нәтиже: шағын diff және тексеру қадамдарының тізімі. Егер ол файлдың жартысын қайта жаза бастаса, `Esc` пернесін бас — ол тоқтайды, бұған дейінгі жұмысы сақталады — сосын сұрағыңды тарылтып, қайта сұра.
</Step>

<Step title="Тым ұнатып кетпей тұрып, commit жаса">
Бос жолдың басына `!` таңбасын тер — shell режимі қосылады, сонда нәтиже Claude көретін әңгіменің ішіне түседі.

<Terminal title="Claude Code · shell mode">
```bash
! git status
```
</Terminal>

<Prompt title="Commit промпты" where="Claude Code · manual approve mode">
```text
Осы қалтадағының бәрін commit жаса. type(scope): summary түрінде, бұл бет не
істейтінін айтатын бір сипаттама хабар жаз.
Сосын маған git log --oneline және git status нәтижесін көрсет.
```
</Prompt>

Күтілетін нәтиже: бір commit, бір жол, шамамен `feat(signup): event landing page with seat counter` сияқты, әрі таза `git status`. Anthropic-тің harness туралы зерттеуі мұны ашық жазады: әр ілгерілеу бөлігінен кейін сипаттама хабармен commit жаса — сонда кейінгі сеанс, немесе ертеңгі өзің, жұмыс істеген күйге қайта орала алады ([ұзақ жұмыс істейтін агенттерге арналған harness](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)).
</Step>

</Steps>

## Бұл іс бұзылатын төрт жағдай және әрқайсысының шешімі

- **Зерттеуі бітпейді.** Шеңбері белгіленбеген зерттеу жүздеген файлды оқып, контекст терезесін толтырып тастайды — құжаттамадағы аты «infinite exploration». Оны нақты аталған файлдармен шектеп қой немесе субагентке тапсыр.
- **Бір нәрсені екі рет түзеттің.** Тоқта: контекстің енді негізінен сәтсіз әрекеттерден тұр. `/clear` пәрменін орында да, бірінші промптты жақсырақ жаз ([үздік тәжірибелер](https://code.claude.com/docs/en/best-practices)).
- **«Бітті» дейді, бірақ бітпеген.** Құжаттама мұны trust-then-verify алшақтығы деп атайды. Мәлімдеме емес, дәлел сұра: қандай пәрмен орындағанын және қандай нәтиже алғанын көрсетсін.
- **Ол үнсіз алдап отыр.** Kent Beck атаған белгілер: бір шеңберде айналады, ешкім сұрамаған мүмкіндіктер қосады немесе жасыл нәтиже алу үшін тестерді өшіріп, жойып жібереді ([augmented coding](https://newsletter.kentbeck.com/p/augmented-coding-beyond-the-vibes)).

Соңғы он минутты қайтарғың келе ме? Бос енгізу өрісінде `Esc` `Esc` басу кері қайтару мәзірін ашады: кодты, әңгімені немесе екеуін де қалпына келтіресің. Bash пәрмені істеген нәрсені ол кері қайтармайды. Ол үшін commit бар.

<Callout type="warn" title="Жасағаның әлі тіркелу жүйесі емес">
Брондаулар келушінің өз браузерінде ғана тұр. Оларды басқа ешкім көрмейді, ал сайттың деректерін тазалағанда олар жойылады. Мұны қызмет емес, жай ғана бет деп есепте: әзірге оған нағыз іс-шараны қойма, әрі шын мекенжайды сақтайтын қауіпсіз орын пайда болғанша ешкімнен шын электрондық пошта сұрама.
</Callout>

<Deeper title="Жоспарды мүлде жасамауға болатын кездер">
Жоспарлау режимі тегін емес — зерттеу де, жоспардың өзі де контексті жұмсайды. Құжаттамадағы ереже: шығатын өзгерісті бір сөйлеммен айтып бере алсаң, жоспарды аттап өтіп, бірден сұра. Қате терілген әріп, бір журнал жолы, атын өзгерту. Жоспарлау тәсіл әлі белгісіз болғанда, өзгеріс бірнеше файлды қамтығанда немесе код саған таныс болмағанда пайда береді ([үздік тәжірибелер](https://code.claude.com/docs/en/best-practices)).
</Deeper>

<Deeper title="Жоспарлау режимін жоба үшін әдепкі ету">
Әрқашан алдымен жоспар керек repo үшін оның `.claude/settings.json` файлына `{"permissions": {"defaultMode": "plan"}}` жазып қой; сонда ондағы әр сеанс жоспарлау режимінен басталады, ал `Shift+Tab` бұрынғысынша ештеңені мақұлдамай-ақ одан шығарады ([рұқсат режимдері](https://code.claude.com/docs/en/permission-modes)).
</Deeper>
