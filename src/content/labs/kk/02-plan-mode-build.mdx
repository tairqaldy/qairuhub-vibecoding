<Lead>
Жиырма бес минутта бос қалтадан жұмыс істейтін тіркелу бетіне жетесің. Ең құнды әрекет — теру емес, *жоспарды оқу* және бірде-бір файл пайда болмай тұрып оның бір жолын өзгерту.
</Lead>

Anthropic құжаттамасы ретті төрт сөзбен береді: explore, plan, implement, commit. Жоспарлау режимі (plan mode) алғашқы екеуін атқарады ([үздік тәжірибелер](https://code.claude.com/docs/en/best-practices)). Жоспардың бір қате жолы кодтың жүздеген қате жолына айналады, сондықтан тек diff-ті емес, жоспардың өзін тексер ([контекст инженериясы](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/ace-fca.md)). Жоспар — толық оқып шығатындай қысқа, diff — олай емес.

**QAIRU Event Sign-up** жасайсың: бір бет, бір іс-шара, брондау формасы, кері санайтын есептегіш. Бәрі бір файлда: framework те, build қадамы да жоқ.

## Бос қалтадан commit-ке дейінгі тоғыз қадам

<Steps>

<Step title="Агент тиіп үлгермей тұрып, қалтаны repo-ға айналдыр">
<Terminal title="bash">
```bash
mkdir qairu-event
cd qairu-event
git init
```
</Terminal>

Күтілетін нәтиже: `Initialized empty Git repository` және `qairu-event/.git/` деп аяқталатын жол. Windows PowerShell-де үшеуін `&&` емес, `;` арқылы тізбекте — ол жерде `&&` таңбасы `The token '&&' is not a valid statement separator` деп жазады.

`git init` пәрменін аттап кетпе. Claude Code өз өңдеулерін checkpoint-пен сақтайды, ал Bash пәрмендерін, субагент түзетулерінің көбін және басқа терезеде өзгерткен файлдарыңды қадағаламайды ([checkpoint жүйесі](https://code.claude.com/docs/en/checkpointing)). Checkpoint — жергілікті кері қайтару. Git — тұрақты ([09-модуль](/kk/learn/git-and-github/)).
</Step>

<Step title="Жоспарлау режимінде баста да, шынымен сонда екеніңе көз жеткіз">
<Terminal title="bash">
```bash
claude --permission-mode plan
```
</Terminal>

Жаңа қалтада алғаш іске қосқанда жұмыс кеңістігіне сенім сұралады — келісім бер. Содан кейін енгізу өрісінің астындағы күй жолағында `plan mode on` деп тұруға тиіс.

Сеанс ашық тұрса, сол жазу шыққанша `Shift+Tab` бас: **auto** режимінен үш басу (Pro, Max, Team тарифтерінде әдепкі режим — сол), Manual-дан екі басу ([сеанс қай режимнен басталады](https://code.claude.com/docs/en/permission-modes#which-mode-a-session-starts-in)). Кейбір Windows жүйелерінде бұл тіркесім — `Alt+M`.
</Step>

<Step title="Бүкіл тапсырманы бір промптпен бер">
Мынаны дәл сол күйінде қой. Іс-шара деректерін өзіңдікімен алмастыр немесе солай қалдыр.

<Prompt title="Жасау промпты" where="Claude Code · plan mode">
```text
Осы қалтада QAIRU Event Sign-up тіркелу бетін бір файл етіп жаса: index.html.
Ешқандай framework, build қадамы, жаңа тәуелділік болмасын. Бүкіл CSS пен JS index.html ішінде.

Бет БІР іс-шараны көрсетеді және келушіге орын брондауға мүмкіндік береді:
- іс-шараның атауы, күні, уақыты, өтетін жері және ол туралы екі сөйлем
- брондау формасы: аты, электрондық пошта, бір Reserve түймесі
- 40-тан басталып, әр брондаудан кейін бірге азаятын "қалған орын" есептегіші
- брондағандардың тізімі, ең жаңасы жоғарыда
- орын 0 болғанда: форма өшіріледі және бетте іс-шараның толғаны жазылады
- бет қайта жүктелгенде брондаулар сақталып қалады
- аты бос, поштасы бос немесе поштасында "@" жоқ болса, көрінетін хабармен қабылданбайды

Әзірге ешқандай код жазба.
1. Осы қалтада қазір не бар екенін және нені қайта пайдаланбақ екеніңді айт.
2. Жоспарды көрсет: реттелген қадамдар, әр қадам тиетін файл, әрі әр қадам үшін
   браузерде нақты нені басатынымды және нақты нені көретінімді жаз.
3. Не істемейтіңді тізіп бер, әрі менен растауды қажет ететін болжамдарыңды айт.

Тоқта да, менің мақұлдауымды күт. Мақұлдағанымда, басқа ештеңені өзгертпей тұрып,
мақұлданған жоспарды PLAN.md етіп сақта.
```
</Prompt>

Ол қалтаны оқиды, оқуға ғана арналған бір-екі пәрмен орындайды да, тапқандарымен және нөмірленген жоспармен оралады. `index.html` әзірге жоқ: жоспарлау режимінде сен мақұлдағанша кодты өңдеуге тыйым салынған ([жоспарлау режимі](https://code.claude.com/docs/en/permission-modes#analyze-before-you-edit-with-plan-mode)). Жұмыс кезінде `Ctrl+T` тапсырмалар тізімін, `Ctrl+O` әңгіме жазбасын ашады.
</Step>

<Step title="Жоспарды бүгін оқитын жалғыз мәтінің сияқты оқы">
Үш сұрақ.

1. **Әр қадамда өзім орындай алатын тексеріс бар ма?** «Брондау формасын жаса» — қадам емес, тілек: оның жұмыс істегенін ештеңе көрсетпейді ([үздік тәжірибелер](https://code.claude.com/docs/en/best-practices)).
2. **Неге тиіспейтінін айтқан ба?** Шекарасы айтылмаған агент сен сұрамаған нәрселерді қайта реттеп тастайды.
3. **Қасыңдағы адамға түсіндіріп бере алмайтын қадам бар ма?** Кейін дәл сол соққы береді.

Екі жауап нашар болса — **«No, keep planning»**, себебін қоса жаз: `3 және 5-қадамда браузерде тексеру жоқ. Екеуін де мен нені басатынымды, нені көруім керегін жазып қайта жаз.`
</Step>

<Step title="Мақұлдар алдында бір жолды өзгерт">
`Ctrl+G` бас. Жоспар редакторыңда ашылады. Мынаны қос, сақта, жап.

<Prompt title="Өзің қосатын жол" where="Your editor · via Ctrl+G">
```text
- Келуші көретін әр жазба қазақша және ағылшынша болады. Беттің жоғарғы жолағындағы
  KK / EN түймесі екеуін ауыстырады және таңдауды есте сақтайды. Әдепкісі — қазақша.
```
</Prompt>

Агент бұл талапты сен үшін ойлап таппайды. Енді жоспар ішінара өзіңдікі — жобаны басқару мен оны жай бақылап отырудың айырмасы осында.
</Step>

<Step title="Асықпай мақұлда">
Claude үш жауап ұсынады: auto режимі, қолмен мақұлдау немесе жоспарлауды жалғастыру. Auto режимі қолжетімсіз жерде біріншісі "Yes, auto-accept edits" деп тұрады.

**«Yes, manually approve edits»** дегенді таңда. **Бір** diff-ті басынан аяғына дейін оқы: форманы жіберуді өңдейтін JavaScript — сен жазған ережелердің бар-жоғы сол жерден көрінеді. Қалғанын қалаған жылдамдықпен мақұлда. Simon Willison-да дәл осы ереже, бір деңгей үлкені: өзің оқымаған кодпен pull request ашпа ([анти-үлгілер](https://simonwillison.net/guides/agentic-engineering-patterns/anti-patterns/)).

Күтілетін нәтиже: алдымен `PLAN.md`, сосын `index.html`, қалтада басқа ештеңе жоқ.
</Step>

<Step title="Өзің іске қосып көр">
Claude жұмыс істей берсін. Сол қалтада **екінші** терминал аш.

<Terminal title="bash">
```bash
npx -y serve
```
</Terminal>

Ол `http://localhost:3000` сияқты жергілікті мекенжай шығарады. Портты өз экраныңнан оқы. Мекенжайды ашып, бетті бұзып көр: орын бронда (есептегіш азаяды, аты жоғарыда шығады), бетті қайта жүкте (аты орнында тұр), бос форманы жібер (үнсіздік емес, көрінетін хабар шығады), KK / EN түймесін бас (әр жазба өзгереді).

Интернет жоқ па, әлде `npx` қатып қалды ма? `index.html` файлын файлдар менеджерінен аш. Бүгінге жарайды, бірақ `http://` арқылы ашуды әдетке айналдыр — бет ноутбугіңнен шыққанда дәл солай жұмыс істейді.
</Step>

<Step title="Жұмыс істемейтін бір нәрсені тауып, оны дәл айт">
Ондай нәрсе әрқашан табылады. «Бұзылып қалды» емес: белгісі, орны, не болса бітті саналатыны.

<Prompt title="Түзету промпты" where="Claude Code · manual approve mode">
```text
Қате: [не көріп тұрсың]. Күтілетіні: [не болуға тиіс].
Қай жерде: index.html, [күдіктенген функция немесе блок].
Оны жұмыс істейтін ең шағын өзгеріспен түзет те, браузерде тексеретін
нақты қадамдарды айт. Басқа ештеңеге тиіспе.
```
</Prompt>

Күтілетін нәтиже: шағын diff және тексеру қадамдарының тізімі. Егер файлдың жартысын қайта жаза бастаса, `Esc` бас — ол тоқтайды, бұған дейінгі жұмысы сақталады — сосын сұрағыңды тарылтып, қайта сұра.
</Step>

<Step title="Тым ұнатып кетпей тұрып, commit жаса">
Бос жолдың басына `!` тер — shell режимі қосылады, нәтиже Claude көретін әңгіменің ішіне түседі.

<Terminal title="Claude Code · shell mode">
```bash
! git status
```
</Terminal>

<Prompt title="Commit промпты" where="Claude Code · manual approve mode">
```text
Осы қалтадағының бәрін commit жаса. type(scope): summary түрінде, бұл бет не
істейтінін айтатын бір сипаттама хабар жаз.
Сосын маған git log --oneline және git status нәтижесін көрсет.
```
</Prompt>

Күтілетін нәтиже: бір commit, шамамен `feat(signup): event landing page with seat counter` сияқты, әрі таза `git status`. Әр ілгерілеу бөлігінен кейін commit жаса — жұмыс істеген күйге қайта орала аласың ([ұзақ жұмыс істейтін агенттерге арналған harness](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)).
</Step>

</Steps>

## Бұл іс бұзылатын төрт жағдай

- **Зерттеуі бітпейді.** Шеңбері белгіленбеген зерттеу жүздеген файлды оқып, контекст терезесін толтырады — құжаттамадағы аты «infinite exploration». Нақты аталған файлдармен шектеп қой немесе субагентке тапсыр.
- **Бір нәрсені екі рет түзеттің.** Тоқта: контекстің енді негізінен сәтсіз әрекеттерден тұр. `/clear` орында да, бірінші промптты жақсырақ жаз ([үздік тәжірибелер](https://code.claude.com/docs/en/best-practices)).
- **«Бітті» дейді, бірақ бітпеген.** Мәлімдеме емес, дәлел сұра: қандай пәрмен орындады, қандай нәтиже алды.
- **Ол үнсіз алдап отыр.** Kent Beck атаған белгілер: бір шеңберде айналады, ешкім сұрамаған мүмкіндіктер қосады немесе жасыл нәтиже алу үшін тестерді өшіріп, жояды ([augmented coding](https://newsletter.kentbeck.com/p/augmented-coding-beyond-the-vibes)).

Соңғы он минутты қайтарғың келе ме? Бос енгізу өрісінде `Esc` `Esc` кері қайтару мәзірін ашады ([04-практика](/kk/labs/undo-anything/)). Bash пәрменін ол кері қайтармайды. Ол үшін commit бар.

<Callout type="warn" title="Жасағаның әлі тіркелу жүйесі емес">
Брондаулар келушінің өз браузерінде ғана тұр. Оларды басқа ешкім көрмейді, ал сайт деректерін тазалағанда олар жойылады. Бұл — қызмет емес, жай ғана бет: әзірге оған нағыз іс-шараны қойма, әрі сақтайтын қауіпсіз орын болмайынша ешкімнен шын пошта мекенжайын сұрама.
</Callout>

<Deeper title="Жоспарды мүлде жасамауға болатын кездер">
Зерттеу де, жоспар да контексті жұмсайды. Өзгерісті бір сөйлеммен айтып бере алсаң — қате терілген әріп, бір журнал жолы, атын өзгерту — жоспарды аттап, бірден сұра. Жоспарлау тәсіл белгісіз болғанда, өзгеріс бірнеше файлды қамтығанда немесе код таныс болмағанда пайда береді ([үздік тәжірибелер](https://code.claude.com/docs/en/best-practices)).
</Deeper>

<Deeper title="Жоспарлау режимін жоба үшін әдепкі ету">
Repo-да әрқашан алдымен жоспар керек пе? Оның `.claude/settings.json` файлына `{"permissions": {"defaultMode": "plan"}}` жаз. Сонда ондағы әр сеанс жоспарлау режимінен басталады, ал `Shift+Tab` бұрынғысынша ештеңені мақұлдамай шығарады ([рұқсат режимдері](https://code.claude.com/docs/en/permission-modes)).
</Deeper>
