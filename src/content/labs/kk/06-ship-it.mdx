<Lead>
Дәл қазір сенің жобаң — жай ғана қалта. Жиырма бес минуттан кейін ол URL болады. Алдымен *өз қолыңмен* жасайсың: өзің істеп көрмеген нәрсені агент дұрыс істеп жатыр ма — оны бақылай алмайсың.
</Lead>

«Deploy сәтті өтті» дегені — мәлімдеме, дәлел емес. Осы беттің соңына жеткенде оның қате болуының төрт жолын білесің.

## Бірінші бөлім: өз қолыңмен жасайтын алты қадам

<Callout type="warn" title="Жаман бір аптадан құтқаратын отыз секунд">
Бірінші push-тан бұрын `.gitignore` файлын ашып, ішінде `.env` бар екеніне көз жеткіз. Ашық репозиторий пайда болған сәттен бастап ашық, ал бір рет commit-ке түскен кілт өшірілгеннен кейін де ұрланған болып саналады. Commit жасар алдында `git status` орындап, әр файл атауын оқып шық.
</Callout>

<Steps>

<Step title="Терминалдан GitHub-қа кір">
GitHub CLI аккаунт жұмысын пәрменге айналдырады, яғни кейін оны агентің де орындай алады. Әрі сол жұмысты істейтін GitHub MCP серверінен гөрі контекстті аз жейді ([шығындар туралы құжаттама](https://code.claude.com/docs/en/costs)).

<Terminal title="bash">

```bash
gh auth login
gh auth status
```

</Terminal>

`gh auth login` браузердегі кіру бетін және бір реттік кодты ашады. `gh auth status` шын мәнінде қай аккаунтпен кіргеніңді көрсетеді. Соны тексер: мұндағы «permission denied» мәселелерінің жартысы — ұмытып кеткен екінші GitHub аккаунт.
</Step>

<Step title="Репозиторийді құрып, бір пәрменмен push жаса">
github.com-ды мүлде ашпайсың. Жоба қалтаңның ішінен:

<Terminal title="bash">

```bash
git init
git add -A
git commit -m "QAIRU Event Sign-up: first working version"
gh repo create qairu-event --public --source=. --remote=origin --push
```

</Terminal>

`--source=.` дегені «репозиторий — осы қалта». `--remote=origin` байланысқа әдеттегі атау береді, `--push` commit-терді бірден жібереді. Ал `--public` — ақша мәселесі: GitHub-тың стандартты Actions серверлері ашық репозиторийлерде тегін, ал тегін жабық репозиторийге айына 2 000 минут қана беріледі ([GitHub-тың төлем құжаттамасы](https://docs.github.com/en/billing/concepts/product-billing/github-actions)).
</Step>

<Step title="Сайттың өзі болатын қалтаны құрастыр">
Статикалық сайт — қалта. Құрастыр да, қалтаны ашып, ішіне қарап шық. Осы әрекеттің өзі deploy-дан қорқуды жойып жібереді.

<Terminal title="bash">

```bash
npm run build
ls dist
```

</Terminal>

Егер `dist/` пайда болмаса, жобаң нәтижені басқа жерге шығарады — `build/`, `out/`, `public/`. Нақты атауын дәл қазір тауып ал. Бірінші deploy-дың ең жиі сәтсіздігі — басқа қалтаның мүлтіксіз сәтті жүктелуі.

Құрастыру қадамы жоқ па? [02-практикумдағы](/kk/labs/plan-mode-build/) QAIRU Event Sign-up беті — бір ғана `index.html`, ал ол қазірдің өзінде сайт. Оған бөлек қалта бер: сонда бүкіл репозиторийді емес, бетті ғана жүктейсің:

<Terminal title="bash">

```bash
mkdir site
mv index.html site/
```

</Terminal>

Бұдан әрі `dist` деп тұрған жерде `site` деп оқы.
</Step>

<Step title="Cloudflare Pages-ге deploy жаса">
Wrangler — Cloudflare-дің CLI құралы. `npx` оны орнатпай-ақ іске қосады.

<Terminal title="bash">

```bash
npx wrangler pages deploy dist --project-name=qairu-event
```

</Terminal>

Бірінші рет іске қосқанда браузерге жібереді: сонда Wrangler-ге рұқсат бересің, ал жоба жоқ болса, оны құруды ұсынады. Содан кейін `dist/` қалтасын жүктеп, `pages.dev` сілтемесін шығарады — әлдеқашан HTTPS-пен, әлдеқашан дүниежүзіне беріліп тұр.

Қай аккаунтқа жүктеп жатқаныңды тексеру үшін:

<Terminal title="bash">

```bash
npx wrangler whoami
```

</Terminal>
</Step>

<Step title="Телефоннан, мобильді интернетпен аш">
Ноутбуктан емес. Ноутбугыңда кэштелген localhost пен саған өтірік айтатын браузер бар. Телефондағы Wi-Fi-ды өшір, `pages.dev` сілтемесін теріп, бетті жүкте.

Дәлел деп саналатын жалғыз қадам — осы. Қалғанының бәрі — мәлімдеме. Сенікі емес құрылғы, сенікі емес желі арқылы, сенікі емес серверден жауап алды.
</Step>

<Step title="Жеке домен қос — ал бұл қадам пәрмен емес">
Бұған арналған `wrangler` жалауы жоқ. Cloudflare басқару панелін ашып, Pages жобаңды тауып, **Custom domains** бөліміне атауды қос. DNS жазбасын да, SSL сертификатын да Cloudflare өзі жасайды (бұлар не екені — [12-модуль](/kk/learn/deploy/)). Содан кейін DNS тарайды — бірнеше минуттан бірнеше сағатқа дейін.

Осы қадамды жазып қой. Бірнеше минуттан кейін бұл жұмысты браузер аша алмайтын агентке тапсырасың, ал ол бәрібір `pages.dev` сілтемесін «дайын» деп хабарлайды.

Cloudflare-дің тегін тарифі әр жобаға 100 жеке домен береді ([Pages шектеулері](https://developers.cloudflare.com/pages/platform/limits/)). Шектеу — ешқашан себеп емес. Себеп — ешкімнің басып қоймағаны.

Домен жоқ па? GitHub Student Developer Pack бір жылға тегін домен береді — Namecheap-тен `.me`, `.TECH` немесе Name.com-нан `.dev` не `.app` ([education.github.com/pack](https://education.github.com/pack)).
</Step>

</Steps>

<Deeper title="Тегін тариф нақты не беретіні — сандармен">
Cloudflare Pages Free: айына 500 build, бір уақытта 1 build, build үшін 20 минут шек, әр сайтқа 20 000 файл, әр файл 25 МиБ, әр жобаға 100 жеке домен және әр аккаунтқа 100 жоба. Статикалық файлдар үшін трафик шегі мүлде көрсетілмеген.

Кейін функция қоссаң, Workers Free күніне 100 000 сұрау, әр шақыруға 10 мс процессор уақытын береді, шығыс трафикке ақы алынбайды. Ақылы тариф айына $5-тан басталады.

Дереккөздер: [Workers бағалары](https://developers.cloudflare.com/workers/platform/pricing/), [Pages шектеулері](https://developers.cloudflare.com/pages/platform/limits/). Студенттік жоба үшін мәні мынау: бетіңді беру саған ештеңеге түспейді. Бюджетті HTML емес, функциялар мен дерекқорлар жейді.
</Deeper>

## Екінші бөлім: дәл сол жұмысты агентке тапсыр

Дұрыс deploy қалай көрінетінін білесің, демек бұрысын да танисың. Енді тапсыр.

<Prompt title="Осы жобаны deploy жаса" where="Claude Code · plan mode">

```text
Осы жобаның Cloudflare Pages-ге бірінші рет deploy жасалуын жоспарла.
Мен жоспарды мақұлдағанша код жазба, бірде-бір пәрмен орындама.

Репозиторий туралы фактілер:
- Статикалық сайт. Құрастыру пәрмені — `npm run build`. Нәтиже шығатын
  қалтаны конфигурацияны оқып өзің анықта — dist/ деп жорамалдама.
- GitHub-та әлі жоқ. Маған qairu-event деген ашық репозиторий керек.
- `gh` және `npx` бар. Мен [Windows PowerShell / macOS / Linux]
  жүйесінде жұмыс істеймін.

Жоспарда маған мынаны бер:
1. Орындайтын нақты пәрмендеріңді, кезегімен.
2. Әрқайсысы туралы: файлды өңдеу арқылы кері қайтара алмайтындай не
   өзгереді.
3. Қайсысын мүлде орындай алмайсың және неліктен.
4. Сайттың тірі екенін дәлелдеу үшін кейін өзім орындайтын бір пәрмен.

Содан кейін «Мынаны браузерде өзім істеуім керек» деген тақырыппен,
CLI баламасы жоқ әр қадамды тізіп бер. Сол тізім босағанша немесе мен
оларды істедім деп растағанша, сайт тірі деп айтпа.
```

</Prompt>

**Ол deploy жасар алдында тоқтап, рұқсат сұрайды — бұл дұрыс.** Pro, Max және Team тарифтерінде сеанстар auto режимінде басталады: әрекеттерді алдымен жіктеуіш модель қарап шығады, ал production-ға жасалатын deploy әдепкіде бұғатталған — force push пен жаппай жоюдың қасында ([рұқсат режимдері](https://code.claude.com/docs/en/permission-modes); режимдердің өзі — [07-модуль](/kk/learn/the-agent/)). Құжаттама ескертеді: бұл сұрақтарды азайтады, бірақ қауіпсіздікке кепілдік бермейді. Ол сұрап тұрған пәрменді де, ішіндегі қалта атауын да оқы.

**Шекараны жай сөзбен де сыза аласың.** «Push жасама» десең, жіктеуіш модель мұны сен алып тастағанша шекара деп санайды. Сыпайылық емес, нағыз қоршау.

**Немесе қоршауды тұрақты ет** ([03-практикум](/kk/labs/claude-md-and-permissions/) тереңірек айтады). `.claude/settings.json` файлында:

<Terminal title=".claude/settings.json">

```json
{
  "permissions": {
    "ask": ["Bash(git push *)", "Bash(npx wrangler *)"],
    "deny": ["Read(./.env)", "Read(./.env.*)"]
  }
}
```

</Terminal>

Жұлдызшаның алдындағы бос орынға көңіл бөл: `Bash(git push *)`, жұлдызша қосалқы пәрменнен кейін тұрады, `Bash(git *)` емес ([рұқсаттар құжаттамасы](https://code.claude.com/docs/en/permissions)). Әрі Bash ережелері бағдарламаны емес, пәрмен мәтінін салыстырады — қауіпсіздік шекарасы емес, жай ғана ыңғайлылық.

## Үшінші бөлім: оның шын мәнінде не істегенін тексер

Claude Code пайдаланушылары рұқсат сұрауларының 93%-ын мақұлдайды. Anthropic-тің инженерлік жазбасы мұны мақұлдау шаршауы дейді — «where people stop paying close attention», яғни адамдар мұқият қарауды қояды ([auto режимі, 2026 ж. 25 наурыз](https://www.anthropic.com/engineering/claude-code-auto-mode)). Сен де ерекшелік емессің, сондықтан механикалық түрде тексер.

Транскрипт көрінісін ашу үшін `Ctrl+O` бас та, агент жазған қорытындыны емес, оның орындаған нақты пәрмендерін оқы ([интерактивті режим](https://code.claude.com/docs/en/interactive-mode)). Сеанстың ішінде жол басындағы `!` таңбасы пәрменді орындап, нәтижесін әңгімеге тастайды.

<Terminal title="bash">

```bash
git log --oneline -3
git remote -v
gh repo view --web
curl -sI https://qairu-event.pages.dev | head -1
```

</Terminal>

Төрт пәрмен — төрт түрлі өтірік. `git log`: commit шынымен бар ма, әлде агент файлдарды тек қосып қана қойды ма? `git remote -v`: қай репозиторийге push жасалды? `gh repo view --web`: ішінде `.env` жатыр ма? `curl -sI`: `HTTP/2 200` дегені — сервер жауап берді.

Windows PowerShell-де соңғы жолға екі өзгеріс керек: ондағы `curl` — басқа пәрменнің бүркеншік атауы, ал `head` мүлде жоқ. `curl.exe -sI https://qairu-event.pages.dev` пәрменін бөлек орында немесе бүкіл блокты Git Bash-та іске қос.

<Prompt title="Жаңа ғана жасалған deploy-ды тексер" where="Claude Code · new session, after /clear">

```text
Осы жобаға жаңа ғана жасалған deploy-ды тексер. Жадыңдағы ештеңені
шындық деп алма — ағымдағы күйді пәрмендермен тексеріп шық.

Нәтижені кесте түрінде бер, әр мәлімдемеге бір жол:
- мәлімдеме (мысалы: «репозиторий ашық», «жүктелген қалта — dist/»,
  «тірі сілтеме ең соңғы build-ті береді»)
- оны тексеру үшін орындаған пәрменің
- нақты шыққан нәтиже
- PASS немесе FAIL

Соңында екі тізім жаса: дәл қазір шынымен тірі тұрғаны және әлі тек
менің ноутбугымда ғана бар нәрсе. Қандай да бір мәлімдемені осы жерден
пәрменмен тексеру мүмкін болмаса, жорамалдаудың орнына соны айт.
```

</Prompt>

Мұны `/clear` жасағаннан кейін орында. Жұмысты өзі істеген сеанс өз қорытындысын өзі растайды; ал deploy туралы жады жоқ сеансқа барып қарауға тура келеді.

<Callout type="danger" title="Кері қайтару интернетке жетпейді">
Бақылау нүктелері ([04-практикум](/kk/labs/undo-anything/)) Claude Code құралдары сенің файлдарыңа енгізген өзгерістерді ғана қамтиды. Қашықтағы салдарлар — дерекқорға жазу, push, deploy — қадағаланбайды ([бақылау нүктелері](https://code.claude.com/docs/en/checkpointing)).

Сондықтан `/rewind` кодыңды қайтарады, ал бұзылған нұсқа сол уақыттың бәрінде тірі тұра береді, терминалың тып-тыныш көрінеді. Deploy-ды кері қайтару — `git revert`, push, қайта құрастыру, қайтадан `npx wrangler pages deploy`. Қысқа жолы жоқ, сондықтан оны шынымен қажет болғанда емес, дәл қазір жасап көр.
</Callout>
