<Lead>
Дәл қазір сенің жобаң — жай ғана қалта. Жиырма бес минуттан кейін ол URL болады. Алдымен *өз қолыңмен* жасайсың, себебі өзің ешқашан істеп көрмеген нәрсені агент дұрыс істеп жатыр ма — оны бақылай алмайсың, ал бақылау деген — бұл жұмыстың өзі.
</Lead>

Бірінші жартысын жалғыз жаса. Екінші жартысын Claude Code-пен жаса, ал соңғы бес минутты оның айтқаны шын ба — соны дәлелдеуге жұмса. Кезегі маңызды: «deploy сәтті өтті» деген агент бар болғаны мәлімдеме жасап тұр, ал осы беттің соңына жеткенде сол мәлімдеменің қате болуының төрт түрлі жолын білетін боласың.

## Бірінші бөлім: өз қолыңмен жасайтын алты қадам

<Callout type="warn" title="Жаман бір аптадан құтқаратын отыз секунд">
Бірінші push-тан бұрын `.gitignore` файлын ашып, ішінде `.env` бар екеніне көз жеткіз. Ашық репозиторий пайда болған сәтте-ақ ашық болады, ал бір рет commit-ке түскен кілт оны өшіргеннен кейін де ұрланған болып саналады. Күмәнің болса, commit жасар алдында `git status` пәрменін орындап, тізімдегі әр файл атауын оқып шық.
</Callout>

<Steps>

<Step title="Терминалдан GitHub-қа кір">
GitHub CLI аккаунтпен істелетін жұмысты пәрменге айналдырады, яғни кейін оны агентің де орындай алады. Оған қоса, ол GitHub MCP серверіне қарағанда контекстті аз жейді — Anthropic-тің өз кеңесі де осы: бір жұмысты істегенде `gh` сияқты CLI құралдары MCP серверінен арзанға түседі ([шығындар туралы құжаттама](https://code.claude.com/docs/en/costs)).

<Terminal title="bash">

```bash
gh auth login
gh auth status
```

</Terminal>

`gh auth login` пәрмені сені браузердегі кіру бетіне және бір реттік кодқа алып барады. `gh auth status` шын мәнінде қай аккаунтпен кіргеніңді көрсетеді — соны тексер, себебі осы практикумдағы «permission denied» мәселелерінің жартысы — ұмытып кеткен екінші GitHub аккаунтың.
</Step>

<Step title="Репозиторийді құрып, бір пәрменмен push жаса">
github.com сайтын ашудың қажеті жоқ. Жоба қалтаңның ішінен:

<Terminal title="bash">

```bash
git init
git add -A
git commit -m "QAIRU Event Sign-up: first working version"
gh repo create qairu-event --public --source=. --remote=origin --push
```

</Terminal>

Жалауларды бір рет оқып шық — енді ешқашан іздеп отырмайсың. `--source=.` дегені «репозиторий — осы қалта». `--remote=origin` байланысты әдеттегі атаумен жалғап қояды. `--push` commit-терді бірден жібереді. Ал `--public` — ақша мәселесі: GitHub-тың стандартты Actions серверлері ашық репозиторийлерде тегін, ал тегін жабық репозиторийге айына 2 000 минут қана беріледі ([GitHub-тың төлем құжаттамасы](https://docs.github.com/en/billing/concepts/product-billing/github-actions)).

Windows PowerShell-де бұларды бір жолға тізсең, `&&` орнына `;` қой. Әр пәрменді бөлек жолға жазсаң, қай жүйеде болса да жұмыс істейді.
</Step>

<Step title="Сайттың өзі болатын қалтаны құрастыр">
Статикалық сайтта сиқыр жоқ. Ол — қалта. Құрастыр да, қалтаны ашып, ішіне қарап шық: тек осы әрекеттің өзі deploy-дан қорқуды дерлік жойып жібереді.

<Terminal title="bash">

```bash
npm run build
ls dist
```

</Terminal>

Егер `dist/` пайда болмаса, жобаң нәтижені басқа жерге шығарады — `build/`, `out/`, `public/`. Қалтаның нақты атауын дәл қазір тауып ал, себебі сен оны қазір deploy пәрменіне тересің, ал бірінші deploy-дың ең жиі кездесетін сәтсіздігі — мүлде басқа каталогтың тап-тамаша сәтті жүктелуі.

Құрастыру қадамы мүлде жоқ па? 02-практикумдағы QAIRU Event Sign-up беті — бір ғана `index.html`, басқа ештеңе жоқ, ал ол қазірдің өзінде сайт. Оған бөлек қалта бер, сонда бүкіл репозиторийді емес, бетті ғана жүктейсің:

<Terminal title="bash">

```bash
mkdir site
mv index.html site/
```

</Terminal>

Содан кейін практикумның қалған бөлігінде `dist` деп тұрған жердің бәрінде `site` деп оқы.
</Step>

<Step title="Cloudflare Pages-ге deploy жаса">
Wrangler — Cloudflare-дің CLI құралы. `npx` оны тұрақты орнатпай-ақ іске қосады.

<Terminal title="bash">

```bash
npx wrangler pages deploy dist --project-name=qairu-event
```

</Terminal>

Бірінші рет іске қосқанда ол сені браузерге жібереді: сонда Wrangler-ге Cloudflare аккаунтыңмен жұмыс істеуге рұқсат бересің, ал жоба әлі жоқ болса, оны құруды ұсынады. Содан кейін `dist/` қалтасын жүктеп салады да, `pages.dev` деп аяқталатын сілтемені шығарады — ол әлдеқашан HTTPS-пен жұмыс істейді және дүниежүзіндегі деректер орталықтарынан беріледі.

Басқа ештеңе термей тұрып, қай аккаунтқа жүктеп жатқаныңды тексергің келсе:

<Terminal title="bash">

```bash
npx wrangler whoami
```

</Terminal>
</Step>

<Step title="Телефоннан, мобильді интернетпен аш">
Ноутбуктан емес. Ноутбугыңда кэштелген localhost пен көзіңе қарап тұрып өтірік айтатын браузер бар. Телефондағы Wi-Fi-ды өшір, `pages.dev` сілтемесін теріп, бетті жүкте.

Практикумда дәлел деп саналатын жалғыз қадам — осы. Бұған дейінгінің бәрі — мәлімдеме; ал мынау — сенікі емес құрылғыдан, сенікі емес желі арқылы, сенікі емес серверге жеткен нақты сұрау.
</Step>

<Step title="Жеке домен қос — ал бұл қадам пәрмен емес">
Бұған арналған `wrangler` жалауы жоқ. Cloudflare басқару панелін ашып, Pages жобаңды тауып, **Custom domains** бөлімін аш та, атауды қос. DNS жазбасын Cloudflare өзі жасайды, SSL сертификатын да өзі береді. Содан кейін DNS тарауы керек — бірнеше минуттан бірнеше сағатқа дейін, кім қай жерден сұрап тұрғанына байланысты.

Осы қадамды бір жерге жазып қой, себебі бірнеше минуттан кейін сен бұл жұмысты браузер аша алмайтын агентке тапсырасың. Ол осы олқылықты айналып өтеді де, `pages.dev` сілтемесін «дайын» деп хабарлайды.

Cloudflare-дің тегін тарифі әр жобаға 100 жеке доменге дейін рұқсат етеді, яғни шектеу бұл қадамның орындалмауына ешқашан себеп болмайды ([Pages шектеулері](https://developers.cloudflare.com/pages/platform/limits/)). Орындалмауының себебі — ешкімнің басып қоймағаны.

Домен әлі жоқ па? GitHub Student Developer Pack бір жылға тегін домен береді — Namecheap-тен `.me`, `.TECH` немесе Name.com-нан `.dev` не `.app` ([education.github.com/pack](https://education.github.com/pack)).
</Step>

</Steps>

<Deeper title="Тегін тариф нақты не беретіні — сандармен">
Cloudflare Pages Free: айына 500 build, бір уақытта 1 build, build үшін 20 минут шек, әр сайтқа 20 000 файл, әр файл 25 МиБ, әр жобаға 100 жеке домен және әр аккаунтқа 100 жоба. Статикалық файлдар үшін трафик шегі мүлде көрсетілмеген.

Кейін функция қоссаң, Workers Free күніне 100 000 сұрау және әр шақыруға 10 мс процессор уақытын береді, ал шығыс трафик үшін ақы алынбайды. Ақылы тариф айына $5-тан басталады.

Дереккөздер: [Workers бағалары](https://developers.cloudflare.com/workers/platform/pricing/), [Pages шектеулері](https://developers.cloudflare.com/pages/platform/limits/). Студенттік жоба үшін мұның практикалық мәні мынау: бетіңді беру саған ештеңеге түспейді және бұдан кейін де түспейді. Бюджетті HTML емес, функциялар мен дерекқорлар жейді.
</Deeper>

## Екінші бөлім: дәл сол жұмысты агентке тапсыр

Енді deploy дұрыс өткенде қалай көрінетінін білесің — демек, оның бұрыс кеткенін де тани аласың. Тапсыр.

<Prompt title="Осы жобаны deploy жаса" where="Claude Code · plan mode">

```text
Осы жобаның Cloudflare Pages-ге бірінші рет deploy жасалуын жоспарла.
Мен жоспарды мақұлдағанша код жазба, бірде-бір пәрмен орындама.

Репозиторий туралы фактілер:
- Статикалық сайт. Құрастыру пәрмені — `npm run build`. Нәтиже шығатын
  қалтаны конфигурацияны оқып өзің анықта — dist/ деп жорамалдама.
- GitHub-та әлі жоқ. Маған qairu-event деген ашық репозиторий керек.
- `gh` және `npx` бар. Мен [Windows PowerShell / macOS / Linux]
  жүйесінде жұмыс істеймін.

Жоспарда маған мынаны бер:
1. Орындайтын нақты пәрмендеріңді, кезегімен.
2. Әрқайсысы туралы: файлды өңдеу арқылы кері қайтара алмайтындай не
   өзгереді.
3. Қайсысын мүлде орындай алмайсың және неліктен.
4. Сайттың тірі екенін дәлелдеу үшін кейін өзім орындайтын бір пәрмен.

Содан кейін «Мынаны браузерде өзім істеуім керек» деген тақырыппен,
CLI баламасы жоқ әр қадамды тізіп бер. Сол тізім босағанша немесе мен
оларды істедім деп растағанша, сайт тірі деп айтпа.
```

</Prompt>

Ол жұмыс істеп жатқанда назар аударатын үш нәрсе.

**Ол deploy жасар алдында тоқтап, рұқсат сұрайды — бұл дұрыс.** Pro, Max және Team тарифтерінде интерактивті сеанстар енді auto режимінде басталады: онда әрекеттер орындалмай тұрып, оларды екінші, жіктеуіш модель қарап шығады. Жұмыс ортасына (production) жасалатын deploy — әдепкіде бұғатталатын әрекеттер тізімінде, force push пен жаппай жоюдың қасында ([рұқсат режимдері](https://code.claude.com/docs/en/permission-modes)). Сол беттің өзінде құжаттаманың ескертуі тұр: бұл сұрақтардың санын азайтады, бірақ қауіпсіздікке кепілдік бермейді. Ол сұрап тұрған пәрменді оқы, ішіндегі қалта атауын да оқы.

**Шекараны жай сөзбен де сыза аласың.** Әңгіме барысында «push жасама» десең, жіктеуіш модель мұны сен алып тастағанша шекара деп санайды. Бұл — сыпайылық емес, нағыз қоршау.

**Немесе қоршауды тұрақты ет.** `.claude/settings.json` файлында:

<Terminal title=".claude/settings.json">

```json
{
  "permissions": {
    "ask": ["Bash(git push *)", "Bash(npx wrangler *)"],
    "deny": ["Read(./.env)", "Read(./.env.*)"]
  }
}
```

</Terminal>

Жұлдызшаның алдындағы бос орынға көңіл бөл: дұрыс жазылуы — `Bash(git push *)`, яғни жұлдызша қосалқы пәрменнен кейін тұрады, `Bash(git *)` емес ([рұқсаттар құжаттамасы](https://code.claude.com/docs/en/permissions)). Әрі шынайы шегін де көзден таса қылма: Bash ережелері бағдарламаны емес, пәрмен мәтінін салыстырады, сондықтан олар қауіпсіздік шекарасы емес, жай ғана ыңғайлылық.

## Үшінші бөлім: оның шын мәнінде не істегенін тексер

Бұл бөлімнің неге бар екенін Anthropic-тің өз саны түсіндіреді: Claude Code пайдаланушылары рұқсат сұрауларының 93%-ын мақұлдайды, ал инженерлік жазба мұны мақұлдау шаршауына апарады дейді — «where people stop paying close attention», яғни адамдар мұқият қарауды қояды ([auto режимі, 2026 ж. 25 наурыз](https://www.anthropic.com/engineering/claude-code-auto-mode)). Сен де ерекшелік емессің. Сондықтан сезіммен емес, механикалық түрде тексер.

Транскрипт көрінісін ашу үшін `Ctrl+O` бас та, нақты құрал шақыруларын оқы — агент жазған қорытындыны емес, оның орындаған пәрмендерін ([интерактивті режим](https://code.claude.com/docs/en/interactive-mode)). Содан кейін тексеруді өзің жүргіз. Сеанстың ішінде жол басындағы `!` таңбасы пәрменді орындап, нәтижесін әңгімеге тастап кетеді.

<Terminal title="bash">

```bash
git log --oneline -3
git remote -v
gh repo view --web
curl -sI https://qairu-event.pages.dev | head -1
```

</Terminal>

Төрт пәрмен — төрт түрлі өтірікті ұстайды. `git log` commit шынымен бар ма, әлде агент файлдарды тек қосып қана қойды ма — соны көрсетеді. `git remote -v` қай репозиторийге push жасалғанын көрсетеді. `gh repo view --web` репозиторийді ашады, сонда ішінде `.env` жатыр ма — өз көзіңмен көресің. Ал `curl -sI` тірі сілтемеден күй жолын сұрайды: `HTTP/2 200` дегені — сервер жауап берді, ал есепке алынатын жалғыз нәрсе — сол.

Windows PowerShell-де соңғы жолға екі өзгеріс керек: ондағы `curl` — мүлде басқа пәрменнің бүркеншік атауы, ал `head` деген мүлде жоқ. `curl.exe -sI https://qairu-event.pages.dev` пәрменін бөлек орында немесе бүкіл блокты Git Bash-та іске қос.

<Prompt title="Жаңа ғана жасалған deploy-ды тексер" where="Claude Code · new session, after /clear">

```text
Осы жобаға жаңа ғана жасалған deploy-ды тексер. Жадыңдағы ештеңені
шындық деп алма — ағымдағы күйді пәрмендермен тексеріп шық.

Нәтижені кесте түрінде бер, әр мәлімдемеге бір жол:
- мәлімдеме (мысалы: «репозиторий ашық», «жүктелген қалта — dist/»,
  «тірі сілтеме ең соңғы build-ті береді»)
- оны тексеру үшін орындаған пәрменің
- нақты шыққан нәтиже
- PASS немесе FAIL

Соңында екі тізім жаса: дәл қазір шынымен тірі тұрғаны және әлі тек
менің ноутбугымда ғана бар нәрсе. Қандай да бір мәлімдемені осы жерден
пәрменмен тексеру мүмкін болмаса, жорамалдаудың орнына соны айт.
```

</Prompt>

Мұны `/clear` жасағаннан кейін жаңа сеанста орында. Жұмысты жаңа ғана істеген сеанс — оны тексеретін ең нашар сеанс: ол өз қорытындысын өзі растайды. Ал deploy туралы жады жоқ сеансқа барып қарауға тура келеді.

<Callout type="danger" title="Кері қайтару интернетке жетпейді">
Claude Code-тың бақылау нүктелері (checkpoint) оның өз құралдары сенің файлдарыңа енгізген өзгерістерді ғана қамтиды. Сондықтан `/rewind` бастапқы кодыңды қате жасалғанға дейінгі күйге қайтара алады, ал бұзылған нұсқа сол уақыттың бәрінде тірі тұра береді; терминалың болса, мүлде тып-тыныш көрінеді. Deploy-ды кері қайтару деген — git әрекеті, содан кейін тағы бір deploy: `git revert`, push, қайта құрастыру, қайтадан `npx wrangler pages deploy`. Мұның қысқа жолы жоқ, ал оны шынымен қажет еткен сәтің — оны бірінші рет жасап көрген сәтің болмасын.
