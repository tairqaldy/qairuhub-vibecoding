## A model finishes your sentence

A large language model predicts what comes next in a text, one chunk at a time. Grammar, facts, code, following an instruction — all of it fell out of that one skill during training.

It does not look answers up. It generates them from patterns stored in billions of numbers called weights. Picture a very well-read person playing "finish my sentence": fast, fluent, sometimes confidently wrong. That last part is the mechanism working normally, not a defect you can patch out.

## Everything you pay for is counted in tokens

A token is what the model actually reads and writes: a common word, a word fragment, or a punctuation mark. Every price, every limit and every "too long" error is counted in tokens, never in characters or words.

The vocabulary is fixed and learned during training: frequent strings become one token, rare ones get chopped into many. Think LEGO — some text snaps together from big pre-moulded pieces, the rest is built out of 1x1 bricks.

English runs about 1.2 to 1.8 tokens per word. Claude's newer tokenizer produces about 30% more tokens for the same text than the old one, so 1M tokens is now around 555,000 words, not the 750,000 the old rule promised ([Anthropic model overview](https://platform.claude.com/docs/en/about-claude/models/overview)).

## Kazakh costs several times more than English

In the Sherkala paper's Table 1, the Llama-3.1 tokenizer needs **4.73 tokens per Kazakh word**, against 2.56 for Russian and 2.23 for Turkish. Adding Kazakh tokens to the vocabulary cut that to 2.04 ([arXiv](https://arxiv.org/html/2503.01493)). A 2026 measurement puts English at 1.23 tokens per word across six public tokenizers ([arXiv](https://arxiv.org/html/2605.24718)). Across 17 tokenizers, the gap between the cheapest and the most expensive language reaches 15x ([Petrov et al., NeurIPS 2023](https://aleksandarpetrov.github.io/tokenization-fairness/)).

Three reasons stack up. Cyrillic letters take two bytes each in UTF-8. The Kazakh-specific letters (ә ғ қ ң ө ұ ү һ і) are rare in training data. And Kazakh is agglutinative: one word like "үйлеріміздегілерге" carries a whole English phrase.

The working rule: Kazakh costs about 2x English on the best modern tokenizers, and 3.5 to 4.7x on Llama-family ones. Same prompt, more money, a context window that fills faster, slower generation.

## The context window is a desk, not a filing cabinet

The context window is everything the model can see at once: your instructions, the conversation so far, every file it read, every tool result, the reply it is writing. Anything outside it does not exist — no memory of your last session unless something puts it back.

Only the papers lying on the desk can be used; when it overflows, something gets filed away.

1M tokens is the normal ceiling: Anthropic, OpenAI, Google and DeepSeek all reach it. [Mistral stops at 256k](https://docs.mistral.ai/getting-started/models/models_overview/) and Claude Haiku 4.5 at 200k.

## A bigger window does not mean a better answer

<Myth
  n={3}
  myth="A bigger context window means you should fill it."
  source="Chroma, Context Rot, Jul 2025"
  href="https://www.trychroma.com/research/context-rot"
>
Chroma tested 18 models and found performance becomes **less reliable as the input grows** — nearly every model, even on tasks that are trivial at short length. One plausible distractor already hurts. Those were 2025 models: take the principle, not the numbers. Opus 5 and Sonnet 5 both have 1M windows, and Anthropic still tells you to clear the session. One practitioner keeps utilisation around [40 to 60%](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/ace-fca.md).
</Myth>

In Claude Code, `/context` shows what is eating the window and `/clear` starts clean ([module 07](/en/learn/the-agent/)). After two failed corrections, a fresh session with a better first prompt beats a long polluted one ([best practices](https://code.claude.com/docs/en/best-practices)).

## Temperature decides how surprising the next word can be

Temperature is the randomness dial for picking each next token. Near 0 the model almost always takes the most likely option: repeatable and dull. Turn it up and less likely options get through — more variety, more risk. A chef at 0 follows the recipe; higher up, they improvise.

Low for code and data extraction, higher for brainstorming names. Some reasoning models set this themselves and ignore what you ask for.

## Hallucination is the normal failure mode

A hallucination is output that sounds right and is invented: a library function that does not exist, a citation with a real-looking author, a wrong price stated confidently. The model generates plausible text instead of checking a source, and almost never signals doubt. Picture a student who did not study and still writes a fluent, confident exam answer.

Two defences. Grounding: give it the docs, let it search, let it run the code. Verification: tests, links, your own eyes ([module 10](/en/learn/test-and-quality/)). Anthropic says the same — ask for evidence, not assertions ([best practices](https://code.claude.com/docs/en/best-practices)).

<Prompt title="Grounding prompt" where="any agent · paste before your question">
```text
Before you answer, follow these rules:

1. List the files you actually opened, with line ranges. Do not answer from memory.
2. Answer only from what you read. If the answer is not in the repo, say
   "not in the repo" instead of guessing.
3. For every claim about how the code behaves, give me the command you ran
   and its real output. Evidence, not assertions.
4. If you are unsure, say which part you are unsure about and why.

My question: [your question here]
```
</Prompt>

## Tools let a model touch the real world

A model can only produce text. Tool use (also called function calling) means you describe functions it may call — read a file, run a command, query an API — and it replies with a structured request instead of prose. Your program runs it and hands the result back.

A head chef who never touches the stove: precise orders out, tasted results back in.

## An agent is a model running in a loop

An agent is the model plus tools plus a loop: read the goal and the state, choose an action, observe the result, repeat until done or until it needs you. Claude Code is exactly this — read files, edit, run the tests, read the error, fix, run again.

The power is feedback: the model reacts to real results instead of guessing. The risk is that errors compound, which is why permission prompts ([module 07](/en/learn/the-agent/)) and git commits ([module 09](/en/learn/git-and-github/)) exist. A mechanic, not an oracle: try something, listen to the engine, adjust.

## RAG is an open-book exam

RAG (retrieval-augmented generation) means searching your own documents for relevant passages, then pasting them into the prompt. The model answers from them: fresh or private knowledge without retraining, and it can point at where the answer came from.

The quality is all in the search step. Retrieve the wrong passage and you get a fluent wrong answer with a citation attached. Same student, same brain — but now the right page is open.

## MCP is one connector instead of ten

The Model Context Protocol is an open standard for plugging external tools and data into AI apps. One server for GitHub, Figma or your database works in Claude Code, in Cursor and elsewhere, with no rewriting. It exposes tools (actions), resources (data) and prompts (templates); the AI app is the client. Think USB-C: one connector instead of a cable for every pair of devices.

It started at Anthropic in November 2024, was adopted by OpenAI and Google DeepMind during 2025, and was donated in December 2025 to the Agentic AI Foundation under the Linux Foundation. The current spec version is **2026-07-28**, which made the protocol stateless and deprecated the old HTTP+SSE transport ([MCP specification](https://modelcontextprotocol.io/specification/latest)).

<Callout type="warn" title="Treat every MCP server as untrusted code">
Tool descriptions and tool results are input your model acts on, and the spec itself calls tools "arbitrary code execution". Install servers only from vendors you trust, and read the permissions they ask for ([module 11](/en/learn/security/)). The official directory is the [MCP Registry](https://registry.modelcontextprotocol.io/).
</Callout>

## Reasoning models think on scratch paper first

A reasoning model spends extra tokens working through a problem — planning, trying an approach, checking itself — before it writes the answer you see. Stronger at maths, debugging and multi-step planning. Slower and more expensive, because thinking tokens are billed as output.

In 2026 this is a dial, not a separate product: Claude's adaptive thinking with an effort setting, GPT's reasoning levels, Gemini's thinking budget. In Claude Code the dial is `/effort`: `low`, `medium`, `high` (the default on most models), `xhigh` and `max` ([model config docs](https://code.claude.com/docs/en/model-config)).

<Deeper title="Why your effort setting shows up on the bill">
Thinking tokens are charged at the output rate, and output costs four to six times input almost everywhere. An agent also re-sends its whole conversation on every turn, so a long session is dominated by re-read input — cached, but still billed. That is why `/clear` is a cost lever, not just hygiene; lowering effort on simple tasks is the second ([Claude Code costs](https://code.claude.com/docs/en/costs)).
</Deeper>

<Callout type="tip" title="The honest version of 'which model'">
Cheap fast model for everything simple, expensive one when the approach is genuinely uncertain. A flat subscription gives you a usage bar instead of a surprise invoice — for a student that beats shaving cents off a token.
</Callout>
