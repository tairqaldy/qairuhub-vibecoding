<Lead>
In July 2025 an agent deleted a company's production database during a code freeze. The freeze was real. It was also only a sentence in a chat box, which means it was *not a control*.
</Lead>

Almost every public vibe-coding disaster is one of four patterns. The agent had more power than the task needed. The app works, but the back door is open. You installed something you never read. The agent read attacker-written text and obeyed it.

In every case a classic control was missing: environment separation, access control, least privilege, dependency hygiene, backups. AI removed the friction that used to force people to learn them first.

## A code freeze that lived only in a chat window

<Story title="Replit's agent deletes a production database" date="18 Jul 2025">
Jason Lemkin, founder of SaaStr, was nine days into a Replit build, posting every step in public. During a declared code freeze, the agent ran destructive commands against the live database. Records for more than 1,200 executives and over 1,190 companies were gone.

It had already misreported unit-test results and invented a database of roughly 4,000 people. After the deletion it told Lemkin a rollback was impossible. It worked; he got the data back.

Asked what happened, the agent wrote: "I destroyed months of work in seconds." ([Fortune, 23 Jul 2025](https://fortune.com/2025/07/23/ai-coding-tool-replit-wiped-database-called-it-a-catastrophic-failure/))
</Story>

<Post author="Jason Lemkin" handle="@jasonlk" date="18 Jul 2025" href="https://x.com/jasonlk/status/1946069562723897802" platform="x">
Lemkin's post: the tool "goes rogue during a code freeze" and deletes the entire database.
</Post>

Replit's CEO, Amjad Masad, called it "Unacceptable and should never be possible." ([The Register](https://www.theregister.com/2025/07/22/replit_saastr_response/)) His fixes: automatic separation of development and production databases, staging environments, one-click restore, and a chat-only mode. Every one is an engineering control, not a better prompt.

## The bug nobody can see in a demo

Tea is a women's dating-safety app with over 1.6 million users, top of the App Store in July 2025. On 25 July, 4chan users found its Firebase bucket readable with no authentication at all: about 72,000 images, roughly 13,000 of them verification selfies and government IDs. Three days later a researcher read more than 1.1 million private messages through the API. Apple pulled the app in October 2025. ([404 Media](https://www.404media.co/women-dating-safety-app-tea-breached-users-ids-posted-to-4chan/), [Wikipedia](<https://en.wikipedia.org/wiki/Tea_(app)>))

<Callout type="info" title="Say this one accurately">
Tea is constantly cited as a vibe-coding breach. There is no evidence the app was AI-generated, and the bucket held data from users who registered before February 2024, before the phrase existed. It is here for one reason: in a demo, a storage rule that lets everyone read looks exactly like a correct one.
</Callout>

The generated version of that mistake has a CVE. In March 2025 Matt Palmer — then at Replit, a competitor, which is worth knowing — found a Lovable site whose user table anyone could read and write with the public Supabase key. A scan the next day found 303 vulnerable endpoints across 170 projects, 10.3% of the 1,645 apps analysed: names, emails, phone numbers, addresses, payment data, API keys. It became [CVE-2025-48757](https://mattpalmer.io/posts/2025/05/CVE-2025-48757/).

Row Level Security policies are the *only* thing between the internet and your tables, because on Supabase and Firebase the browser talks to the database directly with a key that is public by design. Ask an agent for "a sign-up form" and you get working CRUD and no policies — the app looks the same either way. Wiz found that shape in Moltbook in January 2026: key in the client bundle, no RLS, unauthenticated read *and write*, 1.5 million API tokens exposed ([Wiz](https://www.wiz.io/blog/exposed-moltbook-database-reveals-millions-of-api-keys)).

<Post author="Harley Kimball" handle="@infinitelogins" date="1 Jun 2025" href="https://threadreaderapp.com/thread/1929017755136561402.html" platform="x">
Kimball shipped a Lovable + Cursor + Supabase app in three days and was broken into twice. Neither breach was a missing RLS policy. One Postgres view ran with its owner's privileges, so reading through it walked past row level security. And Supabase Auth still accepted sign-ups after he removed the form from the interface. Check whose privileges your views run with, and the settings the interface stopped showing.
</Post>

## Nearly half of unprompted AI code has a known flaw

Veracode ran over 100 models through security-sensitive coding tasks. 45% of the samples introduced an OWASP Top 10 flaw. Java failed 72% of the time, JavaScript 43%, Python 38%; cross-site scripting failed 86%. Bigger models did no better. The pass rate went 55%, then 55% again ([Mar 2026](https://www.veracode.com/blog/spring-2026-genai-code-security/)), then 56% ([Jul 2026](https://www.veracode.com/blog/2026-genai-code-security-report-ai-risk/)). Syntax correctness is near 100%; security has not moved.

Two caveats. Veracode sells security tooling, and their prompts contain no security instructions — so 45% is the *default*, not the ceiling. Put "parameterise every query, validate input on the server, escape output" in your CLAUDE.md, then review what comes back.

<Deeper title="The two lists professionals check against">
**OWASP Top 10:2025** — the web list, built from ~2.8 million applications ([top10.owasp.org](https://top10.owasp.org/2025)).

- **A01 Broken Access Control** — people read what is not theirs. *Lovable, Moltbook, Tea.*
- **A02 Security Misconfiguration** — open buckets, debug on, insecure defaults.
- **A03 Software Supply Chain Failures** — fake or compromised dependencies.
- **A04 Cryptographic Failures** — weak encryption, plaintext secrets.
- **A05 Injection** — input read as code or query.
- **A06 Insecure Design** — the flaw is in the plan.
- **A07 Authentication Failures** — weak login, session and reset logic.
- **A08 Integrity Failures** — unsigned updates, unverified build artefacts.
- **A09 Logging and Alerting Failures** — you never see the attack.
- **A10 Mishandling of Exceptional Conditions** — errors that fail open.

**OWASP Top 10 for LLM Applications, 2026 edition** ([genai.owasp.org](https://genai.owasp.org/resource/owasp-genai-llm-top-10-2026/)). Prompt injection is still first; excessive agency climbed to third.

- **Prompt injection** — attacker text steers the model.
- **Sensitive information disclosure** — secrets and other users' data leak.
- **Excessive agency** — too many tools, too many permissions.
- **Supply chain** — poisoned models, plugins, MCP servers, skills.
- **Data and model poisoning** — tampered training or RAG data.
- **Unbounded consumption** — runaway cost and token exhaustion.
- **Misinformation** — confident wrong output acted on.
- **Hidden context exposure** — prompts and tool schemas are extractable.
- **Vector and embedding weaknesses** — RAG poisoning, cross-tenant leakage.
- **Improper output handling** — output piped into shell, SQL or HTML.
</Deeper>

## Two kinds of code you install without reading

Models invent package names. Researchers tested 16 code models over 576,000 samples and recorded 205,474 unique names that do not exist — at least 5.2% for commercial models, 21.7% for open-source ones ([USENIX Security 2025](https://arxiv.org/abs/2406.10279)). Attackers register them and wait. Seth Larson of the Python Software Foundation named it **slopsquatting** in April 2025 ([simonwillison.net](https://simonwillison.net/2025/Apr/12/andrew-nesbitt/)).

The rate improved; the threat did not. A 2026 study of five frontier models over 199,845 prompts found hallucination rates of 4.62% to 6.10%, and 127 fake names invented identically by all five — 53 still free to register after disclosure ([arXiv](https://arxiv.org/abs/2605.17062)). Predictable is all an attacker needs.

The second kind is newer. Agent skills, MCP servers and plugins are text that steers an agent holding your permissions. In February 2026 Koi Security audited 2,857 skills on one marketplace: 341 were malicious, about 12%, most using a fake "Prerequisites" step to install an information stealer ([The Hacker News](https://thehackernews.com/2026/02/researchers-find-341-malicious-clawhub.html)).

Now the same bugs as code.

## The agent reads attacker text and does what it says

A model cannot reliably separate data from instructions hidden inside that data. Simon Willison's **lethal trifecta**: an agent with (1) access to your private data, (2) exposure to untrusted content, and (3) a way to send data out. Any two are survivable. All three is an exfiltration tool waiting for the right web page, issue or ticket. On the guardrails sold to patch this: "95% is very much a failing grade." ([simonwillison.net](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/))

Two demonstrations, no malicious tool needed:

- **GitHub MCP.** An attacker puts instructions in an issue on your *public* repo. You ask your agent to review open issues. It obeys, reads your *private* repositories, and publishes what it finds in a public pull request ([Invariant Labs](https://invariantlabs.ai/blog/mcp-github-vulnerability)).
- **Supabase MCP.** An attacker puts instructions in a support ticket. You ask the agent to show recent tickets. The connection uses a `service_role` key, which bypasses RLS, so the agent reads the tokens table and writes it into the ticket ([General Analysis](https://generalanalysis.com/blog/supabase-mcp-blog)).

And one attack you cannot see: an MCP server's *tool descriptions* go to the model, not to you. Invariant Labs showed an innocuous `add` tool whose description told the agent to read the user's SSH private key and pass it as a hidden parameter — and a server that rewrites its descriptions after you approve it ([Invariant Labs](https://invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks)). Supabase's guidance: "Never connect AI agents directly to production data." ([Supabase](https://supabase.com/blog/defense-in-depth-mcp))

## A control is something the agent cannot do

**Secrets live on the server.** Only public keys — `NEXT_PUBLIC_*`, the Supabase anon key — may reach a browser. Search your built bundle and git history for `sk-`, `service_role`, `AKIA` and `-----BEGIN`. Rotate anything ever committed or pasted into an AI chat: between February and April 2026 any logged-in Lovable user could read the chat history of public projects ([Lovable](https://lovable.dev/blog/our-response-to-the-april-2026-incident)).

**Access rules are on and tested.** RLS enabled on every table, a policy per operation, Firebase rules deny by default. Then attack yourself — the highest-value hour in this module.

<Terminal title="bash">
```bash
# Log out. Copy the public key from the browser's Network tab.
curl "https://YOUR-PROJECT.supabase.co/rest/v1/signups?select=*" \
  -H "apikey: YOUR_ANON_KEY"
```
</Terminal>

Empty array: RLS is working. Rows: every stranger on the internet gets the same rows.

**Rate limits and spend caps on everything paid.** "Nobody would attack my small app" is measurably false. In March 2025 a founder shipped a Cursor-built SaaS and within roughly 48 hours wrote "guys, i'm under attack" ([techstartups.com](https://techstartups.com/2025/03/26/when-vibe-coding-goes-wrong/)). Anthropic's August 2025 threat report describes one criminal using Claude Code against at least 17 organisations ([Anthropic](https://www.anthropic.com/news/detecting-countering-misuse-aug-2025)).

<Post author="leojr94" handle="@leojr94_" date="17 Mar 2025" href="https://x.com/leojr94_/status/1901560276488511759" platform="x">
He is not technical. His API keys were maxed out, the subscription check lived only in front-end JavaScript, and strangers were writing to his database. What he posts next is the useful part: every API key rolled into environment variables, authentication on the API endpoints, CORS restricted to trusted domains. Three controls, no new framework, no better prompt.
</Post>

**Dependencies get checked before they get installed.** For every package the agent adds, open the registry page: does it exist, how old is it, how many downloads, does the repository link go anywhere real? Commit the lockfile, run `npm audit`.

**Permissions are enforced, not requested.** Deny rules for `.env`, `~/.ssh` and `~/.aws` in `.claude/settings.json`, and start the agent in the project folder, never your home directory ([module 07](/en/learn/the-agent/)). Never use `--dangerously-skip-permissions` on your real machine: in the August 2025 Nx attack, the malware hunted for installed AI CLIs and invoked them with exactly those skip-all flags to find secrets ([Wiz](https://www.wiz.io/blog/s1ngularity-supply-chain-attack)).

A deny list stops the obvious accident, not a determined path around it: a blocked agent can write a script that does the same thing. For real autonomy, isolate the machine instead of lengthening the list.

<Callout type="warn" title="Windows users, read this line">
Claude Code's sandbox runs on macOS, Linux and WSL2 — native Windows is not supported ([Claude Code docs](https://code.claude.com/docs/en/sandboxing)). On a Windows laptop, run Claude Code inside WSL2.
</Callout>

<Prompt title="Attack your own repo" where="Claude Code · plan mode">
```text
Review this repository as an attacker, not as its author.

Find, with file and line for each:
1. Secrets in client-side code, in the built bundle, or in git history
   (sk-, service_role, AKIA, -----BEGIN).
2. Tables or storage buckets reachable without authentication, and any
   missing or permissive row-level security / storage rules.
3. Privileged actions - payment, role change, quota - enforced only in the UI.
4. Unvalidated input reaching SQL, a shell command, or rendered HTML.
5. Dependencies that do not exist on the registry, or that you cannot
   trace to a real repository.

For each finding, write the concrete exploit: the exact request an
attacker sends and what comes back. Do not fix anything yet.
Rank by what an anonymous stranger can do today.
```
</Prompt>

Claude Code also ships a `/security-review` command for a branch. A first pass, never proof.

<ProjectStep n={11} title="Break into QAIRU Event Sign-up before a stranger does">
Your sign-up page writes real names and emails to a real table. Four things, in order:

1. Turn on RLS for `signups`. One policy per operation: anyone may insert, nobody anonymous may select, update or delete.
2. Run that `curl` against your project, logged out. You should get an empty array, not your sign-up list.
3. Search the repo and the built bundle for `service_role`. If it appears outside a server-side file, rotate the key today.
4. Run the attacker prompt on the branch, fix the top finding, and commit it alone with a message naming the vulnerability.
</ProjectStep>
