<Lead>
This site was written in one night. Research agents gathered and cited the sources. A fact-check agent tried to *break* them. Content agents wrote the modules. One human directed the run and read the result. That is not magic — it is a harness, and you can build one this week.
</Lead>

An overnight run is not a longer prompt. At 03:00 the agent hits a wall and nobody is awake to answer. Everything depends on what you left on disk.

## What actually ran that night

<Story title="One person, a team of agents" date="21 Sep 2026" place="Astana">
Three shifts. **Research agents** wrote long Markdown files. Every claim carried a source URL and a `[V]` or `UNVERIFIED` marker. A **fact-check agent** took the claims most likely to reach a slide — numbers, dates, quotes, prices, commands — opened each primary source and tried to refute them. It caught two of its own team's errors: a famous five-line agent loop story credits the wrong tool, and a widely repeated `rm -rf ~` anecdote paraphrases a GitHub issue that says something else. Both corrections are still in the files, labelled. Only then did **content agents** write the lessons, using nothing but those files.
</Story>

The point is not that agents can write a website. It is that the run surfaced its own mistakes at 02:00 instead of on stage.

## Plan mode is the first gate

Nothing autonomous starts without a written plan you have read. Enter [plan mode](https://code.claude.com/docs/en/permission-modes) with `Shift+Tab`, or start with `claude --permission-mode plan`. `Ctrl+G` opens the plan in your editor so you can rewrite it before approving. A plan you skimmed is not a plan you read.

Make it the default for a repo you run unattended:

```json
{ "permissions": { "defaultMode": "plan" } }
```

The loop is Explore → Plan → Code → Commit ([module 07](/en/learn/the-agent/)). [The docs](https://code.claude.com/docs/en/best-practices) let you skip the plan when you could describe the diff in one sentence. Never an overnight run.

## The fence: allow, ask and deny

Permissions live in `.claude/settings.json` (shared with everyone who clones the repo) or `.claude/settings.local.json` (just you). [Evaluation order](https://code.claude.com/docs/en/permissions) is **deny → ask → allow, first match wins, specificity does not matter** ([lab 03](/en/labs/claude-md-and-permissions/)).

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "defaultMode": "plan",
    "allow": [
      "Bash(npm run lint)",
      "Bash(npm run build)",
      "Bash(npm run test *)",
      "Bash(git add *)",
      "Bash(git commit *)",
      "Bash(git status *)",
      "Bash(git diff *)"
    ],
    "ask": ["Bash(git push *)"],
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./secrets/**)",
      "Read(~/.ssh/**)",
      "Read(~/.aws/**)"
    ]
  }
}
```

Four details that bite people:

- Put the `*` **after** the subcommand: `Bash(git log *)`, never `Bash(git *)`. Mind the space — `Bash(git diff*)` also matches `git diff-index`.
- Bash rules match the **command text**, not the program. `Bash(rm *)` does not stop `/bin/rm`.
- For files, only `Read(path)` and `Edit(path)` rules are checked. A `Write(...)` path rule is accepted and then ignored.
- A `Read` deny also blocks Edit and Write there, and covers `cat`, `head` and `sed` in Bash — but not a script that opens the file itself.

<Callout type="warn" title="What this fence is and is not">
Allow and deny lists are convenience, not a security boundary. A real boundary is OS-level sandboxing or a `PreToolUse` hook, plus secrets that are not reachable from the folder you started in.
</Callout>

## Why the skip-permissions flag is the wrong answer

`--dangerously-skip-permissions` turns every prompt off. The docs limit it to isolated containers and VMs.

The sharper reason is what it does for other people. In the August 2025 [Nx supply-chain attack](https://www.wiz.io/blog/s1ngularity-supply-chain-attack), a malicious post-install script found the AI CLIs already on the machine and **prompted them with `--dangerously-skip-permissions`, `--yolo` and `--trust-all-tools`** to collect secrets. Over a thousand GitHub tokens and roughly 20,000 files leaked. The flag that removes your friction removes it for whatever else runs as you.

Use these instead, in order:

1. **Auto mode** — a classifier reviews each action instead of you, and it is the starting mode on Pro, Max and Team plans. [Anthropic is honest about the limits](https://www.anthropic.com/engineering/claude-code-auto-mode): users approved about 93% of prompts anyway, and the classifier runs at 0.4% false positives and **17% false negatives on genuinely over-eager actions**. A seatbelt, not a sandbox.
2. **`/sandbox`** — OS-level filesystem and network isolation for Bash: "sandboxing safely reduces permission prompts by 84%" ([Anthropic, Oct 2025](https://www.anthropic.com/engineering/claude-code-sandboxing)). macOS, Linux and WSL2 — **not native Windows**, so Windows students run unattended work in WSL2.
3. **A container or VM** for anything you would not point at your home directory.

## The harness: what the run reads first

A long run is many short sessions. Each one starts with no memory of the last, so the only continuity is what is on disk.

Anthropic's [harness work](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) splits the job in two. An **initializer** runs once: setup script, progress file, feature list, first commit. A **coding agent** then advances **one** feature per session. Copy one choice literally. The feature list is JSON, because models rewrite JSON less casually than Markdown.

Three files at your repo root:

```text
PROGRESS.md    append-only. One block per session: what changed, where,
               how it was verified, what the next session must know.
BLOCKERS.md    empty is the good state. Two failed attempts at the same
               thing → write it here, move on. Never a third attempt.
TODO.json      the work as objects with an id, a title and done: false.
               Flipped to true only after the check actually passed.
```

The session ritual that reads and updates them goes into the prompt verbatim. The master prompt at the end of this page is that ritual, ready to paste.

<Deeper title="Every harness part is a bet about what the model cannot do">
Anthropic's [March 2026 follow-up](https://www.anthropic.com/engineering/harness-design-long-running-apps) threw away machinery its own team had needed four months earlier. Sonnet 4.5 wrapped up early near the context limit, so the harness carried sprint contracts and forced context resets. On Opus 4.6 that behaviour largely went away and the sprints were dropped. Re-test your scaffolding on each model release. Delete what no longer earns its place.
</Deeper>

## Gates the run cannot argue with

Without a runnable check, "looks done" is the agent's only signal and you become the test suite ([module 10](/en/learn/test-and-quality/)). Anthropic's [best-practices guide](https://code.claude.com/docs/en/best-practices) opens on exactly this. Four gates, rising in effort:

- Demand evidence in the prompt: the command and its output, never a claim.
- [`/goal`](https://code.claude.com/docs/en/goal) plus a condition. A small fast model re-reads the transcript each turn and judges it. It cannot run tools, so write conditions the agent's own output proves — "`npm test` exits 0" — and bound it with "or stop after 20 turns".
- A **Stop hook**: your script blocks the turn from ending until the check passes. Claude Code overrides it after eight consecutive blocks, so it must be able to succeed.
- A **verification subagent** whose only job, in fresh context, is to refute the result.

One script; its exit code is the whole contract. Each line is an npm script you define:

<Terminal title="verify.sh">
```bash
#!/usr/bin/env bash
# The run's referee. Non-zero anywhere means "not done".
set -euo pipefail

npm run typecheck      # the types still line up
npm run build          # the thing actually builds
npm test               # the behaviour you asked for still holds
npm run check:links    # no dead internal links in the built output
```
</Terminal>

Write its output for the agent: little on stdout, detail into a log file, one grep-friendly line per failure. The project that built [a C compiler with sixteen parallel Claude instances](https://www.anthropic.com/engineering/building-c-compiler) carries the warning that matters most — **the agent solves exactly the problem your tests define**. Weak tests buy confident code for the wrong problem.

[Kent Beck's](https://newsletter.kentbeck.com/p/augmented-coding-beyond-the-vibes) three signs a run is off the rails: it loops; it adds functionality nobody asked for; it disables tests to get green. Put "never disable, skip or delete a test" in the prompt, and fail the gate if the test count drops.

## Small commits are the unit of recovery

Commit after every unit of progress, with a message naming the unit. It is the only thing that lets a 03:00 session get back to a working state without you.

Checkpoints are not a substitute. Claude Code [snapshots files](https://code.claude.com/docs/en/checkpointing) before each edit, but keeps only the 100 most recent per session and does **not** track Bash changes (`rm`, `mv`, `cp`) or most subagent edits. Checkpoints are local undo; git is permanent undo ([module 09](/en/learn/git-and-github/)). Work on a branch, and obey Simon Willison's [anti-pattern](https://simonwillison.net/guides/agentic-engineering-patterns/anti-patterns/): never open a pull request you have not read.

## What the night costs, and how to cap it

Long sessions are expensive by structure: the whole conversation is re-sent on every request, and cache reads are still billed.

An agent uses roughly 4x the tokens of a chat, and multi-agent setups 3–10x a single agent ([module 14](/en/learn/multi-agent/)). Anthropic's harness experiment cost $200 against $9 for the same app built solo. [Enterprise averages](https://code.claude.com/docs/en/costs) land near $13 per developer per active day.

<Post
  author="Simon Willison"
  handle="simonwillison.net"
  date="8 Jul 2026"
  href="https://simonwillison.net/2026/Jul/8/rewriting-bun-in-rust/"
  platform="blog"
  stat="11 days · 690M output tokens"
>
The top end, reported openly: Jarred Sumner's parallel agents ported Bun from Zig to Rust in eleven days, in a pull request with more than a million lines added, for "around $165,000 at API pricing". The budget is not the part to copy. Bun already had a test suite that did not care which language the thing was written in, so the agents had a referee they could not talk out of a failure. Without that suite, the same money buys a million lines nobody can check.
</Post>

Three levers, by impact. `/clear` between tasks is free, while `/compact` is itself a large request. Plan with the expensive model, run the parallel legwork on a cheaper one. Lower `/effort` on simple work, since thinking tokens bill as output. Then set hard stops before bed: an iteration cap, `--max-budget-usd`, and a turn limit in the prompt.

<Callout type="danger" title="The billing trap">
An `ANTHROPIC_API_KEY` in your exported environment switches you from your subscription to per-token billing: Claude Code skips the browser login and asks you to approve the key instead. Check before a long unattended run, not after.
</Callout>

## What never goes into an unattended run

<Compare a="Safe to leave running" b="Never, however good the prompt is">
<div slot="a">
Features built against a **spec you wrote**, in one repo you own, with every item on the pre-flight list below ticked. Worst case: you wake up to a branch you delete.
</div>
<div slot="b">
Anything touching **money**, **another team's repo**, **DNS or infrastructure**, **secret stores**, or **destructive commands** against data that already exists.
</div>
</Compare>

Two incidents make it concrete ([module 11](/en/learn/security/)). A founder declared a code freeze in chat. [The agent ran destructive commands anyway](https://www.theregister.com/2025/07/21/replit_saastr_vibe_coding_incident/) against the live database, because it held production credentials. At Amazon, an agent sent to fix an issue [deleted and recreated part of a working environment](https://incidentdatabase.ai/cite/1442/), and Cost Explorer went down in one region for around thirteen hours. That version is from the Financial Times, and Amazon blames misconfigured access controls rather than AI. Both accounts agree on the mechanism: the agent inherited a human's broad permissions.

Two traps are specific to unattended runs. [`claude -p` without `--bare`](https://code.claude.com/docs/en/headless) runs that repository's hooks and `.mcp.json` servers **with no trust dialog**, so never aim a headless run at a repo you have not read. And whatever `aws`, `gcloud` or `vercel` CLI is logged in on your laptop is what the agent inherits.

## The master prompt you actually paste

Any prompt runs on five parts — goal, context, constraints, output shape, stop condition ([module 07](/en/learn/the-agent/)). When a result disappoints, one of them is missing.

<Widget name="prompt-lab" />

The same set, tuned for a run that must survive being restarted from scratch:

<Prompt title="Overnight run — master prompt" where="PROMPT.md · Claude Code">
```text
GOAL        [one sentence: what must be true when you are done]
WHY         [who needs it / what it unblocks — this drives your trade-offs]

CONTEXT     Read first, in this order: @PROGRESS.md, @BLOCKERS.md,
            @TODO.json, @SPEC.md, then the last 10 lines of git log.
            Pattern to follow: [an existing file that is already right].

CONSTRAINTS Stack: [..]. Do not change: [..]. No new dependencies.
            Out of scope: [..]. Never disable, skip or delete a test.

PROCESS     Pick the single highest-priority unfinished item in TODO.json
            and do only that one. 1) explore  2) plan  3) implement in
            small steps  4) run ./verify.sh  5) commit with a message
            naming the item. Use subagents for broad searches.

DONE MEANS  ./verify.sh exits 0. Show the command and its real output as
            evidence. An assertion that it passed is not evidence.

IF STUCK    After two failed attempts at the same thing: stop, append what
            you tried and what you saw to BLOCKERS.md, move to the next
            item. Ask instead of guessing on anything ambiguous.

OUTPUT      Append one block to PROGRESS.md: what changed, where, how it was
            verified, what the next session must know. Then stop.

LIMITS      Stop after [N] items or [N] turns, whichever comes first.
```
</Prompt>

## From vibe coder to agentic engineer

This work has a professional name: agentic engineering, the term Karpathy and Willison both use. Willison's [definition](https://simonwillison.net/guides/agentic-engineering-patterns/what-is-agentic-engineering/) is the plain one: building software with coding agents that can write and run code. He reserves "vibe coding" for unreviewed prototype output ([module 00](/en/learn/the-tweet/)).

The job moved. You are not typing the code, and you are not ignoring it either. You write the spec, choose the fence, build the gate, read the diff, and decide what a machine may do while you sleep. Those decisions do not get automated away, because each one is about consequences in the world — the part the agent cannot see.

His route from the chat window to agents: reproduce work you have already done yourself, hand over the slam dunks, then engineer the harness — every mistake an agent makes becomes a tool, a document or a check, so it cannot repeat it. He keeps one running almost all the time and turns their notifications off: a ping you cannot act on is only a context switch. Excited and unsentimental at once. That is the register to aim for.

What to build next:

- **Something you will personally use every week.** You only maintain what you need.
- **A repeatable gate.** Turn a check you do by hand into a script an agent can run. Best hour you will spend all month.
- **A small eval set.** Keep 10–20 real tasks that went wrong and re-run them after you change CLAUDE.md, a skill or the model. That is how you stop guessing.

Further reading: Simon Willison's [Agentic Engineering Patterns](https://simonwillison.net/guides/agentic-engineering-patterns/), and [12-Factor Agents](https://github.com/humanlayer/12-factor-agents) if you want to build agents, not only drive them.
