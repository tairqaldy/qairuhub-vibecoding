<Lead>
Сен оқып отырған сайт бір түнде жазылды. Зерттеу агенттері дереккөздерді жинап, әрқайсысына сілтеме қойды. Факт тексеретін агент соларды *сындырып* көрді. Мазмұн агенттері модульдерді жазды. Бір адам бағыт беріп, нәтижесін оқып шықты. Бұл сиқыр емес — бұл harness (агент түнде сүйенетін тірек жүйе), оны сен де осы аптада құра аласың.
</Lead>

Түнгі жұмыс — жай ғана ұзынырақ промпт емес. Түнгі 03:00-де агент тығырыққа тіреледі, ал жауап беретін адам ұйықтап жатады. Бәрі сенің дискіде не қалдырғаныңа байланысты.

## Сол түні шын мәнінде не істелді

<Story title="Бір адам, бір топ агент" date="21 Sep 2026" place="Астана">
Үш ауысым. **Зерттеу агенттері** ұзын Markdown файлдарын жазды: әр тұжырымның қасында дереккөз сілтемесі және `[V]` не `UNVERIFIED` белгісі тұрды. **Факт тексеретін агент** слайдқа шығу ықтималдығы ең жоғары тұжырымдарды — сандарды, күндерді, дәйексөздерді, бағаларды, пәрмендерді — бөліп алды да, бастапқы дереккөзін ашып, оларды теріске шығаруға тырысты. Ол өз командасының екі қатесін тапты: бес жолдық агент циклі туралы әйгілі әңгіме басқа құралға қатысты болып шықты, ал жиі қайталанатын `rm -rf ~` оқиғасы GitHub-тағы issue мәтінінің еркін мазмұндамасы екен. Екі түзету де файлдарда, белгісімен тұр. Тек содан кейін ғана **мазмұн агенттері** сабақтарды жазды — сол файлдардан басқа ештеңеге сүйенбей.
</Story>

Мәселе агенттердің сайт жаза алатынында емес. Мәселе басқада: бұл жұмыс өз қателерін сахнада емес, түнгі 02:00-де бетке шығарды.

## Жоспарлау режимі — бірінші қақпа

Сен оқып шыққан жазбаша жоспар болмайынша, ешқандай автономды жұмыс басталмайды. [Жоспарлау режиміне](https://code.claude.com/docs/en/permission-modes) `Shift+Tab` арқылы кір немесе бірден `claude --permission-mode plan` деп баста. `Ctrl+G` жоспарды редакторда ашады — мақұлдамай тұрып қайта жазып шығуға болады. Үстірт қарап шыққан жоспар — оқылған жоспар емес.

Қараусыз жұмыс істейтін репозиторийде оны әдепкі режим қыл:

```json
{ "permissions": { "defaultMode": "plan" } }
```

Цикл мынадай: Explore → Plan → Code → Commit ([07-модуль](/kk/learn/the-agent/)). [Құжаттама](https://code.claude.com/docs/en/best-practices) diff-ті бір сөйлеммен сипаттай алатын кезде жоспарды өткізіп жіберуге рұқсат етеді. Түнгі жұмыс ондай емес.

## Қоршау: allow, ask және deny

Рұқсаттар `.claude/settings.json` файлында (репозиторийді клондаған әркімге ортақ) немесе `.claude/settings.local.json` файлында (тек сенде) тұрады. [Тексеру реті](https://code.claude.com/docs/en/permissions) мынадай: **deny → ask → allow, бірінші сәйкестік жеңеді, нақтылық рөл ойнамайды** ([03-зертхана](/kk/labs/claude-md-and-permissions/)).

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "defaultMode": "plan",
    "allow": [
      "Bash(npm run lint)",
      "Bash(npm run build)",
      "Bash(npm run test *)",
      "Bash(git add *)",
      "Bash(git commit *)",
      "Bash(git status *)",
      "Bash(git diff *)"
    ],
    "ask": ["Bash(git push *)"],
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./secrets/**)",
      "Read(~/.ssh/**)",
      "Read(~/.aws/**)"
    ]
  }
}
```

Көбіне сүріндіретін төрт нәрсе:

- `*` таңбасын ішкі пәрменнен **кейін** қой: `Bash(git log *)`, ешқашан `Bash(git *)` емес. Бос орынға да мән бер — `Bash(git diff*)` деген жазу `git diff-index` пәрменіне де сәйкес келеді.
- Bash ережелері бағдарламаға емес, **пәрмен мәтініне** қарап сәйкестендіріледі. `Bash(rm *)` ережесі `/bin/rm` шақыруын тоқтатпайды.
- Файлдар үшін тек `Read(path)` және `Edit(path)` ережелері қаралады. `Write(...)` жолы бар ереже қабылданады да, ешқашан тексерілмейді.
- `Read` бойынша тыйым сол жерде Edit пен Write әрекетін де бұғаттайды әрі Bash-тегі `cat`, `head`, `sed` пәрмендерін қамтиды — бірақ файлды өзі ашатын скриптті қамтымайды.

<Callout type="warn" title="Бұл қоршау не және не емес">
Allow мен deny тізімдері — ыңғайлылық, қауіпсіздік шекарасы емес. Нағыз шекара — операциялық жүйе деңгейіндегі sandbox немесе `PreToolUse` hook, оған қоса жұмысты бастаған қалтадан қол жетпейтін жерде жатқан құпия деректер.
</Callout>

## Рұқсаттарды өшіретін жалауша неге дұрыс жауап емес

`--dangerously-skip-permissions` барлық сұрауды өшіреді. Құжаттама бұл жалаушаны (flag) тек оқшауланған контейнерлер мен виртуалды машиналармен шектейді.

Одан да өткір себеп — оның басқаларға не істейтіні. 2025 жылғы тамызда болған [Nx жеткізу тізбегіне шабуылда](https://www.wiz.io/blog/s1ngularity-supply-chain-attack) зиянды post-install скрипті машинада бұрыннан тұрған ЖИ CLI құралдарын тауып алды да, **оларға `--dangerously-skip-permissions`, `--yolo` және `--trust-all-tools` жалаушаларымен промпт беріп**, өзіне құпия деректерді жинатты. Мыңнан астам GitHub токені және шамамен 20 000 файл сыртқа шықты. Сенің кедергіңді алып тастайтын жалауша сенің атыңнан жүрген кез келген басқа нәрсе үшін де оны алып тастайды.

Оның орнына мыналарды осы ретпен қолдан:

1. **Auto режимі** — әр әрекетті сенің орныңа классификатор қарайды, әрі ол Pro, Max және Team жоспарларында бастапқы режим. [Anthropic оның шегін ашық айтады](https://www.anthropic.com/engineering/claude-code-auto-mode): пайдаланушылар сұраулардың шамамен 93%-ын бәрібір мақұлдайды екен, ал классификатордың жалған оң нәтижесі — 0,4%, **шынымен шектен шыққан әрекеттердегі жалған теріс нәтижесі — 17%**. Бұл — қауіпсіздік белдігі, sandbox емес.
2. **`/sandbox`** — Bash үшін операциялық жүйе деңгейіндегі файлдық жүйе мен желі оқшаулауы: "sandboxing safely reduces permission prompts by 84%" ([Anthropic, 2025 жылғы қазан](https://www.anthropic.com/engineering/claude-code-sandboxing)) — яғни рұқсат сұраулары 84%-ға азаяды. macOS, Linux және WSL2-де жұмыс істейді, **таза Windows-та жоқ**, сондықтан Windows-пен отырған студент қараусыз жұмысты WSL2 ішінде жүргізеді.
3. **Контейнер немесе виртуалды машина** — үй қалтаңа бағыттағың келмейтін кез келген іс үшін.

## Harness: жұмыс ең алдымен нені оқиды

Ұзақ жұмыс — бұл көп қысқа сеанс. Әрқайсысы алдыңғысын мүлде есіне сақтамай басталады, сондықтан жалғастықтың жалғыз көзі — дискіде жатқан нәрсе.

Anthropic-тің [harness бойынша жұмысы](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) мұны екіге бөледі. **Инициализатор** бір-ақ рет орындалады: орнату скрипті, үлгерім файлы, мүмкіндіктер тізімі, бірінші commit. Одан кейінгі әр сеанста **кодтаушы агент** **бір ғана** мүмкіндікті ұқыпты аяқтайды. Бір шешімді сөзбе-сөз көшіріп ал. Мүмкіндіктер тізімі JSON форматында, себебі модельдер JSON-ды Markdown-ға қарағанда жеңіл-желпі қайта жазып жібермейді.

Репозиторий түбірінде үш файл жатады:

```text
PROGRESS.md    append-only. One block per session: what changed, where,
               how it was verified, what the next session must know.
BLOCKERS.md    empty is the good state. Two failed attempts at the same
               thing → write it here, move on. Never a third attempt.
TODO.json      the work as objects with an id, a title and done: false.
               Flipped to true only after the check actually passed.
```

Осы файлдарды оқып, жаңартып отыратын сеанс рәсімі промптқа сөзбе-сөз түседі. Беттің соңындағы басты промпт — дәл сол рәсім, қоя салуға дайын.

<Deeper title="Harness-тің әр бөлігі — модель не істей алмайтыны туралы бәс">
Anthropic-тің [2026 жылғы наурыздағы жалғасында](https://www.anthropic.com/engineering/harness-design-long-running-apps) өз командасына төрт ай бұрын керек болған механизм лақтырылып тасталды. Sonnet 4.5 контекст шегіне жақындағанда жұмысты ертерек аяқтап қоятын, сондықтан harness ішінде спринт келісімдері мен мәжбүрлі контекст тазалау болды. Opus 4.6-да бұл мінез көбіне жоғалды да, спринттер алынып тасталды. Әр жаңа модель шыққан сайын өз тіреуіңді қайта сынап көр. Орнын ақтамайтынын жой.
</Deeper>

## Жұмыс дауласа алмайтын қақпалар

Іске қосылатын тексеру болмаса, агенттің жалғыз белгісі — «дайын сияқты» деген сезім, ал тест жинағының рөлін сен атқарасың ([10-модуль](/kk/learn/test-and-quality/)). Anthropic-тің [үздік тәжірибелер нұсқаулығы](https://code.claude.com/docs/en/best-practices) дәл осыдан басталады. Күш-жігері арта беретін төрт қақпа:

- Промптта дәлел талап ет: пәрменнің өзі және оның шығысы, құр сөз емес.
- [`/goal`](https://code.claude.com/docs/en/goal) және оған қоса бір шарт. Шағын әрі жылдам модель әр қадамда жазбаны қайта оқып, баға береді. Ол құрал іске қоса алмайды, сондықтан шартты агенттің өз шығысы дәлелдейтіндей етіп жаз — «`npm test` 0 кодымен аяқталады» — және «немесе 20 қадамнан кейін тоқта» дегенмен шектеп қой.
- **Stop hook**: сенің скриптің тексеру өтпейінше қадамның аяқталуын бұғаттайды. Қатарынан сегіз рет бұғаттағаннан кейін Claude Code оны елемей өтеді, сондықтан ол сәтті аяқтала алатындай болуы керек.
- **Тексеруші субагент** — таза контексте отырып, нәтижені теріске шығарудан басқа ешқандай міндеті жоқ агент.

Бір скрипт; оның шығу коды — бүкіл келісім. Әр жолы — сен өзің анықтайтын npm скрипті:

<Terminal title="verify.sh">
```bash
#!/usr/bin/env bash
# The run's referee. Non-zero anywhere means "not done".
set -euo pipefail

npm run typecheck      # the types still line up
npm run build          # the thing actually builds
npm test               # the behaviour you asked for still holds
npm run check:links    # no dead internal links in the built output
```
</Terminal>

Сол шығысты агентке арнап жаз: stdout-қа аз нәрсе, егжей-тегжейі журнал файлына, әр сәтсіздікке `grep` таба алатын бір жол. [Он алты Claude данасымен параллель C компиляторын жазған](https://www.anthropic.com/engineering/building-c-compiler) жобаның осы жердегі ең маңызды ескертуі мынадай — **агент сенің тестерің қандай мәселе қойса, дәл соны шешеді**. Әлсіз тест — сенімді түрде жазылған, бірақ басқа мәселені шешетін код.

[Kent Beck-тің](https://newsletter.kentbeck.com/p/augmented-coding-beyond-the-vibes) айтуынша, жұмыстың жолдан шыққанының үш белгісі бар: цикл айналады; ешкім сұрамаған функцияны қосады; жасыл нәтиже алу үшін тестерді өшіреді. Промптқа «тестті ешқашан өшірме, өткізіп жіберме, жойма» деп жаз да, тест саны азайса, қақпаны құлат.

## Шағын commit — қалпына келудің өлшем бірлігі

Әр аяқталған бөліктен кейін commit жаса, әрі хабарда сол бөліктің атын жаз. Түнгі 03:00-дегі сеанстың сенсіз-ақ жұмыс істейтін күйге орала алатын жалғыз тетігі — осы.

Checkpoint мұны алмастырмайды. Claude Code әр өңдеудің алдында [файлдардың суретін түсіреді](https://code.claude.com/docs/en/checkpointing), бірақ бір сеанста ең соңғы 100 суретті ғана сақтайды әрі Bash пәрмендері (`rm`, `mv`, `cp`) жасаған өзгерістерді және субагент өңдеулерінің көбін **бақыламайды**. Checkpoint — жергілікті болдырмау, ал git — тұрақты болдырмау ([09-модуль](/kk/learn/git-and-github/)). Тармақта жұмыс істе және Simon Willison сипаттаған [анти-үлгіні](https://simonwillison.net/guides/agentic-engineering-patterns/anti-patterns/) ұста: өзің оқып шықпаған pull request-ті ешқашан ашпа.

## Түн қанша тұрады және оны қалай шектеу керек

Ұзақ сеанстар құрылымы жағынан қымбат: әр сұрауда бүкіл әңгіме қайтадан жіберіледі, ал кэштен оқу да ақылы.

Агент чатпен салыстырғанда шамамен 4 есе көп токен жұмсайды, ал көп агентті құрылым бір агенттен 3–10 есе қымбат ([14-модуль](/kk/learn/multi-agent/)). Anthropic-тің harness тәжірибесі $200 тұрды — дәл сол қолданбаны жалғыз жасағанда $9 болған. [Компаниялардағы орташа көрсеткіш](https://code.claude.com/docs/en/costs) бір әзірлеушіге белсенді күніне шамамен $13.

## Қараусыз жұмысқа ешқашан берілмейтін нәрселер

**Өзің жазған спецификация** бойынша жасалатын мүмкіндіктер: өз репозиторийіңде, төмендегі ұшу алдындағы тізімнің әр тармағы орындалған күйде. Ең нашар жағдайда: таңертең оянып, бір тармақты жойып тастайсың.

Мұны екі оқиға нақтылай түседі ([11-модуль](/kk/learn/security/)). Бір негізін қалаушы чатта кодты өзгертуге тыйым салынғанын жариялады. [Агент бәрібір қиратушы пәрмендерді тірі дерекқорға қарсы іске қосты](https://www.theregister.com/2025/07/21/replit_saastr_vibe_coding_incident/), себебі оның қолында жұмыс ортасының (production) кілттері бар еді. Amazon-да бір мәселені түзетуге жіберілген агент [жұмыс істеп тұрған ортаның бір бөлігін жойып, қайта жасап шықты](https://incidentdatabase.ai/cite/1442/), сөйтіп бір аймақта Cost Explorer шамамен он үш сағат істемей тұрды. Бұл нұсқа Financial Times-тен алынған, ал Amazon кінәні ЖИ-ге емес, дұрыс бапталмаған қол жеткізу параметрлеріне артады. Екі баяндама да тетік жағынан бір нәрсені айтады: агент адамның кең рұқсаттарын мұра етіп алды.

Қараусыз жұмысқа тән тағы екі тұзақ бар. [`--bare` жалаушасысыз `claude -p`](https://code.claude.com/docs/en/headless) сол репозиторийдің hook-тарын және `.mcp.json` серверлерін **сенім сұрайтын терезесіз** іске қосады, сондықтан headless жұмысты өзің оқып шықпаған репозиторийге ешқашан бағыттама. Ал ноутбугіңде `aws`, `gcloud` немесе `vercel` CLI құралы қай аккаунтқа кіріп тұрса, агент соны мұра етіп алады.

## Vibe coder-ден агенттік инженерге дейін

Бұл жұмыстың кәсіби атауы бар: агенттік инженерия — Karpathy да, Willison да қолданатын термин. Willison [берген анықтама](https://simonwillison.net/guides/agentic-engineering-patterns/what-is-agentic-engineering/) ең қарапайымы: код жаза да, іске қоса да алатын агенттермен бағдарламалық жасақтама құру. «Vibe coding» деген сөзді ол тексерілмей қалған прототип нәтижесіне ғана қалдырады ([00-модуль](/kk/learn/the-tweet/)).

Жұмыстың өзі жылжыды. Сен кодты теріп отырған жоқсың, бірақ оны елемей де отырған жоқсың. Сен спецификацияны жазасың, қоршауды таңдайсың, қақпаны құрасың, diff-ті оқисың және өзің ұйықтап жатқанда машинаға неге рұқсат бар екенін шешесің. Бұл шешімдер автоматтандырылмайды, себебі әрқайсысы — нақты дүниедегі салдар туралы, ал агент дәл соны көрмейді.

Енді нені құрасың:

- **Өзің апта сайын қолданатын нәрсе.** Адам тек өзіне керек нәрсені ғана күтіп ұстайды.
- **Қайталауға келетін қақпа.** Қолмен істейтін тексеруіңді агент іске қоса алатын скриптке айналдыр. Бұл — айдағы ең пайдалы сағат.
- **Шағын бағалау жиыны.** Сәтсіз аяқталған 10–20 нақты тапсырманы сақтап қой да, `CLAUDE.md` файлын, skill-ді немесе модельді өзгерткен сайын қайта жүргіз. Болжаудан осылай құтыласың.

Әрі қарай оқуға: Simon Willison жазған [Agentic Engineering Patterns](https://simonwillison.net/guides/agentic-engineering-patterns/), ал агентті жүргізіп қана қоймай, өзің құрғың келсе — [12-Factor Agents](https://github.com/humanlayer/12-factor-agents).
