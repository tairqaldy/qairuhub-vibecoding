## Агент жұмыс біткендей көрінген жерде тоқтайды

Anthropic-тің Claude Code нұсқаулығы «Give Claude a way to verify its work» (Claude-қа өз жұмысын тексеретін жол бер) деген бөлімнен басталады — жоспарлаудан да, контексттен де бұрын, беттің ең басында ([code.claude.com/docs](https://code.claude.com/docs/en/best-practices)).

Агентке «бітті» деп шешу үшін сигнал керек. Сигнал бермесең, қолда бары біреу-ақ: *бітіп қалған сияқты*. Сонда тест жиынтығының рөлін сен атқарасың: шертіп шығасың, бұзылған жерін табасың, агентке қайта көшіріп бересің. Әр мүмкіндікте, жобаның соңына дейін.

Әзірлеушілер ең жиі шағымданатыны — қате жауаптар емес. Дұрысқа жақындары.

## Тексеріс дегеніміз — «өтті» не «өтпеді» деп қайтаратын кез келген нәрсе

Бастау үшін тестілеу құралдары керек емес. Тексеріс — агент іске қоса алатын, «иә» не «жоқ» деп қайтатын кез келген нәрсе. Claude Code нұсқаулығы әдеттегілерін тізеді: тест жиынтығы, build пәрменінің шығу коды, линтер, нәтижеңді эталон үлгімен салыстыратын шағын скрипт, дизайнмен салыстырылатын браузер скриншоты.

Агентті тексеріске бағындырудың төрт жолы бар, баптау күрделілігі бойынша:

1. **Промптта сұра.** «`npm test` пәрменін орында да, ол өткенше жалғастыра бер. Нәтижесін көрсет.» Тегін, әрі көбіне жұмыс істейді.
2. **`/goal <condition>`.** Claude Code әр қадамнан кейін сенің шартыңды қайта тексеретін бөлек шағын модельді іске қосады.
3. **Stop hook.** Пәрменің нөлмен аяқталмайынша қадамды бітіруге жібермейтін скрипт. Қатарынан сегіз рет бөгегеннен кейін Claude Code оны аттап өтеді — бұл темір тор емес, күшті нұсқау.
4. **Тексеруші субагент** — жалғыз міндеті нәтижені теріске шығаруға тырысу болатын таза модель.

Сол беттегі екі ереже. Дәлел сұра — пәрмен мен оның нәтижесін, жай мәлімдемені емес. Тексере алмасаң, шығарма.

<Callout type="warn" title="Агент саған өтірік айтып тұрған жоқ">
«All tests pass» деген сөз әрі шын, әрі пайдасыз болуы мүмкін. Тесттер кодтан кейін, сол кодтың өзіне қарап, код не істесе соны сипаттап жазылған болуы мүмкін. Бүкіл модуль дәл осы ақауға қарсы құрылған.
</Callout>

Бұл — бір жылдан кейінгі күйің, бастағандағы күйің емес. Тестің нөл болса, ең жоғарыдан бір тест жаз: өнімің сол үшін ғана бар болатын жалғыз жол. QAIRU Event Sign-up үшін бұл — *бетті ашу, атын және поштасын толтыру, орын брондау түймесін басу, растауды көру*.

Содан кейін төменге қарай жылж, ал нені тестілеуді қателердің өзі таңдасын. Бірдеңе бұзылған сайын сол қате түзетуге айналмай тұрып модульдік тестке айналады. Anthropic-тің [қатені түзету үлгісі](https://code.claude.com/docs/en/best-practices) — дәл осы: симптомды, ықтимал орнын және «түзелді» дегеннің не екенін сипатта, соны қайталайтын құлайтын тест сұра, сосын ғана түзетуді сұра. Сонда жиынтығың ойдан шығарылған емес, нағыз ақаулардан құралады.

## Алдымен құлайтын тест жаз, содан кейін ғана код жаздыр

Red/green TDD адамдарға қарағанда агенттерге жақсырақ жарайды. Simon Willison-ның бір жолдық нұсқасы: құрастыру промптының соңына «Use red/green TDD» деп қос. Агент тестті жазады, құлағанын көреді, сосын өткенше жүзеге асырады ([Agentic Engineering Patterns](https://simonwillison.net/guides/agentic-engineering-patterns/red-green-tdd/)).

Қызыл қадам — адамдар аттап кететін, бірақ бүкіл құндылықты көтеріп тұрған қадам. Құлағанын көрмеген тест дұрыс емес себептен өтіп жүрген болуы мүмкін: ештеңені тексермейтін шығар, немесе мүмкіндікті өшірсең де өте беретін шығар. Алдымен қызыл көру — тесттің өзі тексеретін мінез-құлыққа жалғанғанының дәлелі.

Бұл агентке неге жақсы жарайтынының төрт себебі:

- **Цикл сенсіз-ақ тұйықталады.** Агент тестті өзі іске қосады, қатені өзі оқиды, өзі жөндейді. Бірінші әрекет пен екіншісінің арасында сен тұрмайсың.
- **Жұмыстың шекарасын белгілейді.** Red/green әрі жұмыс істемейтін кодтан, *әрі* сұралмаған артық кодтан қорғайды. Тапсырманың шеті — тест.
- **Сеанстан ұзақ жасайды.** Келесі сеанс бұл сеанс туралы ештеңе білмей басталады. Тест біледі.
- **Агент сен нені өлшесең, соны жақсартады.** Anthropic он алты параллель Claude данасымен C компиляторын жазды; сабағы мынау: агент тесттер айқындаған мәселені ғана шешеді ([C компиляторын жасау](https://www.anthropic.com/engineering/building-c-compiler)). Күшті тест — дұрыс өнім. Әлсіз тест — сенімді түрде қате өнім.

## Ең маңызды жол үшін бір end-to-end тест

Модульдік тесттер функцияларды тексереді. Өнімнің өзін тек end-to-end тест тексереді. Playwright нағыз браузерді сенің қолданбаң арқылы жүргізеді — Anthropic ұзақ жұмыс істейтін harness-те бағалаушы агентке дәл осы құралды береді ([harness дизайны, 2026 ж. 24 наурыз](https://www.anthropic.com/engineering/harness-design-long-running-apps); ұзақ жұмыстар — [15-модуль](/kk/learn/overnight-builds/)).

Бір рет баптап ал:

<Terminal title="bash">
```bash
npm init playwright@latest
# choose TypeScript, put the tests in ./e2e, let it install the browsers
npx playwright test
```
</Terminal>

QAIRU Event Sign-up үшін тесттің бәрі — осы:

```ts
// e2e/reserve-seat.spec.ts
import { test, expect } from '@playwright/test';

test('a visitor can reserve a seat and sees a confirmation', async ({ page }) => {
  await page.goto('http://localhost:3000/');
  await expect(page.getByRole('heading', { name: 'QAIRU Meetup' })).toBeVisible();

  await page.getByLabel('Name').fill('Aiganym');
  await page.getByLabel('Email').fill('aiganym@example.kz');
  await page.getByRole('button', { name: 'Reserve a seat' }).click();

  await expect(page.getByText('Seat reserved')).toBeVisible();
});
```

Дауыстап оқы: бұл — адамның істейтін әрекеті. Сондықтан ол адам сүрінетін жерде құлайды, функцияның қолтаңбасы өзгергенде емес. Элементтерді CSS класы бойынша емес, көрінетін рөлі мен белгісі бойынша сұрайды — стильді ауыстырсаң бұзылмайды, түймені алып тастасаң бұзылады.

`AGENTS.md` файлың ([6-модуль](/kk/learn/context-ssot/)) E2E пәрменін уәде еткен. Енді ол пәрмен бар, сол жолды шындыққа айналдыр — агент өзі көрмеген пәрменді болжай алмайды:

```markdown
## Commands
- E2E: `npx playwright test` (needs the dev server running on port 3000)
```

## Агент әкеліп берген diff-ті оқу

Бұл — ЖИ нашар код жазады деген сөз емес. Бұл — *тексерілмеген* ЖИ коды репозиторийге не істейтіні туралы. Мүмкіндік қосуды сұрасаң, агент төрт рет жазылған функцияның бесінші көшірмесін жаза береді: оған жазу арзан, ал іздеу контекст шығындайды ([2-модуль](/kk/learn/ai-in-plain-language/)). Бұл қарызды ешкім әдейі жинамаған — жай ғана diff-ті бірде-бір адам оқымаған.

<Deeper title="Бұл сандарға қаншалық сенуге болады">
GitClear код сапасына арналған құрал сатады, әрі зерттеу корреляциялық — бақылау тобы жоқ. «Жылжытылған жолдар» көрсеткіші де агент функцияны орнында қайта жазғанда рефакторингті кем санауы мүмкін. Басқа компанияның зерттеуі — [CodeRabbit](https://www.coderabbit.ai/newsroom/state-of-ai-vs-human-code-generation-report) (2025 ж. 17 желтоқсан, 470 ашық бастапқы кодты pull request) — ЖИ бірге жазған pull request-терде мәселе шамамен 1,7 есе көп екенін тапты: әр PR-ға 10,83 және 6,45; логикалық қателер 1,75 есе жиі. Адам жазған PR-ларда емле қателері 1,76 есе, тестілеуге қолайсыздық 1,32 есе көп. Мұнда таза жақ жоқ. Бәрін өлшем емес, бағыт деп қабылда.
</Deeper>

ЖИ жазған diff-тен нені іздеу керек — бес нәрсе, дәл мына ретпен.

1. **Сен сұраған нәрсені істей ме?** «Орынды көрінеді ме» емес — талапты орындай ма. Орындалмағанын атап айт.
2. **Мүмкіндік бұзылса, тесттер құлар ма еді?** Мүмкіндікті ойша өшір де, қай тест қызылға айналатынын сұра. Бірде-біреуі болмаса — тесттер тек әшекей.
3. **Бірдеңе үнсіз жұтылып кетті ме?** Бос `catch`, жетіспейтін жағдайды жасыратын әдепкі мән, құлауды үнсіздікке айналдыратын `try`. Бұл ақау жұмыс ортасына (production) жетеді және журналда көрінбейді.
4. **Бұл код бұрыннан бар ма?** Жоғарыдағы сандардағы ең айқын сигнал — қайталану, әрі ұстауға ең оңайы: жай ғана сұрау керек.
5. **Сен сұрамаған не өзгерді?** Тапсырма шегінен шығу агент diff-інде жиі кездеседі, тәуекел сонда жасырынады.

Енгізілген деректерді тексеру, кіруді растау және кодтағы құпия деректер де осы тізімге кіреді; қалғаны — [11-модуль](/kk/learn/security/).

5. Қайталану: мұнда осы репозиторийдің басқа жерінде әлдеқашан бар код бар ма?

## Екінші агент оны бұзып көрсін

Жоғарыдағы үлгінің аты бар: Anthropic-тің **evaluator-optimizer** циклі. Бір модель жасайды, екіншісі нақты өлшемдер бойынша сынайды, сыншы риза болғанша шеңбер қайталанады ([2024 ж. 19 желтоқсан](https://www.anthropic.com/engineering/building-effective-agents)).

Агенттер өз жұмысын тым жомарт бағалайды, сондықтан бағалаушы бөлек ұсталады әрі кодты оқудың орнына жұмыс істеп тұрған қолданбаны өзі басқарады. Күнделікті түрі — тексеруші субагент: ештеңені өткізбей тұрып толық тест жиынтығын іске қосуы міндет ([көп агентті жүйелер, 2026 жылғы қаңтар](https://claude.com/blog/building-multi-agent-systems-when-and-how-to-use-them); оларды қалай құру — [14-модуль](/kk/learn/multi-agent/)).

Бүгін саған бұл инфрақұрылымның ешқайсысы керек емес. `/clear` пәрменін орында да, шолу промптын қой. Таза контекст жақсырақ шолады, себебі жаңа ғана жазған кодына бауыр басқан жері жоқ.

Осы модуль сүйенген red/green нұсқаулығының авторы өз ережесін енді ұстанбайды.
