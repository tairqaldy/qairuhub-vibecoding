<Lead>
Агент кодты сен оқып үлгергеннен жылдам өзгертеді. Бір жерін қате істейтіні сөзсіз. Сол қате саған қаншаға түсетінін git шешеді — жауабы *бір пәрмен*.
</Lead>

Нұсқаларды басқару жүйесі жоқ болса, агентті қосқан сайын артқа жол жабылады. Үш промпт бұрын не өзгергені жайлы машинамен таласып жүргенде, жұмыс істеп тұрған нұсқадан айырыласың.

Жүйе бар болса, сәтсіз әрекет уайымға тұрмайды: тастай сал, промптты жақсырақ жаз, қайта қос.

## Бүкіл жүйені бес сөз ұстап тұр

| Сөз | Не екені |
|---|---|
| **Репозиторий (repo)** | Жобаңның қалтасы мен оның толық тарихы, жасырын `.git` қалтасында. Интернетсіз де жүреді, аккаунт та керек емес. |
| **Commit** | Бір түсірілім: әр файлдың сол сәттегі күйі және өзгерісті түсіндіретін хабар. |
| **Тармақ (branch)** | Жұмыстың қатар жүретін желісі. Сен біріктірмейінше `main` бұрынғы қалпында қалады. |
| **Remote** | Репозиторийдің серверде тұрған көшірмесі, әдетте GitHub. Оған push жасайсың, одан pull жасайсың. |
| **Pull request** | Бір тармақты екіншісіне біріктіру ұсынысы. Қай жолдар өзгергенін көрсетеді, алдымен тексерулерді жүргізеді. |

Күнделікті жұмыстың дені бес пәрменге сияды.

<Terminal title="bash">
```bash
cd qairu-signup
git init
git status
git add .
git commit -m "chore: first working version"
git log --oneline
```
</Terminal>

Ең жиі орындайтының — `git status`. Ол соңғы түсірілімнен бері не өзгергенін және келесісіне не кіретінін айтады. `git add` файлдарды дайындайды, `git commit` түсірілімді жасайды, `git log --oneline` тарихты оқып береді.

## Ноутбуктан интернеттегі мекенжайға дейін

GitHub-та бос репозиторий жаса — README де, лицензия да керек емес, файлдарың бұрыннан бар. URL-ді көшіріп ал.

<Terminal title="bash">
```bash
git remote add origin https://github.com/YOUR-NAME/qairu-signup.git
git branch -M main
git push -u origin main
```
</Terminal>

Алғашқы push-тан кейін жай ғана `git push` жетеді. Кері бағыты — `git pull`: ол қашықтағы репозиторийде бар, сенде жоқ commit-терді алып түседі. Оны жұмысты бастар алдында орында, файлды өзгертіп қойғаннан кейін емес. Енді тарихың екі жерде тұр, ал хостинг сол URL-ден deploy жасай алады ([12-модуль](/kk/learn/deploy/)).

## .gitignore файлдарды репозиторийден тыс ұстайды

`.gitignore` файлы git-ке қай жолдарды көрмегенсуі керегін айтады. Кәдімгі жобаға төрт жол жетеді:

<Terminal title=".gitignore">
```text
.env
node_modules/
dist/
.claude/worktrees/
```
</Terminal>

`.env` ішінде API кілттерің жатыр ([8-модуль](/kk/learn/local-build/)) — ол ешқашан commit-ке түспеуге тиіс. `node_modules/` қайта орнатылады әрі орасан үлкен, `dist/` автоматты жасалады, ал `.claude/worktrees/` ішінде Claude Code-тың қатарлас жұмыс көшірмелері тұрады.

<Callout type="danger" title="Commit-ке түскен құпия дерек кері шықпайды">
Кілтті файлдан өшіріп, қайта commit жасау оны жоймайды. Бұрынғы әр түсірілімде ол әлі тұр, ал push жасаған болсаң — бөтен серверде де тұр. Commit-ке түскен кілтті жария деп есепте: жаңасын ал да, ескісінің күшін жой. `.gitignore` файлын бірінші commit-тен бұрын жаз.
</Callout>

## Түнгі екіде де оқи алатын commit хабарларын жаз

Commit хабарының бір ғана міндеті бар: оны оқыған адам екі секундта «кері қайтаратын commit осы ма» дегенді шеше алсын. Conventional commits оған пішін береді — тип, қажет болса scope, бір жол сипаттама.

<Terminal title="git log --oneline" copy={false}>
```text
feat(signup): store reservations in D1
fix(form): reject an empty email instead of saving it
test(form): cover the duplicate-email case
refactor(api): split the handler into two files
docs(readme): how to run the dev server
chore(deps): bump astro
```
</Terminal>

Алты тип күнделікті жағдайдың бәрін дерлік қамтиды: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`. Бірінші жолды шолып өтерліктей қысқа ұста, ал *неге* екенін хабардың негізгі бөлігіне жаз. Сонда `git log --oneline` жолма-жол кері қайтара алатын журналға айналады.

Anthropic-тің [ұзақ жұмыс істейтін агенттердің жұмыс ортасы туралы мақаласы](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) агентке де осы әдетті береді: әр аяқталған жұмыс бөлігінен кейін commit жасат — сонда кейінгі сеанс жұмыс істеген күйге жолын табады.

## Кері қайтарудың үш түрі бар, push-тан кейін қауіпсізі — біреуі ғана

Жағдайға сәйкес пәрменді тап.

| Не болды | Нені орындайсың |
|---|---|
| Агент файлдарды өзгертті, ештеңе commit-ке түспеген, ескі күйді қайтарғың келеді | Бақылаудағы файлдар үшін `git restore .` |
| Оның үстіне керексіз жаңа файлдар жасап тастады | `git clean -fd` — бақылауда жоқ файлдар мен қалталарды жояды |
| Былықты жоғалтпай, бір шетке қойғың келеді | `git stash`, кері әкелу үшін `git stash pop` |
| Соңғы commit нашар шықты, ал сен оны push жасаған **жоқсың** | `git reset --hard HEAD~1` — commit жойылады |
| Нашар commit push жасалып немесе таралып кеткен | `git revert HEAD` — жаңа commit оны кері қайтарады |

`git clean -fd` бақылауда жоқ файлдарды біржола жояды — git оларды ешқашан жазып алмаған, қалпына келтіретін ештеңе жоқ. `-x` қоспасаң, елемеу тізіміндегі файлдар аман қалады, демек `.env` қауіпсіз. Алдымен `git clean -nd` орында: ол ештеңеге тимей, нені жоятынын тізіп береді.

<Compare a="git reset --hard" b="git revert">
<div slot="a">
Тармақты артқа шегіндіріп, commit-ті жояды. Жұмыс әлі тек ноутбугыңда тұрса — тамаша. Push жасалғаннан кейін бұл — тұзақ: келесі push `--force` талап етеді, ал басқалар pull жасап үлгерген тармақты күшпен басып жазу — топтың еңбегі жоғалатын жағдай.
</div>
<div slot="b">
Нашар commit-тің дәл кері көшірмесі болатын жаңа commit қосады. Ештеңе жойылмайды, ал журнал қатені де, оның кері қайтарылуын да көрсетіп тұрады. Push-қа дейін де, одан кейін де қауіпсіз. Әдепкі таңдауың осы.
</div>
</Compare>

Revert тек соңғы commit-пен емес, кез келгенімен жұмыс істейді: `git log --oneline` ішінен қысқа hash-ты көшір де, `git revert a1b2c3d` орында. Оның үстіне кейінгі жұмыс салынған болса, git болжамайды: тоқтайды да, қайшылықты көрсетеді.

## Checkpoint — жергілікті кері қайтару. Git — тұрақты кері қайтару.

Claude Code-тың өз сақтандыру торы бар: әр промпт checkpoint жасайды, ал файлдар әр өңдеуден бұрын түсіріліп алынады. Бос енгізу жолында `Esc Esc` немесе `/rewind` кодты да, әңгімені де — не соның біреуін ғана — қалпына келтіреді. «Соңғы өңдеу қате болды» дегенде ол кез келген git пәрменінен озады.

[Checkpoint құжаттамасы](https://code.claude.com/docs/en/checkpointing) оның git орнын баспайтынын ашық айтады. Әр сеанста тек соңғы 100 checkpoint сақталады, ал сеанс соңғысын сақтағаннан кейін шамамен 30 күн өтсе, тазаланады. Олар `rm`, `mv`, `cp` секілді Bash пәрмендерінің өзгерістерін, субагент өңдеулерінің көпшілігін, сеанстан тыс түзетулерді, символдық және қатты сілтемедегі файлдарды бақыламайды.

<Callout type="warn" title="Ең қатерлі жағдай — дәл қамтылмағаны">
Ең көп зиян келтіретіні — агент терминалға шығып кеткен жағдай: қалтаны көшіреді, каталогты жояды, файлдарды скриптпен қайта жасайды. Checkpoint дәл осыны қамтымайды. Ал commit қамтиды, өйткені ол файлды кім, қалай өзгерткеніне қарамайды.
</Callout>

## Enter баспай тұрып commit жаса

**Бірден көп файлға тиетін промпт жібермес бұрын `git status` «working tree clean» деп тұруға тиіс.** Содан кейін өз тексерісінен өткен әр жұмыс бөлігін келесісін бастамай тұрып commit жаса.

Мақұлдаудан шаршау — теория емес, өлшенген дүние. Әр сұрауға дерлік «иә» десең, «рұқсат беру» түймесі шешім болудан қалады. Ал сенің атыңнан «иә» дейтін классификатор шектен шыққан әрекеттердің 17%-ын өткізіп жібереді ([7-модуль](/kk/learn/the-agent/)). Агентті қоспай тұрып жасалған commit ешқашан шаршамайды.

Шағын commit-тер тексеруді де арзандатады. Қырық жолдық diff-ті шынымен оқып шығасың. Екі мың жолдық diff-ті сырғытып өтіп, мақұлдай саласың — бұл тексеру емес, жай ғана қол қою.

<Prompt title="Агентіңе арналған git ережелері" where="Claude Code · AGENTS.md or the first message of a session">
```text
Осы репозиторийдің git ережелері:
- Тапсырманы бастамас бұрын `git status` орында. Жұмыс каталогы таза болмаса, тоқта да, маған айт.
- feat/<қысқа-атау> немесе fix/<қысқа-атау> деп аталған тармақта жұмыс істе.
  main тармағына ешқашан тікелей commit жасама.
- Өз тексерісінен өткен әр жұмыс бөлігінен кейін commit жаса. Бір commit — бір логикалық өзгеріс.
- Хабар пішімі: type(scope): не өзгергені.
  Типтері: feat, fix, docs, refactor, test, chore.
- `git push --force` ешқашан орындама. Push жасалып қойған commit-ке ешқашан amend жасама.
  .env файлын да, .gitignore тізіміндегі ештеңені де ешқашан қоспа.
- Тапсырма біткенде маған осы тармақтың `git log --oneline` тізімін және main-ге қатысты
  `git diff --stat` нәтижесін көрсет, содан соң pull request ашпай тұрып, менің тексеруімді күт.
```
</Prompt>

## Әр тапсырмаға бір тармақ, әр тексеруге бір pull request

Тармақты агент бастағаннан кейін емес, бұрын жаса: `git checkout -b feat/seat-counter`. Іс сәтсіз біткенде тармақты өшіресің де, `main` ештеңе білмей қалады. Сәтті біткенде pull request аш — жалғыз өзің істесең де. Diff-ті файлдап оқитын жерің де, тексерулер жүретін жер де, өзі жазбаған кодты жаңа агент сеансы қарап шығатын жер де — сол.

Simon Willison-ның ережесі: өзің оқып шықпаған код бар pull request ашпа. Оларды шағын ұста, жұмыс істейтінінің дәлелін қоса тіркеп жібер. Оның [анти-паттерндер](https://simonwillison.net/guides/agentic-engineering-patterns/anti-patterns/) жинағы мен [кодтайтын агенттермен git-ті қолдану](https://simonwillison.net/guides/agentic-engineering-patterns/using-git-with-coding-agents/) тарауы — осыдан кейін оқитының.

<Myth
  n={9}
  myth="Агенттер мұншама жақсы болған соң, кодты түсінудің қажеті қалмады."
  source="Simon Willison · anti-patterns"
  href="https://simonwillison.net/guides/agentic-engineering-patterns/anti-patterns/"
>
Оқи алмайтын нәрсеңді қалпына келтіре де алмайсың. Осы беттегі әр қимыл бағалаудан басталады: қай өзгеріс тапсырманікі еді, қатені қай commit әкелді, мына diff — түзету ме, әлде екінші қате ме. Git дәлел береді; оны оқу — сенің ісің. Сен түсінбейтін код жазатын агент жұмысты жойған жоқ — бірдеңе бұзылып қойған сәтке жылжытты.
</Myth>

<Deeper title="Қатар екі агент қосқанда: әрқайсысына бір worktree">
Worktree — өз тармағында тұратын, бірақ сол репозиторийдің тарихын бөлісетін екінші жұмыс каталогы: `git worktree add ../qairu-feature-a -b feature-a`, оған қоса `git worktree list` және `git worktree remove`. Сонда екі агент сеансы бір-бірінің файлдарын басып жазбайды. Claude Code мұны `claude --worktree feature-auth` пәрменіне сыйдырған: ол `worktree-feature-auth` тармағында `.claude/worktrees/feature-auth/` каталогын жасайды, шыққанда таза worktree-лерді өшіреді. Бұл — жаңа көшірме, сондықтан тәуелділіктерді қайта орнатасың, ал `.env` секілді елемеу тізіміндегі файлдар бірге көшпейді ([worktree құжаттамасы](https://code.claude.com/docs/en/worktrees)). Қатар екі сеансты қашан қосу керегі — [14-модуль](/kk/learn/multi-agent/).
</Deeper>

<Prompt title="Агент жолдан шығып кеткенде" where="Claude Code · before you undo anything">
```text
Тоқта. Енді бірде-бір файлды өзгертпе.

1. `git status` және `git diff --stat` орында да, шыққан нәтижені сол күйінде көрсет.
2. Өзгерген әр файл туралы бір жолмен айт: ол мен сұраған тапсырманың бөлігі ме,
   әлде сен өз бетіңмен өзгертуді шешкен нәрсе ме.
3. Commit жасама, git checkout, git restore, git reset, git clean пәрмендерін де орындама.
   Нені лақтырып тастайтынын мен шешемін.
```
</Prompt>

<Callout type="live" title="Мынаны сахнада көрсет">
Керексіз бір commit жаса да, залдың көз алдында `git reset --hard HEAD~1` орында, сосын `git log` ішінде ол commit жай ғана жоқ болып кеткенін көрсет. Содан соң тағы біреуін жасап, `git revert HEAD` орында да, журналда екі жазба да тұрғанын көрсет. «Жойылды» мен «кері қайтарылды» айырмасын көрген адам commit жасай бастайды.
</Callout>

<ProjectStep n={9} title="QAIRU Event Sign-up жобасын git-ке сал да, әдейі бұз">
Бес қимыл. Соңғы екеуін курс бойы қайталайсың.

1. Жоба қалтасында: `git init`. 8-модульде жазған `.gitignore` файлыңды аш та, `dist/` және `.claude/worktrees/` қос — бәрінен бұрын осыны істе.
2. `git add .`, содан соң `git commit -m "chore: first working version"`. Тексер: `git status` таза дейді, `git log --oneline` бір жол көрсетеді.
3. GitHub-та бос репозиторий жаса, сосын ол берген URL-мен `git remote add origin`, одан кейін `git branch -M main` және `git push -u origin main`. Бетті жаңарт — енді жобаңның мекенжайы бар.
4. Жаттығу. `git checkout -b feat/seat-counter` орында, содан соң агентіңнен тіркелу бетіне «12 орын қалды» дейтін есептегіш қосуын сұра. Бітірген соң: `git add .` және `git commit -m "feat(signup): seats-left counter"`.
5. Енді оны кері қайтар: `git revert HEAD`. Бетті қайта жүкте — есептегіш жоқ, ал `git log --oneline` өзгерісті де, оның кері қайтарылуын да көрсетіп тұр. `git checkout main` пәрменімен аяқта. Жаман күні керек болатын қимыл — дәл осы.
</ProjectStep>
