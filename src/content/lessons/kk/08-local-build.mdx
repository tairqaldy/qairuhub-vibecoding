## Терминал — сынақ емес, жай ғана мәтін жолағы

Тінтуірмен баспай, пәрмен тересің. Бұл — дәл, скриптке жазуға келетін әдіс, әрі кез келген компьютерде бірдей.

Дәл қазір бұл маңызды, себебі Claude Code соның ішінде жұмыс істейді. Ол орындаған әр пәрменді де, шыққан әр жолды да экранға шығарады. Соны оқи алсаң, неге рұқсат беріп отырғаныңды өзің бағалайсың.

Enter баспайынша терминал ештеңе істемейді. Ал бірдеңе сәтсіз аяқталғанда, экрандағы қате мәтіні — бөлмедегі ең пайдалы нәрсе.

<Callout type="tip" title="Сен қазірдің өзінде соның ішіндесің">
Claude Code — терминал бағдарламасы. Сеанс ішінде жол басындағы `!` таңбасы shell пәрменін орындап, нәтижесін әңгімеге қосады, ал `@` файл жолын автоматты толтырады ([интерактивті режим](https://code.claude.com/docs/en/interactive-mode)). Төмендегі пәрмендер — бөлек дағды емес, дәл сол дағдының өзі.
</Callout>

## Әр пәрмен бір жерде орындалады

Терминал әрқашан бір қалтаның ішінде тұрады — ол ағымдағы каталог, пәрмендердің көбі соның ішінде жұмыс істейді. «Пәрмен ештеңе істемеді», «файл табылмады» дегеннің астары көбіне біреу: сен басқа жерде тұр екенсің.

Жол (path) — қалтаның немесе файлдың мекенжайы. macOS, Linux, WSL және Git Bash ішінде бөліктерді `/` ажыратады, таза Windows-та `\`. Claude Code файлы macOS пен Linux-та `~/.local/bin/claude` жолында, Windows-та `%USERPROFILE%\.local\bin\claude.exe` жолында жатады ([орнату құжаттамасы](https://code.claude.com/docs/en/setup)). `~` — үй қалтаң. `.` — осы жер. `..` — бір деңгей жоғары.

Бір ереже: агентті іске қоспай тұрып, әрқашан `cd` арқылы жоба қалтаңның ішіне кір. Оның орнына Desktop-та қоссаң, қалған жобаларың түгел агенттің жұмыс каталогында тұрады. Бір жоба — бір қалта — бір сеанс.

## Он пәрмен оқулықтардың бәрін дерлік қамтиды

| Пәрмен | Не істейді |
|---|---|
| `pwd` | қай жерде тұрғаныңды шығарады |
| `ls` | осы қалтада не бар екенін тізеді |
| `cd name` | қалтаның ішіне кіреді |
| `cd ..` | бір деңгей жоғары шығады |
| `cat file` | файлды экранға шығарады |
| `mkdir name` | қалта жасайды |
| `touch name` | бос файл жасайды |
| `cp a b` | a-ны b-ға көшіреді |
| `mv a b` | жылжытады немесе атын өзгертеді |
| `rm name` | жояды |

Windows-та бұлар Git Bash ішінде жазылған күйінде жұмыс істейді. PowerShell көбіне жауап береді, әдетте тек `touch` жетіспейді. CMD жауап бермейді.

Кестедегі кез келген пәрменнен көрі пайдалы екі перне бар. Жоғары көрсеткі соңғы терген жолыңды қайтарады. Tab жартылай терілген атауды өзі толтырады — нағыз терминалда.

<Terminal title="bash">

```bash
pwd
cd qairu-event
ls
cat package.json
cp .env.example .env
```

</Terminal>

<Callout type="danger" title="rm — қоқыс себеті емес">
`rm` бірден жояды: растау да сұрамайды, кері қайтару да жоқ. Агенттің қорғау торы бұған жетпейді: Claude Code-тың [checkpoint жүйесі](https://code.claude.com/docs/en/checkpointing) `rm`, `mv`, `cp` сияқты Bash пәрмендері өзгерткен файлдарды да, deploy мен push сияқты сырттағы салдарларды да қадағаламайды. Нағыз кері қайтару — git-тегі commit ([9-модуль](/kk/learn/git-and-github/)).
</Callout>

Саған зиян келтіре алмайтын терминалда өзің істеп көр.

## node_modules — сенің кодың емес

Пакет менеджері жобаңа керек кітапханаларды, олардың өзіне керек кітапханаларды жүктеп алады да, дәл сол нұсқаларды lock файлына жазып қояды — сонда кез келген компьютер тап сол нәрсені орнатады. JavaScript үшін бұл npm, pnpm немесе bun; Python үшін pip немесе uv.

- **`package.json`** — сенің не сұрағаның: тәуелділіктер және аты берілген пәрмендер (`dev`, `build`, `test`).
- **lock файлы** — шын мәнінде не алғаның, дәл нұсқасына дейін.
- **`node_modules/`** — жүктеп алынған кодтың өзі. Жүздеген қалта. Оны ешкім оқымайды.
- **`npm install`** — алғашқы екеуін үшіншісіне айналдыратын пәрмен.

`node_modules` git-ке ешқашан түспейді: ол орасан үлкен, әрі бір пәрменмен кез келген жерде қайта құрылады. Claude Code-тың git worktree-і — таза көшірме, онда `node_modules` жоқ, оны қайта орнатасың ([worktree туралы](https://code.claude.com/docs/en/worktrees)). Агент сол қалтаны commit-ке қосуды ұсынса, келіспе.

## localhost — сенің үйің, интернет емес

`npm run dev` пәрмені `package.json` ішінен `dev` жолын тауып, орындайды. Сөйтіп dev сервері қосылады: өз компьютеріңдегі шағын веб-сервер. Ол жобаңды браузеріңе береді, файлды сақтаған сайын бетті қайта жүктейді.

Ол мекенжай шығарады, әдетте `http://localhost:3000`. Екінші жоба немесе екінші сервер басқа нөмір шығарады, сондықтан жаттап алмай, өз экраныңнан оқы.

Үш әдет:

1. Dev серверіне жеке терминал қойындысын бер. Ол жұмыс істеп, жазып тұра береді; қатып қалған жоқ.
2. `Ctrl+C` оны тоқтатады. «Port already in use» деген хабар әрдайым дерлік екінші серверді қосып жібергеніңді білдіреді.
3. Қатесі жоқ бос бет те — ілгерілеу. «Бұзылды» демей тұрып, терминалдағы нәтижені де, браузер консолін де оқы. Екеуін де агентке көшіріп жібер.

## .env кілттерді сақтайды, әрі ноутбугіңнен ешқашан шықпайды

Орта айнымалылары — кодтың сыртында тұратын, бағдарлама іске қосылғанда соған берілетін аты бар мәндер: API кілттері, дерекқор мекенжайы, `NODE_ENV=production`. Олар құпия деректерді репозиторийден тыс ұстайды, әрі дәл сол код ноутбугіңде бір түрлі, серверде екінші түрлі жұмыс істей алады. Компьютеріңде олар `.gitignore` тізіміндегі `.env` файлында тұрады. Хостингте оларды басқару панеліне қоясың.

Дұрыс рет біреу ғана, ерекше жағдайы жоқ:

Кілт енді репозиторий тарихында тұр. Файлды өшіру оны ол жерден кетірмейді. Жалғыз шешім — сол кілтті жарамсыз етіп, жаңасын алу.

Кілттердің frontend-те де орны жоқ: ол пайдаланушының құрылғысында жұмыс істейді, оны кез келген адам браузердің әзірлеуші құралдарынан оқиды. Олардың орны — backend немесе хостингтің басқару панелі ([11-модуль](/kk/learn/security/)).

<Deeper title="Агентке .env файлын оқыма деп айтсам, жеткілікті ме?">
Айтуға болады, айту керек те — бірақ бұл құлып емес. [`.claude/settings.json`](https://code.claude.com/docs/en/settings) ішіндегі `"deny": ["Read(./.env)", "Read(./.env.*)", "Read(./secrets/**)"]` сияқты ереже Read құралын да, Bash ішіндегі `cat`, `head`, `tail`, `sed` пәрмендерін де бұғаттайды. Бірақ файлды өзі ашатын скриптті тоқтатпайды: Bash ережелері бағдарламаны емес, пәрмен мәтінін салыстырады. [Рұқсаттар туралы құжаттама](https://code.claude.com/docs/en/permissions) мұны ашық жазады — ыңғайлылық үшін, қауіпсіздік шекарасы емес. Нағыз оқшаулауды тек sandbox береді, ал таза Windows-та ол жоқ. Бір рет commit-ке түскен немесе чатқа көшірілген кілтті түгел ауыстыр.
</Deeper>

## «Менің компьютерімде жұмыс істеп тұр» — әзіл емес, диагноз

Бұл сенің компьютеріңде екінші компьютерде жоқ бір нәрсе бар дегені. Әдетте кінәлі болатын бес себеп бар, бесеуін де екі минутта тексересің.

- **Жетіспейтін орта айнымалысы.** `.env` файлың тек сенде бар, басқа ешқайда жоқ. Шешімі: айнымалыларды хостингтің басқару панеліне қос.
- **Commit жасалмаған файл.** Ол жұмыс істеп тұр, себебі файл жобада емес, дискіңде жатыр. Шешімі: `git status`.
- **Орнатылмаған тәуелділіктер.** Екінші компьютерде `package.json` бар, бірақ `node_modules` жоқ. Шешімі: орнату пәрменін орында.
- **Бас әріптер.** Windows үшін `Hero.astro` мен `hero.astro` — бір файл. Deploy серверлерінің көбі Linux-та жұмыс істейді, ал ол үшін бұл — екі бөлек файл, сондықтан компьютеріңде жұмыс істейтін импорт build кезінде құлайды. Шешімі: файл атын әрпін әрпіне келтіріп жаз.
- **Басқа нұсқа.** Ол жақтағы орындалу ортасы сенікінен жаңарақ немесе ескілеу. Claude Code-тың өзі осыны көрсетеді: npm арқылы орнату жолына Node.js 22 немесе одан жаңа нұсқа керек ([орнату құжаттамасы](https://code.claude.com/docs/en/setup)).

Өз компьютеріңде жұмыс істегені — әлі бітті дегені емес. Deploy жасалса — бітті ([12-модуль](/kk/learn/deploy/)).

## Windows-та отырсаң, бұл бөлімді екі рет оқы

Бұл курсты оқитындардың көбі Windows-та отыр. Оқулықтардың көбі Windows-қа жазылмаған. Саған Linux керек емес: Claude Code Windows 10 1809 немесе одан жаңа нұсқасында, кемінде 4 ГБ жадпен, PowerShell немесе CMD ішінде тікелей жұмыс істейді. WSL **міндетті емес** — WSL 2 тек Claude Code-тың sandbox мүмкіндігі керек болса ғана қажет, оны таза Windows қолдамайды ([орнату құжаттамасы](https://code.claude.com/docs/en/setup)).

Сонда да [Git for Windows](https://git-scm.com/downloads/win) орнатып қой. Ол болса, Claude Code Bash құралы үшін Git Bash пайдаланады; болмаса, PowerShell құралына ауысады. 9-модульде git бәрібір керек.

Алдымен қай shell-ге қарап отырғаныңды біл.

| Пәрмен жолындағы жазу | Қай shell | Демек |
|---|---|---|
| `PS C:\Users\you>` | PowerShell | PowerShell үшін жазылған орнату пәрмендерінің орны осы |
| `C:\Users\you>` | CMD | CMD үшін жазылған орнату пәрмендерінің орны осы |
| `you@laptop:~$` | Git Bash немесе WSL | оқулықтардағы macOS/Linux пәрмендері жазылған күйінде жұмыс істейді |

Содан кейін пәрменді қайталай бермей, қатенің өзін оқы.

| Хабар | Шын мәнінде не болды |
|---|---|
| `The token '&&' is not a valid statement separator` | CMD пәрменін PowerShell ішіне көшіріп қойдың |
| `'irm' is not recognized` | PowerShell пәрменін CMD ішіне көшіріп қойдың |
| `'claude' is not recognized` | орнату қалтасы PATH тізімінде жоқ — оны түзе де, **жаңа** терминал аш |
| `Claude Code does not support 32-bit Windows` | PowerShell орнына «PowerShell (x86)» терезесін ашқансың |

Төртеуі де ресми [орнату](https://code.claude.com/docs/en/setup) және [орнату ақауларын жою](https://code.claude.com/docs/en/troubleshoot-install) беттерінен алынған. Ең жиі кездесетіні — PATH. Шешімі мынау; содан кейін жаңа терезе аш, себебі ашық тұрған терминал PATH өзгергенін байқамайды:

<Terminal title="powershell">

```powershell
$currentPath = [Environment]::GetEnvironmentVariable('PATH', 'User')
[Environment]::SetEnvironmentVariable('PATH', "$currentPath;$env:USERPROFILE\.local\bin", 'User')
```

</Terminal>

<Callout type="live" title="Осыны үйретіп отырған адамға">
Shell кестесін тікелей сабақта істе. Ешкім ештеңе орнатпай тұрып, залдағыларға өз пәрмен жолындағы жазуын дауыстап оқытып шық. Осындағы екі минут практика кезіндегі орнату дүрбелеңінің көбін болдырмайды.
</Callout>

## Жобаны агент таныстырып берсін
