<Lead>
Тіркелу бетің жер бетіндегі жалғыз компьютерде тұр: сенікінде. Қақпағын жапсаң — жоқ. Deploy деген — оны ұйықтамайтын машиналарға көшіру және адам тере алатын атау беру. Мына стекте бұл *төрт пәрмен*, үстіне терминалдан істелмейтін бір қадам.
</Lead>

Компьютеріңде жұмыс істеп тұрғаны — бітті дегені емес. Deploy жасалғаны — бітті дегені.

## Хостинг — ешқашан сөнбейтін, біреудің компьютері

Хост — ашық мекенжайы бар, үнемі қосулы тұратын машина. Сен оған файлдарыңды бересің, ол браузер сұрағанда жауап береді.

Қазіргі хостингтер репозиторийіңді бақылап отырады да, әрбір `git push` сайын deploy жасайды: кодты тартып алады, build жасайды, бір-екі минутта жариялайды, әр тармаққа (branch) бөлек preview сілтемесін береді. Ештеңе қолмен жүктеп салынбайды.

## Статикалық па, серверде жасалады ма — қалғанының бәрі соған байланысты

**Статикалық** дегені — сайт бір рет құрастырылады да, жай ғана HTML, CSS және JavaScript тұратын қалтаға айналады; сол қалта дүниежүзіндегі машиналарға көшіріледі. Әр келушіге бөлек ештеңе іске қосылмайды — сондықтан ең арзан, ең жылдам және бұзуға ең қиын нұсқа. Осы сайт — статикалық: `npm run build` бастапқы кодты `dist/` қалтасына айналдырады, ал `dist/` — сайттың *өзі*.

**Серверде жасалатын** сайтта әр сұрауға бағдарлама іске қосылады: сенің кім екеніңді тексереді, дерекқорды оқиды, ақылы API-ге жүгінеді. Бұл код келушінің көзінен тыс жерде орындалады — құпия тұра алатын жалғыз орын да сол. Екі түрі: үнемі жұмыс істеп тұратын бір сервер немесе әр сұрауда оянып, қайта ұйықтайтын шағын серверсіз функциялар (Cloudflare Workers, Vercel Functions).

Мүмкіндігінше көбін статикалық қалдыр, динамикалық бөлікті ең кішкентай функцияға тығып таста. Статикалық бет саған ештеңеге түспейді. Функция әр жүктелген сайын бюджет жейді — [Cloudflare-дің тегін Workers тарифі](https://developers.cloudflare.com/workers/platform/pricing/) күніне 100 000 сұрау және әр шақыруға 10 мс процессор уақытын береді, ал Pages статикалық файлдарға трафик шегін мүлде көрсетпейді.

<Deeper title="Брондалған орын шын мәнінде қайда сақталады">
Тіркелу формасына дерекқор керек. Ақылға қонымды үш тегін нұсқаның әрқайсысында бір «бірақ» бар.

- **Cloudflare D1** (SQLite): күніне 5 млн жол оқу және 100 мың жол жазу, барлығы 5 ГБ. Pages жобаңмен бір аккаунтта, картасыз.
- **Neon** (Postgres): әр жобаға 0,5 ГБ сақтау орны, айына әр жобаға 100 CU-сағат, 5 минуттан кейін міндетті түрде нөлге дейін сөнеді — яғни тыныш тұрған сағаттан кейінгі алғашқы сұрау баяу болады.
- **Supabase** (Postgres және аутентификация): 500 МБ дерекқор, айына 50 000 белсенді пайдаланушы, 2 белсенді жоба — және жоба **бір апта қимылсыз тұрса тоқтатылады**, ал демо воркшоп пен келесі кездесу арасында дәл сонша тұрады.

Дереккөздер: [Cloudflare](https://developers.cloudflare.com/workers/platform/pricing/), [Neon](https://neon.com/pricing), [Supabase](https://supabase.com/pricing).
</Deeper>

## Домен — жалға алынған атау, ал DNS — телефон кітапшасы

Deploy жасалған сәтте-ақ сайттың мекенжайы бар болады — шамамен `qairu-event.pages.dev` сияқты. Жеке домен — сол орынға бағытталған көркемірек атау.

DNS атауды соған жауап беретін машинаның мекенжайына аударады. Домен қосу деген — жазба қосу, әдетте **CNAME**: «бұл атау сол серверді білдіреді». Одан кейін хост `http://` мекенжайын `https://` ететін SSL сертификатын өзі, тегін береді.

DNS жауаптары бүкіл әлемде кэштеледі, сондықтан өзгеріс бәріне бірнеше минуттан бірнеше сағатқа дейін жетеді. Сайт өзіңде ашылып, досыңда ашылмаса — бұл бұзылған deploy емес, кэштегі ескі жазба. Жөндеуге кіріспей тұрып күте тұр.

## Құпиялардың орны — хостта, репозиторийде де, браузерде де емес

Орта айнымалысы — бағдарлама іске қосылғанда оған берілетін, атауы бар мән: API кілті, дерекқор мекенжайы, `NODE_ENV=production`. Ол кодтың сыртында тұрады, сондықтан бірдей код ноутбугыңда бір түрлі, серверде басқаша жұмыс істейді.

Құпия дәл үш жерде тұра алады. Біреуі ғана дұрыс:

- **Ноутбугыңдағы `.env` файлында.** Бірінші commit-ке дейін `.env` файлы `.gitignore` ішіне жазылса — жарайды.
- **Хостың басқару панелінде**, сервердегі кодың оқитын орта айнымалысы ретінде. Production дегеніміз — осы.
- **frontend-те.** Ешқашан. Браузер жүктеп алатын нәрсенің бәрі — ашық дерек: әзірлеуші құралдары оны бірнеше секундта көрсетеді.

Алғашқы deploy-лар дәл бірінші орыннан екіншісіне көшкенде өледі. `.env` файлың ноутбугыңнан шықпайды, сондықтан сен қолмен термейінше, оның ішіндегі ештеңе хостта болмайды. `.env` файлын аш та, кілттерді бірінен соң бірін хостың панеліне қос. Жергілікті жерде істеп, production ортасында қате беретін беттің себебі әдетте біреу: осы екі орынның біреуінде ғана тұрған айнымалы.

[8-модульдегі](/kk/learn/local-build/) `.env` тыйымы көмектеседі, бірақ ол Claude-тың файл құралдарын бұғаттайды, файлды өзі ашатын скриптті емес ([рұқсаттар туралы құжаттама](https://code.claude.com/docs/en/permissions)).

## Әр тармақтың өз URL-і бар — ендеше ешкім көрмейтін жерде бұз

Preview deploy — бір тармақтан құрастырылған, ешқайда тізілмеген өз мекенжайында тұрған сайтыңның толық көшірмесі. Скриншоттың орнына сол сілтемені жібер. Netlify-де preview deploy-лары мүлде есептелмейді — кредитті тек production deploy жейді, сондықтан қателесудің ең арзан орны — preview.

Preview «менің компьютерімде жұмыс істеп тұр ғой» деген классикалық ақауды да ұстайды: хост build-ті Linux жүйесінде жасайды, ал Linux файл атауындағы бас әріпті ажыратады. `header.astro` деп импортталған `Header.astro` ноутбугыңда күні бойы жұмыс істейді, ал build журналында құлайды. Журналды оқы — ол файл атауын айтып тұр.

## Оны жарыққа шығаратын төрт пәрмен және соңындағы бір басу

<Steps>

<Step title="Біреу көрмей тұрып, build жиналатынын дәлелде">
Осы сайттың репозиторийі барлық тексеруін бір скриптке жинаған: аударма, типтер, build, сілтемелер — осы ретпен, бірінші сәтсіздікте тоқтайды.

<Terminal title="bash">

```bash
npm run verify
```

</Terminal>
</Step>

<Step title="Сайттың өзі болып табылатын қалтаны құрастыр">
`npm run verify` мұны үшінші қадам ретінде әлдеқашан орындады. Сонда да бір рет бөлек іске қос та, `dist/` қалтасын аш: жай ғана HTML, CSS және JavaScript. Статикалық сайт — жай бір қалта.

<Terminal title="bash">

```bash
npm run build
```

</Terminal>
</Step>

<Step title="push жаса — бұл әрі сақтық көшірмең, әрі іске қосқышың">
Commit-терің GitHub-қа кетеді: сен кері қайта алатын тарих, ал CI-ға жалғанған репозиторийде — қалған бәрін іске қосатын түйме.

<Terminal title="bash">

```bash
git push origin main
```

</Terminal>
</Step>

<Step title="Қалтаны edge желісіне жарияла">
Wrangler — Cloudflare-дің CLI құралы. Ол `dist/` қалтасын жүктеп салады да, саған `pages.dev` доменіндегі тірі URL береді: HTTPS арқылы, тегін. `qairu-event` — Pages жобасының атауы; өзіңдікін жаз, ал қайтып келетін URL сол атау мен `.pages.dev` қосындысы болады.

<Terminal title="bash">

```bash
npx wrangler pages deploy dist --project-name=qairu-event
```

</Terminal>
</Step>

<Step title="Доменді қос — және бұл қадам пәрмен емес">
Бұл қадамды терминалдан аяқтай алмайсың. Cloudflare панелін аш, Pages жобаңды тап, **Custom domains** бөліміне кіріп, атауды қос. CNAME жазбасын да, SSL сертификатын да Cloudflare өзі жасайды. Содан кейін DNS таралғанын күт.

Нұсқаулықтар осы қадамды аттап кетеді. Агентің де аттап кетеді, сосын сайт тек `pages.dev` мекенжайында тұрғанда саған «сайт жұмыс істеп тұр» дейді.
</Step>

</Steps>

## Бір GitHub Action, басынан аяғына дейін

Continuous integration — дәл сол пәрмендер, бірақ оларды әр push сайын біреудің машинасы орындайды, сондықтан ұмытып кете алмайсың. Ол репозиторийіңде файл түрінде тұрады:

<Terminal title=".github/workflows/deploy.yml">

```yaml
name: Deploy
on:
  push:
    branches: [main]
jobs:
  ship:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npm run verify
      - run: npx wrangler pages deploy dist --project-name=qairu-event
        env:
          CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
```

</Terminal>

Жоғарыдан төмен оқы: `main` тармағына push жасалғанда Linux машинасын жалға ал, кодты жүктеп ал, Node 20-ны және lock файлы айтқан дәл тәуелділіктерді орнат, тексерулерді орында — олар `dist/` қалтасын әлдеқашан жасап береді — содан кейін жарияла. Токен файлдың ішінде ешқашан болмайды: GitHub оны шифрланған күйде сақтап, орындалу кезінде орнына қояды. Құпиялар хостта тұрады, ал build машинасы — сол хост.

GitHub Free жабық репозиторийлерде айына 2 000 Actions минутын береді, ал ашық репозиторийлерде стандартты runner-лер **тегін**. Ашық repo мен Cloudflare Pages қосылса — нөл теңгеге толыққанды pipeline. ([GitHub төлем құжаттамасы](https://docs.github.com/en/billing/concepts/product-billing/github-actions))

<Callout type="warn" title="Ескіретін екі жол">
Ол файлдағы бәрі тұрақты, тек `uses:` жолдарындағы екі нұсқа ғана ескіреді. Actions құралдарының жаңа үлкен нұсқалары шығады, ескілеріне қолдау тоқтайды. Айлар бойы істеп келген workflow кенет `uses:` жолында құласа — алдымен сол нұсқаны тексер де, журналды агентіңе тастағанда соны айт.
</Callout>

## Кері қайтару — тыныш сейсенбіде жаттығатын дағды

Агенттің «болдырмау» мүмкіндігі production ортасына жетпейді. Claude Code-тың checkpoint-тері файл өзгерістерін қамтиды, ал сыртқы салдарларды — дерекқорға жазуды, push-ты, deploy-ды — қамтымайды. `/rewind` бастапқы кодыңды қайтарады, ал бұзылған нұсқа тірі тұра береді. ([Checkpoint құжаттамасы](https://code.claude.com/docs/en/checkpointing))

Демек, кері қайтару — git әрекеті, одан кейін deploy:

<Terminal title="bash">

```bash
git log --oneline -5
git revert --no-edit <commit-hash>
git push origin main
npm run build
npx wrangler pages deploy dist --project-name=qairu-event
```

</Terminal>

Мұны жылдам ететін нәрсе — шағын commit-тер. Бір commit агенттің қырық файлға тараған бүкіл жұмысын сақтап тұрса, оны кері қайтару жақсысын да, жаманын да бірге лақтырады ([9-модуль](/kk/learn/git-and-github/)).

Ешкім дерлік істемейтінді істе: сол тізбекті сайт әлі жақсы тұрғанда, бүгін орында. Ешқашан сыналмаған кері қайтару — қауіпсіздік торы емес, жай ғана жоспар.
