<Lead>
Дәл қазір сенің тіркелу бетің жер бетіндегі бір ғана компьютерде бар: сенікінде. Қақпағын жапсаң — ол жоқ. Deploy жасау деген — оны ешқашан ұйықтамайтын машиналарға көшіріп қою және адам тере алатын атау беру. Мына стекте бұл — *төрт пәрмен*, оған қоса терминалдан істей алмайтын бір нәрсе.
</Lead>

Компьютеріңде жұмыс істеп тұрғаны — әлі аяқталғаны емес. Аяқталғаны — deploy жасалғаны. Бұл бет сені бірінші сөйлемнен екіншісіне құпияңды да, демалысыңды да жоғалтпай жеткізеді.

## Хостинг — ешқашан сөнбейтін, біреудің компьютері

Хост — ашық мекенжайы бар, үнемі қосулы тұратын машина. Сен оған файлдарыңды бересің, ол браузер сұраған кезде жауап береді. Бар идея — осы.

Өзгерген нәрсе — жеткізу тәсілі. Қазіргі хостингтер репозиторийіңді бақылап отырады да, әрбір `git push` сайын deploy жасайды: кодты тартып алады, build жасайды, бір-екі минутта жариялайды, әр тармаққа (branch) бөлек preview сілтемесін береді. Ештеңе қолмен жүктеп салынбайды, веб-сервер бапталмайды, ал шот шынымен танымал болғаныңа дейін келмейді.

## Статикалық па әлде серверде жасалады ма — қалғанының бәрі соған байланысты

**Статикалық** дегені — сайт бір рет құрастырылады, жай ғана HTML, CSS және JavaScript тұратын қалтаға айналады, сол қалта дүниежүзіндегі машиналарға көшіріледі. Әр келушіге бөлек ештеңе іске қосылмайды. Бұл — ең арзан, ең жылдам және бұзу ең қиын нұсқа. Сен қазір оқып отырған сайт — статикалық: `npm run build` пәрмені бастапқы кодты `dist/` қалтасына айналдырады, ал `dist/` — сайттың *өзі*.

**Серверде жасалатын** сайтта әр сұрауға бағдарлама іске қосылады: сенің кім екеніңді тексереді, дерекқорды оқиды, ақылы API-ге жүгінеді. Ол код серверде, пайдаланушының көзінен тыс жерде тұрады — құпиялар тұра алатын жалғыз орын да сол. Оның екі түрі бар: үнемі жұмыс істеп тұратын бір сервер немесе әр сұрауда оянып, сосын қайта ұйықтайтын шағын серверсіз функциялар (Cloudflare Workers, Vercel Functions).

Бірінші жоба үшін ереже: мүмкіндігінше көбірек бөлікті статикалық қалдыр да, динамикалық бөлікті ең кішкентай функцияға тығып таста. Тегін тарифтер статикалық файлдармен емес, функция шақырулары мен процессор уақытымен саналады — [Cloudflare-дің тегін Workers тарифі](https://developers.cloudflare.com/workers/platform/pricing/) күніне 100 000 сұрау және әр шақыруға 10 мс процессор уақытын береді, ал Pages статикалық файлдар үшін трафик шегін мүлде көрсетпейді. Статикалық бетті беру саған ештеңеге түспейді. Ал функция әр жүктелген сайын бюджет жұмсайды.

<Deeper title="Брондалған орын шын мәнінде қайда сақталады">
Тіркелу формасына дерекқор керек. Ақылға қонымды үш тегін нұсқаның әрқайсысында таңдау жасамай тұрып білуге тұрарлық бір «бірақ» бар.

- **Cloudflare D1** (SQLite): күніне 5 млн жол оқу және 100 мың жол жазу, барлығы 5 ГБ. Pages жобаңмен бір аккаунтта, картасыз.
- **Neon** (Postgres): әр жобаға 0,5 ГБ сақтау орны, айына әр жобаға 100 CU-сағат, 5 минуттан кейін міндетті түрде нөлге дейін сөнеді — яғни тыныш тұрған сағаттан кейінгі алғашқы сұрау баяу болады.
- **Supabase** (Postgres және аутентификация): 500 МБ дерекқор, айына 50 000 белсенді пайдаланушы, 2 белсенді жоба — және жоба **бір апта қимылсыз тұрса тоқтатылады**, ал демо воркшоп пен одан кейінгі кездесу арасында дәл сонша уақыт тұрады.

Дереккөздер: [Cloudflare](https://developers.cloudflare.com/workers/platform/pricing/), [Neon](https://neon.com/pricing), [Supabase](https://supabase.com/pricing).
</Deeper>

## Домен — жалға алынған атау, ал DNS — телефон кітапшасы

Deploy жасалған сәтте-ақ сайттың мекенжайы бар болады — шамамен `qairu-event.pages.dev` сияқты. Жеке домен — сол орынға бағытталған көркемірек атау.

DNS — интернеттің анықтамалығы: адам оқи алатын атауды соған жауап беретін машинаның мекенжайына аударады. Доменді қосқанда сен жазба қосасың, ең бірінші кездесетінің — **CNAME**: ол «бұл атау сол серверді білдіреді» дейді. Одан кейін хост `http://` мекенжайын `https://` етіп түрлендіретін SSL сертификатын автоматты түрде, тегін береді.

Бәрін шатастыратын тұсы: DNS жауаптары бүкіл әлемде кэштеледі, сондықтан өзгерістің бәріне жетуі бірнеше минуттан бірнеше сағатқа дейін созылады. Сайт өзіңде ашылып, досыңда ашылмаса — бұл әрдайым дерлік бұзылған deploy емес, кэштегі ескі жазба. Жөндеуге кіріспей тұрып, аз күте тұр.

## Құпиялардың орны — хостта, репозиторийде де, браузерде де емес

Орта айнымалысы — бағдарлама іске қосылғанда оған берілетін, атауы бар мән: API кілті, дерекқор мекенжайы немесе `NODE_ENV=production` сияқты параметр. Ол кодтың сыртында тұрады, сондықтан бірдей код сенің ноутбугыңда бір түрлі, серверде басқа түрлі жұмыс істей алады.

Құпия тұра алатын дәл үш орын бар, оның біреуі ғана дұрыс:

- **Ноутбугыңдағы `.env` файлында.** Бірінші commit-ке дейін `.env` файлы `.gitignore` ішіне жазылса — жарайды.
- **Хостың басқару панелінде**, сервердегі кодың оқитын орта айнымалысы ретінде. Production дегеніміз — осы.
- **frontend-те.** Ешқашан. Браузер жүктеп алатын нәрсенің бәрі — ашық дерек: келуші әзірлеуші құралдарын ашып, оны бірнеше секундта оқып шығады.

Алғашқы deploy-лардың көбі бірінші орыннан екіншісіне көшкен жерде өледі. `.env` файлың ноутбугыңнан ешқашан шықпайды, сондықтан сен қолмен термейінше, оның ішіндегі ештеңе хостта болмайды. Deploy жасамай тұрып `.env` файлын ашып, кілттерді бірінен соң бірін хостың панеліне қос. Бет жергілікті жерде жұмыс істеп, production ортасында қате берсе — себебі әдетте осы екі орынның біреуінде ғана тұрған бір айнымалы.

8-модульде сен агентке `.claude/settings.json` ішінде `.env` файлына тыйым салатын ереже бердің. Оны сақта, бірақ шегін де есте ұста: ол Claude-тың файл құралдарын және ол танитын shell оқығыштарын бұғаттайды, ал файлды өзі ашатын скриптті бұғаттамайды. Бұл — құлып емес, екінші қабат ([Claude Code рұқсаттары туралы құжаттама](https://code.claude.com/docs/en/permissions)).

## Әр тармақтың өз URL-і бар — ендеше ешкім көрмейтін жерде бұз

Preview deploy — бір тармақтан құрастырылған, өз мекенжайында жарияланған сайтыңның толық көшірмесі; оған сілтемеден басқа ештеңе апармайды. Сен скриншоттың орнына сол сілтемені жібересің. Netlify-де preview мен тармақ deploy-лары мүлде есептелмейді — кредитті тек production deploy жейді, сондықтан қателесудің ең арзан орны — дәл осы preview.

Preview сонымен қатар «менің компьютерімде жұмыс істеп тұр ғой» деген классикалық ақауды ұстайды: хостың build-ті Linux жүйесінде жасайды, ал Linux файл атауындағы бас әріпті ажыратады, Windows ажыратпайды. `header.astro` деп импортталған `Header.astro` ноутбугыңда күні бойы жұмыс істейді, ал build журналында қате болып шығады. Журналды оқы — ол саған файл атауын айтып тұр.

```

<Terminal title="bash">

```

</Terminal>
</Step>

<Step title="push жаса — бұл әрі сақтық көшірмең, әрі іске қосқышың">
Commit-терің GitHub-қа кетеді. Бұл — сен кері қайта алатын тарих, ал CI-ға жалғанған репозиторийде бұл әрі қалған бәрін іске қосатын түйме.

Төрт әдемі пәрменді көрсететін deploy нұсқаулықтары дәл осы қадамды үнсіз аттап кетеді. Агентің де аттап кетеді, сосын сайт тек `pages.dev` мекенжайында ғана тірі тұрғанда саған «сайт жұмыс істеп тұр» деп айтады.

## Бір GitHub Action, басынан аяғына дейін

Continuous integration — дәл сол пәрмендер, бірақ оларды әр push сайын біреудің машинасы орындайды, сонда «тесттерді іске қосуды ұмытып кетіппін» деген нәрсе мүмкін болмай қалады. Ол сенің репозиторийіңде файл түрінде тұрады:

<Terminal title=".github/workflows/deploy.yml">

```yaml
name: Deploy
on:
  push:
    branches: [main]
jobs:
  ship:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npm run verify
      - run: npx wrangler pages deploy dist --project-name=qairu-event
        env:
          CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
```

</Terminal>

Жоғарыдан төмен оқы: `main` тармағына push жасалғанда Linux машинасын жалға ал, кодты жүктеп ал, Node 20 орнат, тәуелділіктерді lock файлы айтқандай дәл орнат, тексерулерді орында — олар `dist/` қалтасын әлдеқашан жасап береді — содан кейін жарияла. Токен ешқашан файлдың ішінде болмайды. GitHub оны шифрланған күйде сақтап, орындалу кезінде орнына қояды — бұл сол «құпиялар хостта тұрады» деген ереженің build машинасына қолданылғаны.

Бағасы: GitHub Free жабық репозиторийлерде айына 2 000 Actions минутын береді, ал ашық репозиторийлерде стандартты runner-лер **тегін**. Ашық repo мен Cloudflare Pages қосылса — нөл теңгеге толыққанды pipeline. ([GitHub төлем құжаттамасы](https://docs.github.com/en/billing/concepts/product-billing/github-actions))

<Callout type="warn" title="Ескіретін екі жол">
Ол файлдағы бәрі тұрақты, тек `uses:` жолдарындағы екі нұсқа ғана ескіреді. Actions құралдарының жаңа үлкен нұсқалары шығады да, ескілеріне қолдау көрсету бір кезде тоқтайды. Айлар бойы жұмыс істеп келген workflow кенет `uses:` жолында құласа — басқа ештеңені жөндемей тұрып, ең алдымен сол нұсқаны тексер. Ал журналды агентіңе тастамай тұрып, күдігің сол нұсқада екенін оған айтып қой.
</Callout>

## Кері қайтару — тыныш сейсенбіде жаттығатын дағды

Агенттің «болдырмау» мүмкіндігі production ортасына жетпейді. Claude Code-тың checkpoint-тері оның сенің файлдарыңа енгізген өзгерістерін қамтиды, ал сыртқы салдарларды — дерекқорға жазуды, push-ты, deploy-ды — нақты қамтымайды. `/rewind` бастапқы кодыңды орнына қайтарады, ал бұзылған нұсқа сол уақыттың бәрінде тірі күйде тұра береді. ([Checkpoint құжаттамасы](https://code.claude.com/docs/en/checkpointing))

Демек, кері қайтару — git әрекеті, одан кейін deploy. Бәрі жақсы болған соңғы commit-ті тап, нашарын жаңа commit арқылы кері қайтар, push жаса, қайта құрастыр, жарияла:

<Terminal title="bash">

```bash
git log --oneline -5
git revert --no-edit <commit-hash>
git push origin main
npm run build
npx wrangler pages deploy dist --project-name=qairu-event
```

</Terminal>

Мұны жылдам ететін нәрсе — шағын commit-тер. Егер бір commit агенттің қырық файлға тараған бүкіл түстен кейінгі жұмысын сақтап тұрса, оны кері қайтару жақсысын да, жаманын да бірге лақтырып тастайды, сонда сен кідіруге болмайтын дәл сол сәтте кідіріп қаласың. Әр жұмыс сеансынан кейін емес, агентке берген әр сұрауыңның алдында commit жаса.

Одан кейін ешкім дерлік істемейтін нәрсені істе: сол тізбекті сайт әлі жақсы тұрғанда, бүгін орында. Ешқашан сыналмаған кері қайтару — бұл қауіпсіздік торы емес, жай ғана жоспар.
