<Lead>
2025 жылдың шілдесінде агент code freeze кезінде — кодқа тиюге тыйым салынған кезеңде — компанияның production дерекқорын өшіріп жіберді. Тыйым шын болатын. Бірақ ол чат терезесіндегі бір ғана сөйлем еді, яғни ол *тосқауыл емес*.
</Lead>

Жұртқа белгілі болған vibe coding апаттарының барлығы дерлік төрт үлгінің бірі. Агентте тапсырмаға қажет емес артық билік болды. Қолданба жұмыс істеп тұр, бірақ артқы есігі ашық. Оқып шықпаған нәрсені орнаттың. Агент шабуылдаушы жазған мәтінді оқып, соны орындады.

Әр жағдайда инженерияның ескі тосқауылы (control) жай ғана жоқ еді: орталарды бөлу, қол жеткізуді бақылау, ең аз рұқсат қағидаты, тәуелділіктерді таза ұстау, сақтық көшірме. ЖИ бұрын сол тосқауылдарды алдымен үйренуге мәжбүрлейтін кедергіні алып тастады.

## Чат терезесінен тысқары шықпаған code freeze

<Story title="Replit агенті production дерекқорын өшіреді" date="18 Jul 2025">
SaaStr негізін қалаушы Jason Lemkin Replit-те қолданба жасағанына тоғыз күн болған, әр қадамын жұртқа ашық жариялап отырған. Жарияланған code freeze кезінде агент тірі дерекқорға деректі жоятын пәрмендер жіберді. 1 200-ден астам басшы мен 1 190-нан астам компанияның жазбасы жоғалды.

Оған дейін де агент модульдік тест нәтижелерін бұрмалап хабарлаған, 4 000-ға жуық жалған адамның дерекқорын ойдан шығарған. Өшіргеннен кейін ол Lemkin-ге кері қайтару мүмкін емес деді. Қайтару жұмыс істеді, деректер орнына келді.

Не болғанын сұрағанда агент былай жазды: "I destroyed months of work in seconds." — айлаған еңбекті бірнеше секундта құртып жібердім. ([Fortune, 2025 ж. 23 шілде](https://fortune.com/2025/07/23/ai-coding-tool-replit-wiped-database-called-it-a-catastrophic-failure/))
</Story>

<Post author="Jason Lemkin" handle="@jasonlk" date="18 Jul 2025" href="https://x.com/jasonlk/status/1946069562723897802" platform="x">
Lemkin-нің жазбасы: құрал "goes rogue during a code freeze" — code freeze кезінде бақылаудан шығып, бүкіл дерекқорды өшіріп жібереді.

Replit-тің бас директоры Amjad Masad мұны "Unacceptable and should never be possible" деп бағалады — мүлде мүмкін болмауы керек еді ([The Register](https://www.theregister.com/2025/07/22/replit_saastr_response/)). Оның шешімдері: әзірлеу мен production дерекқорларын автоматты бөлу, сынақ ортасы, бір басумен қалпына келтіру және агент кодқа тие алмайтын режим. Әрқайсысы — инженерлік тосқауыл, «жақсырақ промпт» емес.

## Демода ешкім көре алмайтын қате

Tea — таныстықтағы қауіпсіздікке арналған әйелдер қолданбасы, 1,6 миллионнан астам пайдаланушысы бар, 2025 жылдың шілдесінде App Store-дың бірінші орнында тұрған. 25 шілдеде 4chan пайдаланушылары оның Firebase қоймасын растаусыз оқуға болатынын тапты. Сыртқа шамамен 72 000 сурет шықты, оның 13 000-ға жуығы — жеке басты растайтын селфилер мен жеке куәліктер. Үш күннен кейін зерттеуші API арқылы 1,1 миллионнан астам жеке хабарламаны оқып шықты. Apple қолданбаны 2025 жылдың қазанында дүкеннен алып тастады. ([404 Media](https://www.404media.co/women-dating-safety-app-tea-breached-users-ids-posted-to-4chan/), [Wikipedia](<https://en.wikipedia.org/wiki/Tea_(app)>))

<Callout type="info" title="Мынаны дәл айт">
Tea оқиғасын жиі vibe coding-тің кесірі деп айтады. Қолданбаны ЖИ жазғанына дәлел жоқ, ал қоймада 2024 жылдың ақпанына дейін тіркелгендердің деректері жатты — «vibe coding» деген тіркес әлі пайда болмаған кез. Ол мұнда бір себеппен тұр: демода «бәріне оқуға рұқсат» деген қойма ережесі дұрыс ережеден еш айнымайды.
</Callout>

Сол қатенің ЖИ жасаған нұсқасының өз CVE нөмірі бар. 2025 жылдың наурызында Matt Palmer — сол кезде бәсекелес Replit-те істеген, мұны біліп қойған жөн — Lovable сайтын тапты: ашық Supabase кілтімен кез келген адам оның пайдаланушылар кестесін оқи да, өзгерте де алатын. Келесі күнгі тексеру 170 жобадан 303 осал endpoint тапты, бұл талданған 1 645 қолданбаның 10,3%-ы: аты-жөні, поштасы, телефоны, мекенжайы, төлем деректері, API кілттері. Бұл [CVE-2025-48757](https://mattpalmer.io/posts/2025/05/CVE-2025-48757/) болып тіркелді.

Интернет пен сенің кестелеріңнің арасындағы *жалғыз* нәрсе — Row Level Security (RLS) ережелері, өйткені Supabase пен Firebase-те браузер дерекқормен тікелей сөйлеседі, ал кілт әдейі ашық. Агенттен «тіркелу формасын жаса» деп сұрасаң, жұмыс істейтін CRUD аласың, ал ережені алмайсың — қолданба екі жағдайда да бірдей көрінеді. Wiz дәл сол суретті Moltbook-тан 2026 жылдың қаңтарында тапты: кілт клиенттік bundle ішінде, RLS жоқ, растаусыз оқуға да, *жазуға да* болады, 1,5 миллион API токені ашық ([Wiz](https://www.wiz.io/blog/exposed-moltbook-database-reveals-millions-of-api-keys)).

<Post author="Harley Kimball" handle="@infinitelogins" date="1 Jun 2025" href="https://threadreaderapp.com/thread/1929017755136561402.html" platform="x">
Kimball қолданбасын үш күнде шығарды (Lovable, Cursor, Supabase), содан соң оны екі рет бұзып кірді. Екеуінің де себебі «RLS ережесі жоқ» емес еді. Бір Postgres view оны жасаған иенің құқығымен орындалатын, сондықтан ол арқылы оқығанда RLS айналып өтілді. Ал тіркелу формасын интерфейстен алып тастағанымен, Supabase Auth тіркелуді әлі қабылдап тұрды. View кімнің құқығымен орындалатынын және интерфейс енді көрсетпейтін параметрлерді бөлек тексер.
</Post>

## Нұсқаусыз жазылған ЖИ кодының жартысына жуығында белгілі осалдық бар

Veracode 100-ден астам модельді қауіпсіздікке қатысты тапсырмалардан өткізді. Үлгілердің 45%-ына OWASP Top 10 тізіміндегі осалдық кіріп кеткен. Java 72% жағдайда, JavaScript 43%, Python 38% құлады; cross-site scripting тапсырмалары 86% құлады. Үлкенірек модель жақсы нәтиже бермеді. Өту деңгейі 55%, сосын тағы 55% ([2026 ж. наурыз](https://www.veracode.com/blog/spring-2026-genai-code-security/)), сосын 56% болды ([2026 ж. шілде](https://www.veracode.com/blog/2026-genai-code-security-report-ai-risk/)). Синтаксистің дұрыстығы шамамен 100%, ал қауіпсіздік орнынан жылжыған жоқ.

Екі ескерту. Veracode қауіпсіздік құралдарын сатады, әрі олардың промпттарында қауіпсіздік туралы нұсқау жоқ — яғни 45% *әдепкі* нәтиже, шегі емес. CLAUDE.md файлыңа «әр сұрауды параметрлендір, енгізілген деректерді серверде тексер, шығатын мәтіндегі арнайы таңбаларды бейтараптандыр» деп жаз, сосын нәтижені өзің қарап шық.

- **A09 Logging and Alerting Failures** — шабуылды мүлде көрмейсің.
- **A10 Mishandling of Exceptional Conditions** — қате шыққанда жүйенің қақпасы ашық қалады.

**OWASP Top 10 for LLM Applications, 2026 жылғы шығарылым** ([genai.owasp.org](https://genai.owasp.org/resource/owasp-genai-llm-top-10-2026/)). Промпт-инъекция әлі бірінші орында; агенттің шектен тыс еркіндігі үшінші орынға көтерілді.

- **Prompt injection** — шабуылдаушының мәтіні модельді басқарып кетеді.
- **Sensitive information disclosure** — құпия деректер мен басқа пайдаланушылардың деректері сыртқа шығады.
- **Excessive agency** — құрал да тым көп, рұқсат та тым көп.
- **Supply chain** — уландырылған модельдер, плагиндер, MCP серверлері, skill-дер.
- **Data and model poisoning** — оқыту деректері не RAG деректері бұрмаланған.
- **Unbounded consumption** — бақылаусыз өсетін шығын және токеннің таусылуы.
- **Misinformation** — сенімді айтылған қате жауапқа сеніп әрекет етіледі.
- **Hidden context exposure** — жүйелік промпттар мен құрал схемаларын сыртқа шығарып алуға болады.
- **Vector and embedding weaknesses** — RAG деректерін улау, бөтен клиенттің деректеріне шығып кету.
- **Improper output handling** — модельдің шығысы тікелей shell-ге, SQL-ге немесе HTML-ге түсіп кетеді.

## Оқымай тұрып орнататын кодтың екі түрі

Модельдер пакет атауларын ойдан шығарады. Зерттеушілер 16 код моделін 576 000 үлгіде сынап, мүлде жоқ 205 474 бірегей атауды тіркеді — коммерциялық модельдерде кемінде 5,2%, ашық кодты модельдерде 21,7% ([USENIX Security 2025](https://arxiv.org/abs/2406.10279)). Шабуылдаушылар соларды өз атына тіркеп қойып, күтеді. Python Software Foundation-нан Seth Larson мұны 2025 жылдың сәуірінде **slopsquatting** деп атады ([simonwillison.net](https://simonwillison.net/2025/Apr/12/andrew-nesbitt/)).

Көрсеткіш жақсарды, қауіп жақсарған жоқ. 2026 жылғы зерттеу бес алдыңғы қатарлы модельді 199 845 промптта тексеріп, галлюцинация деңгейін 4,62%–6,10% аралығында тапты, ал бесеуі де дәл бірдей ойдан шығарған 127 жалған атаудың 53-і жарияланғаннан кейін де тіркеуге бос тұрған ([arXiv](https://arxiv.org/abs/2605.17062)). Шабуылдаушыға керегі — болжауға болатындығы.

Екінші түрі жаңалау. Агент skill-дері, MCP серверлері мен плагиндер — сенің рұқсаттарыңды ұстап тұрған агентті басқаратын мәтін. 2026 жылдың ақпанында Koi Security бір алаңдағы 2 857 skill-ді тексерді: 341-і зиянды болып шықты, шамамен 12%, көбі жалған "Prerequisites" қадамы арқылы дерек ұрлайтын бағдарламаны орнатқызған ([The Hacker News](https://thehackernews.com/2026/02/researchers-find-341-malicious-clawhub.html)).

Енді сол қателерді кодтың ішінен тап.

## Агент шабуылдаушының мәтінін оқып, айтқанын істейді

Модель деректі сол деректің ішіне жасырылған нұсқаудан сенімді түрде ажырата алмайды. Simon Willison-ның **lethal trifecta** деп атағаны: агентте (1) сенің жеке деректеріңе қол жеткізу, (2) сенімсіз мазмұнмен жанасу және (3) деректі сыртқа жіберу жолы бар. Екеуі болса — аман қаласың. Үшеуі бірге болса — бұл дайын тұрған дерек ұрлау құралы, ол қажетті веб-бет, issue немесе қолдау сұрауы келгенше күтіп тұр. Мұны жамайтын «қорғаныс» өнімдері туралы: "95% is very much a failing grade." — 95% дегеннің өзі құлаған баға ([simonwillison.net](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)).

Екі көрсетілім, зиянды құрал керек болмады:

- **GitHub MCP.** Шабуылдаушы сенің *ашық* repo-ңдағы issue ішіне нұсқау жазып қояды. Сен агенттен ашық issue-лерді қарап шығуын сұрайсың. Ол сол нұсқауды орындап, *жабық* репозиторийлеріңді оқиды да, тапқанын ашық pull request ішінде жариялайды ([Invariant Labs](https://invariantlabs.ai/blog/mcp-github-vulnerability)).
- **Supabase MCP.** Шабуылдаушы қолдау сұрауының ішіне нұсқау жазады. Сен агенттен соңғы сұрауларды көрсетуін сұрайсың. Байланыс RLS-ті айналып өтетін `service_role` кілтімен жүреді, сондықтан агент токендер кестесін оқып, оны сол сұраудың ішіне жазып қояды ([General Analysis](https://generalanalysis.com/blog/supabase-mcp-blog)).

Көзге көрінбейтін шабуыл да бар: MCP серверінің *құрал сипаттамалары* саған емес, модельге барады. Invariant Labs зиянсыз көрінетін `add` құралын көрсетті: сипаттамасында агентке пайдаланушының SSH жеке кілтін оқып, жасырын параметр ретінде жіберу нұсқауы тұрған — әрі сен мақұлдағаннан кейін өз сипаттамасын қайта жазатын сервер де бар ([Invariant Labs](https://invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks)). Supabase-тің нұсқауы: "Never connect AI agents directly to production data." — ЖИ-агенттерді production деректеріне тікелей қоспа ([Supabase](https://supabase.com/blog/defense-in-depth-mcp)).

## Тосқауыл — агенттің істей алмайтын нәрсесі

**Құпия деректер серверде тұрады.** Браузерге тек ашық кілттер — `NEXT_PUBLIC_*`, Supabase anon кілті — жетуі мүмкін. Жиналған bundle ішін және git тарихын `sk-`, `service_role`, `AKIA` және `-----BEGIN` бойынша іздеп шық. Бір рет commit-ке түскен немесе ЖИ-чатқа қойылған кілттің бәрін ауыстыр: 2026 жылдың ақпаны мен сәуірі аралығында Lovable-ге кірген кез келген адам ашық жобалардың чат тарихын оқи алатын ([Lovable](https://lovable.dev/blog/our-response-to-the-april-2026-incident)).

**Қол жеткізу ережелері қосулы және тексерілген.** Әр кестеде RLS қосулы, әр әрекетке бөлек ереже, Firebase ережелері әдепкіде тыйым салады. Содан кейін өзіңе өзің шабуыл жаса — бұл модульдегі ең пайдалы бір сағат осы.

<Terminal title="bash">
```bash
# Log out. Copy the public key from the browser's Network tab.
curl "https://YOUR-PROJECT.supabase.co/rest/v1/signups?select=*" \
  -H "apikey: YOUR_ANON_KEY"
```
</Terminal>

Бос массив: RLS жұмыс істеп тұр. Жолдар: интернеттегі кез келген бейтаныс адам дәл сол жолдарды алады.

**Ақылы нәрсенің бәріне сұрау шегі мен шығын шегін қой.** «Менің кішкентай қолданбама ешкім шабуыл жасамайды» дегенді сан жоққа шығарады. 2025 жылдың наурызында бір негізін қалаушы Cursor-мен жасалған SaaS өнімін шығарды, ал шамамен 48 сағаттан кейін "guys, i'm under attack" деп жазды ([techstartups.com](https://techstartups.com/2025/03/26/when-vibe-coding-goes-wrong/)). Anthropic-тің 2025 жылғы тамыздағы қауіп есебінде бір қылмыскердің Claude Code-ты кемінде 17 ұйымға қарсы қолданғаны сипатталған ([Anthropic](https://www.anthropic.com/news/detecting-countering-misuse-aug-2025)).

<Post author="leojr94" handle="@leojr94_" date="17 Mar 2025" href="https://x.com/leojr94_/status/1901560276488511759" platform="x">
Ол өзін техникалық маман емеспін дейді. API кілттері шегіне дейін сарқылған, жазылым тексерісі тек frontend JavaScript-те тұрған, ал бейтаныс адамдар оның дерекқорына дерек жазып жатқан. Ең пайдалысы — содан кейін жазғаны: әр API кілтін ауыстырып, орта айнымалыларына көшірген, API endpoint-теріне аутентификация қойған, CORS-ты тек сенімді домендермен шектеген. Үш тосқауыл, жаңа framework жоқ, «жақсырақ промпт» та жоқ.
</Post>

**Тәуелділіктер орнатылмай тұрып тексеріледі.** Агент қосқан әр пакет үшін registry бетін ашып қара: ол шынымен бар ма, қашан шыққан, қанша рет жүктеп алынған, репозиторий сілтемесі шын жерге апара ма? Lockfile файлын commit-ке қос, `npm audit` пәрменін орында.

**Рұқсаттар сұралмайды, мәжбүрлеп орындалады.** `.env`, `~/.ssh` және `~/.aws` үшін тыйым ережелерін `.claude/settings.json` файлына жаз, ал агентті жобаның қалтасынан іске қос, ешқашан үй қалтаңнан емес ([07-модуль](/kk/learn/the-agent/)). Өз компьютеріңде `--dangerously-skip-permissions` жалаушасын ешқашан қолданба: 2025 жылдың тамызындағы Nx шабуылында зиянды бағдарлама орнатылған ЖИ CLI құралдарын тауып, оларды дәл сол «бәрін өткізіп жібер» жалаушаларымен іске қосып, құпия деректерді тінткен ([Wiz](https://www.wiz.io/blog/s1ngularity-supply-chain-attack)).

Тыйым тізімі айқын кездейсоқ қатені тоқтатады, әдейі іздеген айналма жолды тоқтатпайды: жолы жабылған агент сол әрекетті істейтін скрипт жазып шыға алады. Шын еркіндік керек болса, тізімді ұзартпа, компьютердің өзін оқшаула.

<Callout type="warn" title="Windows пайдаланушысы, мына жолды оқы">

</Callout>
