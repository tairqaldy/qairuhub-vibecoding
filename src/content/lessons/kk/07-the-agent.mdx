<Lead>
Код жазатын агент — жылдамырақ автотолтыру емес. Бұл — қолына құрал берілген модель: файлды оқиды, өңдейді, пәрмен орындайды, нәтижені оқиды — сосын тапсырма бітпейінше немесе сен тоқтатпайынша сол *циклге* салынады. Бұл модуль бір сұрақ туралы: тізгінді кім ұстайды.
</Lead>

Модель — ми. [Claude Code](https://code.claude.com/docs/en/overview) — сол мидың [денесі](https://code.claude.com/docs/en/how-claude-code-works): құралдар, контекстті басқару, пәрменді нақты орындайтын механизм.

## Сен кіріп бара жатқан цикл

Бес қимыл, қайта-қайта. Тапсырманы қарапайым тілмен айтасың. Ол контекст жинайды — файлдар, git күйі, CLAUDE.md. Әрекет етеді: өңдейді, пәрмен орындайды. Тексереді: тесттерді не build-ті іске қосып, нәтижені оқиды. Содан кейін сен бағыттайсың. `Esc` оны әрекет үстінде тоқтатады да, істелген жұмысты сақтап қалады. Ол жұмыс істеп тұрғанда терген мәтінің жоғалмайды: ағымдағы әрекет біткен соң оқылатын түзетуге айналады.

Соңғы қимыл — нақты сенің жұмысың. Агент жұмыс бітті деп *көрінгенде* тоқтайды. Сондықтан оған өзі орындай алатын тексеріс бер — тест, build-тің шығу коды, linter. Бермесең, тест жиынтығының рөлінде сен жүресің. [Anthropic нұсқаулығы](https://code.claude.com/docs/en/best-practices) енді дәл осыдан басталады. Тексере алмасаң, шығарма.

Қай жерде іске қоссаң да, цикл бірдей: қозғалтқыш біреу. CLAUDE.md файлың, параметрлерің және MCP серверлерің жергілікті нұсқалардың бәріне ортақ.

| Интерфейс | Не үшін жақсы | Білгеніңе тұрарлық |
|---|---|---|
| Терминалдағы CLI | бәріне, оның үстіне скрипт жазуға | `claude -p "query"` пәрменін интерактивсіз орындайтын жалғыз интерфейс |
| Desktop қолданбасы | diff-ті көзбен салыстыру, қатар жүретін сеанстар | Claude Code ішінде бар, CLI бөлек орнатылмайды; ақылы жоспар керек |
| Веб, [claude.ai/code](https://claude.ai/code) | қасында отырмайтын ұзақ тапсырмалар | сен ажыратылғаннан кейін де Anthropic басқаратын бұлттық виртуалды машиналарда жалғасады |
| VS Code / JetBrains | редактордың ішіндегі diff, жоспарды сол жерде оқу | VS Code кеңейтімі өзімен бірге CLI құралын әкеледі, бірақ `claude` пәрменін PATH-қа **қоспайды**; JetBrains плагині үшін CLI бөлек орнатылады |

## Рұқсат режимі — сенім реттегіші

Әр әрекет не рұқсат етіледі, не сұралады, не тыйылады. Қайсысы болатынын режим шешеді.

| Режим (экрандағы атауы) | Конфигтегі мәні | Сұрамай орындайтыны |
|---|---|---|
| Manual (қолмен) | `default` | тек оқиды |
| Accept edits (өңдеуге рұқсат) | `acceptEdits` | оқу, файлды өңдеу, жұмыс қалтасындағы кәдімгі файл пәрмендері |
| Plan (жоспарлау) | `plan` | оқу мен зерттеу; жоспарды бекітпейінше кодқа тимейді |
| Auto (авто) | `auto` | бәрін, бірақ әр әрекетті бөлек классификатор модель тексеріп отырады |
| Don't ask (сұрамау) | `dontAsk` | тек алдын ала рұқсат етілгенін, қалғанының бәріне тыйым — CI үшін |
| Bypass permissions (рұқсатты айналып өту) | `bypassPermissions` | бәрін, ешқандай тексеріссіз |

`Shift+Tab` оларды кезекпен ауыстырады, қайсысында тұрғаныңды күй жолағы көрсетеді. `claude --permission-mode plan` деп бірден керегінен бастауға болады. Бөтен репозиторий сені қақпанға түсіре алмайды: жоба өзінің `.claude/settings.json` файлында `auto` немесе `bypassPermissions` қойса, олар еленбейді.

Pro, Max және Team жоспарларында интерактивті терминал мен VS Code сеанстары енді **auto** режимінен басталады. Enterprise жоспарлары, Console арқылы алынған API кілттері және кез келген `claude -p` орындауы бұрынғыша Manual режимінде басталады. «Claude Code әдепкіде бәрін сұрайды» деген сөз ескірді.

Auto режимі бірінші санның кесірінен пайда болды. Anthropic жазбасы: "Claude Code users approve 93% of permission prompts." — пайдаланушылар рұқсат сұрауының 93%-ын мақұлдайды. Бұл — тексеру емес, рефлекс; жазбада оны рұқсат шаршауы деп атайды. Сондықтан әр әрекетті сенің орныңа екінші модель тексереді және сұрағаныңнан асып кететінін бұғаттайды. Жалған оң көрсеткіші — 0,4%. Ол сұрақты азайтады, бірақ қауіпсіздікке кепілдік бермейді. Бұл — қауіпсіздік белдігі, тор емес.

<Callout type="danger" title="bypassPermissions шын мәнінде немен қауіпті">
`bypassPermissions` (`--dangerously-skip-permissions` параметрі) сұрауды мүлде жояды: сұрақ та жоқ, классификатор да жоқ. Агент орындаймын деген әр пәрмен орындалады — файл өшіру де, қашықтағы репозиторийге push та, деректі сыртқа жіберу де. Құжаттама оны тек контейнер мен виртуалды машинада қолдануға рұқсат етеді. SSH кілттерің мен `.env` файлдарың тұрған ноутбукте бұл — жаман айырбас. Сонда да екі нәрсе күшінде қалады: айқын жазылған `deny` ережелері кез келген режимде жеңеді, ал `rm -rf /` немесе `rm -rf ~` ешқашан автоматты түрде мақұлданбайды.
</Callout>

<Deeper title="Auto режимі нені бұғаттайды — және sandbox неге мүлде басқа нәрсе">
Классификатор мынадай әрекеттерді бұғаттайды: `curl | bash` тәрізді «жүктеп ал да орында» үлгілері, құпия деректі сыртқа жіберу, production ортасына deploy пен миграциялар, бұлттағы деректі жаппай өшіру, рұқсат беру, force push және `git reset --hard` сияқты commit жасалмаған жұмысты жоққа шығару. Чатта «push жасама» десең, ол мұны сен алып тастағанша шекара деп санайды.

Sandbox (`/sandbox`) — мүлде басқа нәрсе: Bash құралы үшін операциялық жүйе деңгейінде файл жүйесі мен желіні оқшаулау. Ол macOS, Linux және WSL2-де жұмыс істейді — таза Windows-та **істемейді**, ал залдағылардың көбінде дәл сол. Онда сенің басқару құралың — allow/deny ережелері мен Manual режимі. Олар бағдарламаны емес, пәрмен мәтінін салыстырады: `Bash(rm *)` сол файлды өшіретін Python скриптін тоқтата алмайды. Бұл — ыңғайлылық, қауіпсіздік шекарасы емес.
</Deeper>

## Жоспарлау режимі: diff-пен емес, жоспармен айтыс

Жоспарлау режимінде агент оқиды, зерттейді, бірақ кодыңа қол тигізе алмайды. Ол жоспар ұсынады; `Ctrl+G` оны редакторыңда ашады, сен бекітпей тұрып қайта жаза аласың. Жоспарға бір шектеу қосу — бір сөйлемге тұрады. Сол шектеуді дайын кодтан суырып алу — түстен кейінгі уақытыңа тұрады. Бекіткен соң қалай орындалатынын таңдайсың: auto режимі, әр өзгерісті қолмен мақұлдау немесе «No, keep planning».

Реті мынадай: зертте, жоспарла, жаса, commit жаса. Diff-ті бір сөйлеммен сипаттай алсаң, жоспарды аттап кет — қате әріп, атын өзгерту, бір жол лог. Жоспар тәсіл әлі айқын болмағанда, өзгеріс бірнеше файлды қамтығанда немесе код екеуіңе де жат болғанда керек.

## Сен бір әріп терместен бұрын не жүктеледі

`CLAUDE.md` әр сеанстың басында толығымен оқылады, жалпыдан нақтыға қарай: `~/.claude/CLAUDE.md`, содан кейін `./CLAUDE.md` немесе `./.claude/CLAUDE.md`, одан соң git елемейтін `./CLAUDE.local.md`. v2.1.277 нұсқасынан бастап Claude Code CLAUDE.md болмаса репозиторийдің `AGENTS.md` файлын өзі оқиды — Codex, Cursor, Copilot және Jules оқитын сол файл. Ішіне не жазатының — [06-модуль](/en/learn/context-ssot/). Осы жерде екі нәрсе маңызды: көлемі 200 жолдан аспасын, себебі ұзарған сайын ережелер еленбей қалады; және ол — мәжбүрлеу емес, контекст. Шынымен тыйым салу үшін deny ережесін немесе hook қолдан.

Бәрі бір контекст терезесін бөліседі, ал терезе толған сайын сапа төмендейді ([02-модуль](/en/learn/ai-in-plain-language/)). Төрт пәрмен: `/context` терезені не жеп жатқанын көрсетеді, `/clear` жаңа әңгіме бастайды әрі тегін, `/compact keep the API decisions and the file list` сен қойған шартпен түйін жасайды, `/btw what does localStorage do?` тарихқа кірмейтін бөгде сұрақ қояды. Құжаттаманың өз ережесі: бір нәрсені екі рет түзеттің бе? Үшіншіні жазбай, `/clear` жасап, жақсырақ промпт жаз.

## Rewind — жергілікті кері қайтару. Git — нағыз кері қайтару.

Кезекті бастайтын әр промпт бақылау нүктесін (checkpoint) жасайды. Бос жолда `Esc` `Esc` басу (немесе `/rewind`) мәзірді ашады: кодты да, әңгімені де қалпына келтіру, біреуін ғана қалпына келтіру немесе сеанстың бір бөлігін түйіндеу. Әр сеанста соңғы 100 checkpoint сақталады, көшірмелер шамамен 30 күннен кейін тазаланады.

Checkpoint тек Claude-тың өз өңдеу құралдары жасаған өзгерістерді қадағалайды. Bash пәрмендері өзгерткен файлдарды, субагент өзгерістерінің көбін, сенің қолмен енгізген түзетулеріңді және сырттағы ештеңені — дерекқорға жазуды, deploy-ды, push-ты — **қадағаламайды**. Агентті жібермес бұрын `git init` жасап, commit жасаудың бүкіл себебі — осы ([09-модуль](/en/learn/git-and-github/)).

## Бір рет үйретудің төрт жолы

**Skill** — `.claude/skills/<name>/` ішіндегі `SKILL.md` файлы бар қалта. Контекстте тек сипаттамасы тұрады; негізгі мәтіні керек болғанда ғана жүктеледі. CLAUDE.md файлына тағы бір бет жалғағаннан skill-дің артықшылығы осында. Оны `/name` деп шақырасың немесе сипаттамасы сәйкес келгенде агент өзі алады. Ол ашық [Agent Skills](https://agentskills.io) стандартына сүйенеді, сондықтан skill тек Claude-та ғана жұмыс істемейді.

**Субагенттер** — өз контекст терезесі, өз құралдары және өз рұқсаттары бар көмекшілер. Олар шулы жұмысты істейді — үлкен репозиторийден іздеу, журналды оқу — және қысқаша түйін қайтарады, сондықтан былық сенің терезеңе емес, солардың терезесіне түседі. Explore, Plan және general-purpose дайын тұр; өзіңдікі `.claude/agents/<name>.md` файлында жатады. Олардың өзгерістерін `/rewind` әдетте қалпына келтіре алмайды.

**Hook** — өмірлік циклдің белгілі сәттерінде іске қосылатын өзіңнің shell пәрмендерің: `PreToolUse` (2 коды әрекетті бұғаттайды), `PostToolUse`, `Stop`, `Notification`. CLAUDE.md файлындағы жолдан айырмашылығы — hook әрқашан іске қосылады. «Форматтағышты іске қосшы» деген өтініш пен шынымен іске қосылатын форматтағыштың айырмашылығы — осы.

**MCP** агентке сыртқы құралдар мен деректерді жалғайды: мәселе трекерлері, дерекқорлар, браузерлер, дизайн құралдары ([02-модуль](/en/learn/ai-in-plain-language/)). Бірінші қосуға ең таза сервер — Claude Code құжаттамасының өзі.

<Terminal title="bash">
```bash
claude mcp add --transport http claude-code-docs https://code.claude.com/docs/mcp
claude mcp list
# claude-code-docs ... Connected
```
</Terminal>

Енді ол параметрді болжаудың орнына өз құжаттамасынан қарайды. Классикалық қате — сервер жергілікті пәрмен болғанда `--` таңбасын қалдырып кету (`claude mcp add playwright -- npx -y @playwright/mcp@latest`). `--` таңбасынан кейінгінің бәрі серверді іске қосады. MCP құралдарының анықтамалары керек кезде жүктеледі, сондықтан контекстті аз алады — бірақ сол жұмысқа `gh` сияқты қарапайым CLI бәрібір арзанырақ.

## Жұмыс істейтін промпттың алты бөлігі

Нашар нәтиже мен жақсы нәтиженің айырмашылығы модельде емес. Ол — сенің жазбай кеткеніңде.

<Compare a="Көбі осылай жазады" b="Агент осымен жұмыс істей алады">
<div slot="a">
«тіркелу қатесін түзет»

Ол қатенің қалай көрінетінін де, қай файлды ашуды да, «түзетілді» дегеннің не екенін де, қашан тоқтауды да білмейді. Төртеуін де болжайды, ал сен мүлде басқа мәселені шешкен diff аласың.
</div>
<div slot="b">
«Электрондық поштасында `+` таңбасы бар пайдаланушылар форманы жібергенде 'invalid address' деген хабар алады. Күтілетіні: қабылдануы керек. Ықтимал жері — `src/lib/validate.ts`. Алдымен құлайтын тест жаз, содан кейін ең шағын түзетуді жаса. `npm test` орында да, нәтижесін көрсет.»

Белгісі, орны, «бітті» дегеннің анықтамасы және агент өзі орындай алатын тексеріс.
</div>
</Compare>

Алтауы бірден сирек керек болады:

1. **Рөл** — ол өз жұмысын салыстыратын өлшем. «Сен — қарапайым, оқуға оңай кодты бағалайтын тәжірибелі frontend әзірлеушісің.»
2. **Мақсат** — аяқталу сызығы бар бір сөйлем. «Жақсырақ қыл» дегенде ондай сызық жоқ.
3. **Контекст** — алдымен оқитын файлдар, үлгі ретінде көшіретін код, стек. Онсыз агент сенікі емес стекті ойдан шығарады.
4. **Шектеулер** — неге тимеу керек, жаңа тәуелділік қоспау, неге араласпау. Болып кеткен соң емес, болмай тұрып айтылады.
5. **Нәтиженің пішімі** — «әр файлдың diff-ін қолданбас бұрын маған көрсет» деген жол жұмысты тексеретініңді ме, әлде жай қабылдайтыныңды ма шешеді.
6. **Тоқтау шарты** — «бірдеңе түсініксіз болса, болжамай, менен сұра; тесттер өткеннен кейін тоқта». Көп промптта ең қымбат жол — осы.

Нәтиже көңіліңнен шықпаса, үлкенірек модельге жүгірмей тұрып, осы тізімді шолып шық. Әдетте себебі — 3 не 6.

6-промпттағы «қызыл» қадамы бекер емес: құлағанын өз көзіңмен көрмеген тест дұрыс емес себеппен өтіп тұрған болуы мүмкін ([Simon Willison](https://simonwillison.net/guides/agentic-engineering-patterns/red-green-tdd/)). 4-промпттағы құрылымдық пен мінез-құлықтық өзгерісті бөлу — [Kent Beck-тің](https://newsletter.kentbeck.com/p/augmented-coding-beyond-the-vibes) ережесі. Ол агенттің жолдан шыққанын білдіретін үш белгіні де атайды: цикл ішінде айналады, ешкім сұрамағанды қосады, тесттерді өшіріп қойып алдайды.

<ProjectStep n={7} title="Тіркелу беті үшін айтысуға болатын жоспар ал">
Жоспарлау режимінен баста: `claude --permission-mode plan`. 2-промптты қой да, оны CLAUDE.md файлыңа және спецификацияңа бағытта. Жоспар келгенде `Ctrl+G` бас та, өз қолыңмен бір жол қос — агент ойламаған шектеу. Содан кейін **«Yes, manually approve edits»** таңда да, қабылдамай тұрып бір diff-ті басынан аяғына дейін оқып шық.

Бітті деген белгі: `PLAN.md` репозиторийіңде тұр, онда әр кезең үшін тексеру қадамы аталған және сен бекітпей тұрып оған бір нәрсе өзгерттің.
